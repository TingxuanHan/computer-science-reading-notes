# 【计算机程序设计艺术 TAOCP】卷1·2.1 引论：数据之间的关系，怎样进入内存

> 对应原书：第 1 卷《基本算法》第 3 版，§2.1，书内第 222—226 页。本文按原书的问题次序作学习整理，示例与 Python 程序为重新设计。

第一章主要研究程序怎样一步步执行。进入第二章，问题变成了：程序所操作的东西，究竟怎样组织？

假设内存里有三个值：`30、10、20`。只知道这些值，还不能回答哪一个排在最前面、谁是谁的后继，以及删掉一个元素后应该连接谁。

**数据的值和数据之间的关系，是两个需要分别表示的问题。** §2.1 的任务，就是建立描述这种关系的语言：节点、字段、链接，以及从入口出发访问结构的规则。

## 1. 信息结构包含什么

原书从线性表、数组、树和多重链接结构出发，关心结构的建立、修改、访问与销毁。这里的“结构”不只是一幅静态图，还包括图在操作以后应该保持的性质。

以一张待办事项表为例：

| 信息 | 一种可能的表示 | 它支持的问题 |
|---|---|---|
| 事项名称、完成状态 | 节点里的普通字段 | 这件事是什么，是否完成 |
| 下一个事项 | 后继链接 | 做完以后接着看谁 |
| 第一项的位置 | 入口变量 | 从哪里开始访问 |
| 表的长度 | 单独保存的计数，或遍历计算 | 还有多少项 |

并非表中所有信息都必须额外占一个字段。长度可以每次遍历求出；如果查询很频繁，也可以保存计数，并在每次插入、删除时维护它。

这个选择已经涉及时间与存储的交换：少存一个数字，可能意味着每次多走一遍结构；多存一个数字，则多了一条必须维护的一致性规则。

## 2. 节点、字段和链接不是同一件事

原书把一项结构化信息称为节点。一个节点可以占用一个或多个内存字，并分成若干命名字段。

例如用以下格式表示待办事项：

```text
节点 = {NAME, DONE, NEXT}
```

`NAME` 和 `DONE` 保存内容，`NEXT` 保存另一个节点的位置。这里的位置可以是机器地址，也可以是数组下标；在下面的教学程序中，它是一个整数编号。

假设存储表为：

| 节点编号 | NAME | NEXT |
|---:|---|---:|
| 12 | 写摘要 | 31 |
| 31 | 校对公式 | 7 |
| 7 | 检查代码 | 空 |

另有入口 `HEAD=12`。逻辑顺序是：

```text
HEAD → 12:写摘要 → 31:校对公式 → 7:检查代码 → 空
```

节点编号没有递增，表的顺序仍然清楚。顺序由 `NEXT` 决定，不能把“编号更小”解释成“排得更前”。

反过来，在连续数组中，后继位置可以由地址计算得到，不必逐项保存链接。两种表示都能实现同一个逻辑序列，所需的操作却不同。

## 3. 怎样读懂 NEXT(P)

书中使用 `NEXT(P)` 一类记法，表示“由链接变量 `P` 指向的节点中的 `NEXT` 字段”。它不是说执行一个名叫 `NEXT` 的计算函数。

在上表中：

```text
HEAD = 12
NEXT(HEAD) = 31
NAME(NEXT(HEAD)) = 校对公式
```

要区分三个层次：

- `P`：保存节点位置的变量。
- `NEXT`：字段名称，本身没有一个独立的全局值。
- `NEXT(P)`：某个具体节点里的可读写位置。

原书还使用 `LOC(V)` 表示变量所在的位置，使用 `CONTENTS(P)` 表示位置 `P` 中保存的内容。在适用的单字存储模型下，`CONTENTS(LOC(V))=V`。这些记号帮助我们分开“地址”和“地址中的值”。

Python 对象引用、整数编号和 MIX 地址并非完全相同的机制，但这一层区分对三者都很有用。

## 4. 空链接是一种约定

原书用 $\Lambda$ 表示空链接，并在许多 MIX 程序中用 0 编码它。这里的重点是：**空链接必须能与有效节点位置区分。**

本文使用 `None` 表示空链接，因此整数编号 0 仍然可以作为有效节点。不要因为书中常把 0 用作空链接，就认为所有语言中的 0 都不能成为合法下标。

同样，“字段里保存空链接”不等于“这个节点不存在”。一个实际存在的末节点，恰好以空链接作为后继。

还有两种错误值得分别检查：

```text
悬空链接：NEXT 指向一个不在存储表中的编号。
意外循环：本来应当以空链接结束，却又回到了访问过的节点。
```

循环本身不是错误；§2.2 会专门使用循环表。它是否错误，取决于当前表示的约定。

## 5. 头部插入：两次赋值为什么有顺序

把新节点 `Q` 插入现有表的前端，最小操作是：

```text
NEXT(Q) ← HEAD
HEAD ← Q
```

先把旧入口保存到新节点的链接字段，再让入口指向新节点。若反过来写，随后执行 `NEXT(Q) ← HEAD` 时，`HEAD` 已经等于 `Q`，新节点就会指向自身，旧表也可能丢失入口。

因此，“这两条赋值都执行了”还不够，必须知道第二条读取的是哪个时刻的状态。这正是第一章关于明确性和赋值顺序的讨论在数据结构中的落地。

下面是一个可运行的整数编号模型。它允许合法编号 0，并显式检查新编号是否已经被占用。

```python
def prepend(nodes, head, node_id, value):
    if node_id is None or node_id in nodes:
        raise ValueError("新节点编号必须有效且尚未使用")
    if head is not None and head not in nodes:
        raise ValueError("入口指向不存在的节点")
    nodes[node_id] = {"value": value, "next": head}
    return node_id


def walk(nodes, head):
    values = []
    seen = set()
    p = head
    while p is not None:
        if p not in nodes:
            raise ValueError("出现悬空链接")
        if p in seen:
            raise ValueError("本例的线性表中出现循环")
        seen.add(p)
        values.append(nodes[p]["value"])
        p = nodes[p]["next"]
    return values


nodes = {}
head = None
for node_id, value in [(7, "检查代码"), (31, "校对公式"), (12, "写摘要")]:
    head = prepend(nodes, head, node_id, value)
print(walk(nodes, head))
head = prepend(nodes, head, 0, "确定范围")
print(walk(nodes, head))
```

输出：

```text
['写摘要', '校对公式', '检查代码']
['确定范围', '写摘要', '校对公式', '检查代码']
```

这段程序演示链接关系，没有模拟真实内存分配器。字典查找按通常的平均代价理解；`walk` 为了诊断循环，额外使用了 $O(n)$ 的访问集合。若输入已保证是有限的无环单链表，单纯遍历并计数只需要一个当前位置和一个计数器。

## 6. 写下不变式，指针操作才容易检查

对于本文的表示，可以约定：

1. `head` 是空链接，或存储表中的有效编号。
2. 从 `head` 出发遇到的每个后继都是有效编号或空链接。
3. 从 `head` 出发不会重复访问节点，最终到达空链接。
4. 经过这些节点得到的值序列，恰好是要表示的逻辑表。

注意，这没有要求存储表中的所有节点都能从 `head` 到达。存储池可能还容纳其他表；是否存在失去入口的无用节点，是后续存储管理要研究的问题。

头部插入为什么保持这些性质？新编号没有出现过，旧表的所有后继不变，新节点只指向旧入口。因此新表多了一个前端节点，旧序列完整保留，也不会凭空形成循环。

把这几句话写清楚，通常比画很多没有入口和空值标记的箭头更有帮助。
