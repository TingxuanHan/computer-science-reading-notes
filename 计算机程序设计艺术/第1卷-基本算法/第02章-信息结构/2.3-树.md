# 【计算机程序设计艺术 TAOCP】卷1·2.3 树：从遍历顺序到存储回收

> 对应原书：§2.3，第 293—398 页。本文按定义、遍历、表示、数学性质、列表与废料收集串起 §2.3.1—§2.3.5；数学部分选取可以完整推导的核心结果，程序使用自拟小例子。

树很容易画出来，也很容易被画错：两个节点是否共享同一个子节点？只有一个孩子时，左右位置是否重要？一条指向祖先的箭头，是实际的孩子链接，还是辅助遍历的线索？

这些区别决定了遍历能否终止、计数公式能否使用，以及一个节点能否直接释放。

## 1. 从递归定义开始

原书的一般树是非空的：有一个根，剩余节点分成若干互不相交的子树。每个非根节点只有一个父节点。从根到某个节点的通路因此唯一。

孩子之间的次序如果有意义，就得到有序树。森林是零棵或多棵互不相交的树组成的集合，在本节常考虑它们的排列次序。

二叉树另有一个重要约定：它可以为空；非空时，由根、左二叉子树和右二叉子树组成。**左边只有一个孩子与右边只有一个孩子，是不同的二叉树。** 所以不能把二叉树简单等同于“每个节点至多有两个孩子的一般树”。

本文把根的深度定义为 0，深度按边数计。高度是节点最大深度；涉及空树时会单独处理，不把节点数与边数混作一个高度。

还要区分树和共享结构。如果 `A` 与 `B` 都指向同一个节点 `C`，这张引用图已经不符合普通树的“不相交子树”要求。复制两份相同内容，与两条链接共享一个对象，具有不同的修改和回收语义。

## 2. §2.3.1：三种遍历，是根被访问的时机不同

考虑下面的二叉树，缺少的孩子位置视为空：

```text
        A
       / \
      B   C
       \ /
        D E
```

| 遍历 | 递归动作次序 | 本例结果 |
|---|---|---|
| 先根序 | 根、左、右 | A B D C E |
| 中根序 | 左、根、右 | B D A E C |
| 后根序 | 左、右、根 | D B E C A |

先根序适合先处理一个对象再进入它的组成部分；后根序适合先得到子树结果再计算父节点。对表达式树求值时，必须先得到运算数，后根序就很自然。

中根序与“排序”之间没有自动的联系。只有树另外满足二叉搜索树的键值约束，中根访问才产生相应的有序键序列。

### 栈保存的是尚未完成的工作

原书算法 T 用辅助栈实现中根遍历：沿左链下降时保存祖先；到达空位置后取回一个节点、访问它，然后转向右子树。

下面把同一个想法展开成三个阶段，一次得到三种次序。节点表示为 `(值, 左子树, 右子树)`，空树为 `None`。输入须是有限、无环且无共享节点的二叉树，遍历期间不改变结构。

```python
def traversals(root):
    pre, ino, post = [], [], []
    stack = [(root, 0)]
    while stack:
        node, phase = stack.pop()
        if node is None:
            continue
        value, left, right = node
        if phase == 0:
            pre.append(value)
            stack.append((node, 1))
            stack.append((left, 0))
        elif phase == 1:
            ino.append(value)
            stack.append((node, 2))
            stack.append((right, 0))
        else:
            post.append(value)
    return pre, ino, post


t = ("A", ("B", None, ("D", None, None)),
          ("C", ("E", None, None), None))
for result in traversals(t):
    print(" ".join(result))
```

输出与上表一致。`phase=1` 表示“左子树处理后还要回来”，`phase=2` 表示“右子树处理后还要回来”。这与 §1.4 中保存调用状态的思想相通。

每个节点只经历固定次数的阶段，时间为 $O(n)$。不计结果列表，辅助栈占 $O(h+1)$ 空间，其中 $h$ 是非空树的高度；退化为一条链时仍可能达到 $O(n)$。改成循环不会自动消除保存状态的需要。

### 穿线树：利用原本为空的链接

有 $n$ 个节点的非空二叉树共有 $2n$ 个孩子位置，而实际孩子边只有 $n-1$ 条，因此空位置有

$$
2n-(n-1)=n+1.
$$

穿线表示把部分空链接用于保存遍历中的前驱或后继，并用标记区分“孩子”与“线索”。例如寻找中根后继时，若右字段是线索，就直接沿线索走；若它是真实右子树，则进入右子树并持续沿真实左孩子下降。

一旦忘记检查标记，把线索当成孩子递归，原本正确的树遍历就可能回到祖先而反复运行。穿线节省某些遍历所需的辅助状态，也要求插入、删除时维护更多规则。

## 3. §2.3.2：用两个链接表示一般树

一般树的节点可能有很多孩子。一个固定格式的办法是保存：

```text
first_child：第一个孩子
next_sibling：下一个兄弟
```

例如 `R` 的孩子依次是 `A、B、C`，`B` 的孩子是 `D、E`：

```text
R.first_child = A
A.next_sibling = B
B.next_sibling = C
B.first_child = D
D.next_sibling = E
```

把 `first_child` 当作二叉表示的左链接，`next_sibling` 当作右链接，就得到左孩子、右兄弟表示。

但两条链接的原始语义不同：`B → C` 是兄弟关系，不能说 `C` 在原树中是 `B` 的孩子。由此得到的二叉树高度，也不能直接当作原树高度。

单棵一般树的根没有兄弟，因此转换后的根没有右子树；若是森林，各棵树的根则可以沿兄弟链接串起来。

这种对应还给出有用的遍历关系：森林的先根序对应二叉表示的先根序；森林的后根序对应二叉表示的中根序。第二个关系需要注意“兄弟也是右链接”这一点，不能机械地把两边的后根序对应起来。

## 4. §2.3.3：有些关系可以计算，有些值得显式保存

树不必只用独立分配的指针节点表示。原书也讨论顺序表示、标记和子树范围。

如果按先根序连续存放节点，那么一棵子树中的节点会形成一个连续区间。额外保存子树末端位置，就可以快速跳过整棵子树；若只保存少量形状标记，也可能重建更多关系，但查询时需要扫描或额外计算。

这是一个反复出现的选择：

| 多保存的信息 | 可能加快的操作 | 需要维护的代价 |
|---|---|---|
| 父节点链接 | 从孩子向上移动 | 修改父子关系时同步更新 |
| 子树范围或大小 | 跳过子树、计算规模 | 插入删除后更新范围或计数 |
| 遍历前驱、后继 | 按指定顺序移动 | 结构变化时修复辅助链接 |
| 连续存储中的位置规则 | 通过算术找到某些节点 | 动态修改可能需要搬移 |

静态结构与频繁变化的结构，不一定适合相同的表示。省去一个字段，只有在后续重建它所需的信息不会造成更大成本时才有意义。

## 5. §2.3.4：数学性质给操作代价一个尺度

这一部分覆盖自由树、有向树、无穷性引理、树的枚举与通路长度。下面抓住三条能直接用于分析的主线。

### 5.1 先说明正在数哪一种树

自由树不指定根，作为图是连通且无回路的。有限非空自由树有 $n-1$ 条边，任意两个顶点间有唯一简单通路。

指定根、规定边的方向、规定孩子次序、给节点加可区分标号，都会改变“两个树是否相同”的标准。因此，“$`n`$ 个节点的树有多少种”还不是一个完整的计数问题。

原书不同上下文中的“有向树”有特定方向约定；学习时应先看边朝向根还是离开根，不能仅凭箭头图的外观套用术语。

### 5.2 二叉树形状与 Catalan 数

令 $b_n$ 是具有 $n$ 个节点、不带标号、区分左右的二叉树形状数，空树计作一种，即 $b_0=1$。

非空树占掉一个根以后，若左子树有 $k$ 个节点，右边就有 $n-1-k$ 个；两边可以独立选择，因此

$$
b_n=\sum_{k=0}^{n-1}b_kb_{n-1-k}.
$$

设 $B(z)=\sum_{n\ge0}b_nz^n$，则

$$
B(z)=1+zB(z)^2,
\qquad
B(z)=\frac{1-\sqrt{1-4z}}{2z}.
$$

选择负号分支，是因为要满足常数项 $B(0)=1$；右侧在 0 处按形式幂级数理解。得到

$$
b_n=\frac{1}{n+1}\binom{2n}{n}.
$$

前几项为 $1,1,2,5,14,42$。它们不是“所有无根树”的数量。对于含 $m\ge1$ 个节点的一般有序树，借助前面的森林对应，形状数为 $b_{m-1}$，还要注意这一位移。

这正好连接 §1.2 的递归、生成函数与二项式系数：表示方式一旦明确，计数递推就来自根的分解。

### 5.3 内外通路长度

给每个空孩子位置补一个外部节点，得到扩充二叉树。原有的 $n$ 个节点称为内部节点，新补的外部节点有 $n+1$ 个。

记内部节点深度之和为 $I$，外部节点深度之和为 $E$，则

$$
E=I+2n.
$$

可以从空树逐步生长来证明。把深度为 $d$ 的一个外部节点换成内部节点，再增加两个深度为 $d+1$ 的外部孩子：$`I`$ 增加 $d$，$`E`$ 增加 $2(d+1)-d=d+2$，所以 $E-I$ 每次增加 2。

下面直接计算这些量：

```python
def path_lengths(root):
    n = internal = external = 0
    stack = [(root, 0)]
    while stack:
        node, depth = stack.pop()
        if node is None:
            external += depth
            continue
        n += 1
        internal += depth
        stack.append((node[1], depth + 1))
        stack.append((node[2], depth + 1))
    return n, internal, external


print(path_lengths(t))
```

输出 `(5, 6, 16)`，满足 $16=6+2\times5$。

若树退化成一条链，$`I=0+1+\cdots+(n-1)=n(n-1)/2`$；尽量填满浅层，可以显著降低总深度。

这不能推出“任何随机树的平均深度都是对数级”。对所有二叉树形状均匀取样，与由随机插入过程产生一棵搜索树，是不同的概率模型。讨论平均代价时必须说明树是怎样产生的。

若访问概率不相同，还应考虑带权通路长度 $\sum_i p_i d_i$；节点数相同、甚至高度相同，也不足以决定这个量。

### 5.4 无穷性引理的有限分支条件

原书的无穷性引理指出，在每个节点只有有限个孩子的无限有根树中，存在一条无限分支。直观理由是：如果一个节点有无限多个后代，而孩子只有有限个，那么至少一个孩子也必须有无限多个后代；重复选择即可继续。

有限分支条件不能删掉。根若有无限多个叶孩子，总节点数无限，却没有无限深的分支。研究搜索过程的终止性时，这个区别十分关键。

## 6. §2.3.5：允许共享与循环，回收就不能只看局部

原书的列表可以包含原子和其他列表，也可以共享子列表，甚至形成递归引用。到了这里，存储图已经可能超出树的范围。

如果两个入口都引用同一个子结构，删除一个入口并不意味着这个子结构可以释放。引用计数通过维护被引用次数处理这种共享；但纯粹的引用计数不能自动处理所有环：两个已失去外部入口的对象可以互相引用，让计数始终非零。

标记与清扫换了一个判断标准：

1. 从程序当前持有的所有根入口出发，沿合法引用标记可达节点。
2. 扫描整个存储池，把未标记节点加入空闲结构。

下面只返回可回收编号，不实际删除对象。`heap` 中每个值是该节点的出边列表；假设回收期间图不变化，所有根和链接都正确登记。

```python
def unreachable(heap, roots):
    marked = set()
    stack = []

    def discover(p):
        if p is None:
            return
        if p not in heap:
            raise ValueError("根或链接指向不存在的节点")
        if p not in marked:
            marked.add(p)
            stack.append(p)

    for p in roots:
        discover(p)
    while stack:
        p = stack.pop()
        for child in heap[p]:
            discover(child)
    return set(heap) - marked


heap = {0: [1], 1: [2], 2: [1], 3: [4], 4: [3], 5: []}
print(sorted(unreachable(heap, [0])))
```

输出 `[3, 4, 5]`。`1、2` 虽然成环，但从根 0 可达；`3、4` 也成环，却没有根能到达它们。是否有环，与是否可回收，是两个问题。

这份示例用显式栈和集合，按通常散列表代价，标记阶段为 $O(V_r+E_r)$，扫描全部节点还需 $O(V)$；$`V_r,E_r`$ 指可达子图规模。标记阶段的辅助空间为 $O(V_r)$，末尾构造节点全集及返回可回收集合还需要 $O(V)$ 空间。原书还研究辅助存储非常紧张时如何完成标记，不能把这份易读代码当作那些省空间算法的实现。

“不可达”也必须相对于正确的根集合。漏记一个仍在使用的入口，会把活节点误判为垃圾；一直保留一个无用入口，又会阻止其下游被回收。

## 7. 把树的几个层次分开

读这一节时，可以始终保留三张图：问题中的逻辑树、内存中的链接图，以及算法执行时保存的遍历状态。三者经常相关，却不完全相同。

左孩子、右兄弟表示改变了箭头的含义；穿线增加了遍历辅助边；共享列表又打破了子树互不相交的前提。只有把这些变化说清楚，遍历、计数和回收的结论才知道该用在哪里。
