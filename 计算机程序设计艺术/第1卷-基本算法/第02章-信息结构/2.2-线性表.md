# 【计算机程序设计艺术 TAOCP】卷1·2.2 线性表：一次插入的代价，取决于怎样存储

> 对应原书：§2.2，第 227—292 页。本文将 §2.2.1—§2.2.6 合为一篇，围绕操作、表示与边界条件整理；程序为自拟教学实现。

“数组访问快，链表插入快”很容易记，却省掉了决定结论是否成立的条件。

插入位置已经找到了吗？有没有空余空间？需要维护几个入口？空表和只剩一个节点时怎么办？§2.2 的价值，就在于把这些问题逐项展开。

## 1. §2.2.1：先规定操作，再选择容器

线性表是一个有限序列。相邻关系与元素的逻辑位置有关，与内存地址是否连续无关。

栈、队列和双端队列进一步限制了允许的操作位置：

| 结构 | 插入位置 | 删除位置 | 顺序特点 |
|---|---|---|---|
| 栈 | 同一端 | 同一端 | 后进先出 |
| 队列 | 尾端 | 首端 | 先进先出 |
| 双端队列 | 两端 | 两端 | 可从两端处理 |

它们首先是操作约定。栈可以用连续数组，也可以用链表；一个数组同样可以通过不同的入口规则实现队列。

例如任务必须按到达顺序处理，就需要队列语义。选择了队列以后，才继续决定容量是否固定、如何表示队首队尾，以及满了以后返回错误还是扩充存储。

不要把“用了链表”当作“已经定义了队列”。

## 2. §2.2.2：顺序分配把关系变成地址算术

若每个元素占 $c$ 个存储单位，从 0 开始编号，首元素地址为 $B$，则

```math
\mathop{\mathrm{addr}}\nolimits(i)=B+ci.
```

访问第 $i$ 项只需计算地址。代价是：中间插入时，为保持连续排列，后面的元素需要移动。长度为 $n$ 的表，在位置 $i$ 前插入，需要移动 $n-i$ 项；这里还未计入容量不足时的重新分配。

连续存储实现栈很直接：用长度作为下一个空位置，入栈写入末端，出栈读取末项并减少长度。但必须在改变状态之前判断是否允许操作。

“上溢”和“下溢”也不应被忽略。它们分别意味着存储容量不足，以及试图从空结构中取出元素。算法说明不能把这两种情况永远当作不会发生。

### 循环队列：回收已经用过的前端位置

如果队列每次入队都把尾下标加一，出队只把首下标加一，前面的空位就不能复用。把下标对容量取模，可以让固定数组循环使用。

本文采用 `head + size` 表示法：

- `head` 指向当前首项；空队列时它仍是一个合法下标。
- `size` 为当前元素数，满足 $0\le size\le M$。
- 第 $k$ 项位于 `(head + k) % M`。
- 下一次入队位置为 `(head + size) % M`。

```python
class RingQueue:
    def __init__(self, capacity):
        if type(capacity) is not int or capacity <= 0:
            raise ValueError("容量必须是正整数")
        self.data = [None] * capacity
        self.head = 0
        self.size = 0

    def put(self, value):
        if self.size == len(self.data):
            raise OverflowError("队列已满")
        tail = (self.head + self.size) % len(self.data)
        self.data[tail] = value
        self.size += 1

    def get(self):
        if self.size == 0:
            raise IndexError("队列为空")
        value = self.data[self.head]
        self.data[self.head] = None
        self.head = (self.head + 1) % len(self.data)
        self.size -= 1
        return value

    def values(self):
        m = len(self.data)
        return [self.data[(self.head + k) % m] for k in range(self.size)]


q = RingQueue(3)
q.put("A")
q.put("B")
print(q.get())
q.put("C")
q.put("D")
print(q.values())
print([q.get(), q.get(), q.get()])
```

输出为 `A`、`['B', 'C', 'D']`、`['B', 'C', 'D']`。最后一次入队已经绕回数组前端，逻辑次序没有改变。

这个实现可以存满全部 $M$ 个位置，因为额外保存了 `size`。另一种常见规则只保存两个下标，并保留一个空位置来区分满和空，其可用容量为 $M-1$。两套规则都能成立，但满空判断不能混搭。

在固定容量模型下，`put` 与 `get` 都执行常数次操作；`values` 为了展示完整队列，需要 $O(n)$ 时间和结果空间。`None` 可以作为普通元素入队，队列是否为空由 `size` 判断。

原书还研究多个栈共享存储空间。两个栈从数组两端相向增长，可以共享尚未使用的中间区域；多个栈的增长和搬移则需要更细的分配策略。这再次说明：各表分别预留固定上限，可能浪费它们不同时达到峰值的空间。

## 3. §2.2.3：链接分配把关系写进字段

单链表的节点通常有内容字段和后继字段。已知节点 `P`，要在它后面插入新节点 `Q`：

```text
NEXT(Q) ← NEXT(P)
NEXT(P) ← Q
```

如果新节点已经分配好，只修改两条链接即可。但是，“在第 $k$ 项后插入”还包括寻找第 $k$ 项；只有首入口的单链表，需要沿链走到那里。

删除同样要问清楚手里有什么。已知前驱 `P`，可以绕过 `NEXT(P)`；若只知道待删节点 `Q`，通常还要找到它的前驱。通过复制后继内容来“删除当前节点”的技巧，会改变节点身份，也无法一般地处理末节点，不能代替任意删除操作。

### AVAIL：空闲节点也组织成一个表

原书把未使用的节点链接成 `AVAIL` 表，通常按栈处理。申请节点是从表头取一个，归还节点是放回表头。

```text
申请：先检查 AVAIL 非空；取出首节点，再把 AVAIL 移到后继。
归还：先让归还节点指向原 AVAIL，再更新 AVAIL。
```

这里隐含了所有权条件：已在空闲表中的节点不能再次归还；仍被业务结构使用的节点不能提前归还。否则即使每次赋值都合法，两个表也会错误地共享同一块存储。

链接分配让节点不必相邻，却增加了链接字段和间接访问。若性能取决于实际机器，还应分析节点分布和访存行为，不能仅凭同为 $O(n)$ 就断言遍历成本相同。

## 4. §2.2.4：循环表必须重新定义结束条件

循环表的末节点指回首节点。保存尾节点 `tail` 时，首节点可以通过 `NEXT(tail)` 得到，因此一个入口就能定位两端。

非空表在尾端插入 `Q`：

```text
NEXT(Q) ← NEXT(tail)
NEXT(tail) ← Q
tail ← Q
```

空表需要单独初始化：`NEXT(Q)=Q`，然后令 `tail=Q`。删除最后一个节点时，也必须把入口改为空，而不是留下一个已经归还给 `AVAIL` 的节点位置。

遍历不能再等待空链接。它要在回到起点时结束，或者使用一个不承载普通数据的表头节点作为停止标记。表头方案中，“没有数据”仍可以表示为表头指向自身。

循环表还适合拼接两张互不相交的表：交换尾节点的后继，再调整入口，就能连接两个环。前提是两表确实不相交，并且操作以后旧入口的归属已明确；不能把同一张表误当成两张来拼接。

### 多项式为什么出现在这里

原书以多项式运算展示循环表的用途。若只保存非零项，每个节点需要系数、指数和后继。按指数次序存储以后，加法可以像合并两个有序序列一样进行。

以下用普通 Python 列表保留“逐项合并”的核心，不复刻原书的多变量循环节点格式。输入约定为：指数是非负整数、严格递减、系数非零；每个指数只出现一次。

```python
def add_sparse(a, b):
    i = j = 0
    out = []
    while i < len(a) and j < len(b):
        ea, ca = a[i]
        eb, cb = b[j]
        if ea > eb:
            out.append(a[i])
            i += 1
        elif ea < eb:
            out.append(b[j])
            j += 1
        else:
            if ca + cb != 0:
                out.append((ea, ca + cb))
            i += 1
            j += 1
    out.extend(a[i:])
    out.extend(b[j:])
    return out


# (3x^4 + 2x - 5) + (-3x^4 + 7x^2 + 5)
print(add_sparse([(4, 3), (1, 2), (0, -5)],
                 [(4, -3), (2, 7), (0, 5)]))
```

结果为 `[(2, 7), (1, 2)]`，即 $7x^2+2x$。相消后的零系数项被删掉。两个输入各有 $m,n$ 项时，每一步至少推进一个位置，时间为 $O(m+n)$；结果最多有 $m+n$ 项。

“结果里没有零项、指数保持次序”就是这种表示需要维护的不变式。

## 5. §2.2.5：双重链接把前驱也存下来

双向节点同时保存 `left` 和 `right`。配合循环表头 `H`，空表可以统一写成：

```text
H.left = H
H.right = H
```

对表中的节点 `x`，应满足：

```text
x.left.right is x
x.right.left is x
```

已知一个普通节点 `x` 后，删除它只需连接两侧邻居：

```text
x.left.right ← x.right
x.right.left ← x.left
```

最后才处理 `x` 的回收或脱离标记。表头不能按普通数据节点删除。

如果在相邻节点 `a、b` 之间插入 `x`，可以先设置 `x.left=a`、`x.right=b`，再令 `a.right=x`、`b.left=x`。检查修改后的两条互逆关系，比只看向右遍历是否成功更全面。

原书进一步用离散模拟说明它的用途：事件在离散时刻发生，模拟时钟可以跳到下一个事件时间；如果需要取消一个已经排入表中的事件，已知节点的双向删除就很有价值。

但是，**删除快不意味着按时间找到插入位置也快**。若事件表靠线性查找维持时间次序，插入仍可能需要扫描许多节点。一个操作的局部优势，不能推广为整个应用的所有步骤都很快。

## 6. §2.2.6：数组和正交表，把一维关系推广到多个方向

二维数组的一个元素同时属于一行和一列。对于 $m\times n$ 数组、从 0 开始的下标以及每项 $c$ 个存储单位，按行排列时：

```math
\mathop{\mathrm{addr}}\nolimits(i,j)=B+c(in+j).
```

按列排列时：

```math
\mathop{\mathrm{addr}}\nolimits(i,j)=B+c(jm+i).
```

两种公式中的行数、列数不能交换使用。一般多维数组可通过各维步长计算偏移。

如果只存下三角部分，行长不再相同。从 0 开始，按行存储 $0\le j\le i$ 的元素，每项一个单位时，偏移为：

$$
\frac{i(i+1)}2+j.
$$

这里前 $i$ 行共有 $1+2+\cdots+i$ 项，因此出现三角数。

正交链接提供了另一种表示：一个节点同时参与多个方向的表。例如矩阵非零项可以沿行连接，也可以沿列连接；同一个记录也可以按若干属性进入不同链。

它的收益是提供多条访问路径，代价是更新时维护所有路径。沿行删除了节点，却忘记修复列链接，就会留下不一致的结构。下一节之后的 §2.4 会进一步讨论这种多重关系。

## 7. 比较复杂度时，写清楚“已知什么”

下表忽略存储申请的额外成本，并采用每次字段访问、地址计算为常数代价的模型。

| 操作与已知条件 | 连续顺序表 | 单链表 | 双向链表 |
|---|---:|---:|---:|
| 按下标访问第 $k$ 项 | $O(1)$ | $O(k)$ | 仅有首入口时 $O(k)$ |
| 已找到位置，在中间插入 | 通常需搬移，最坏 $O(n)$ | 已知前驱时 $O(1)$ | 已知相邻节点时 $O(1)$ |
| 已知待删节点，删除它 | 保持紧凑时最坏 $O(n)$ | 一般还需找前驱 | $O(1)$ |
| 按顺序访问全部元素 | $O(n)$ | $O(n)$ | $O(n)$ |
| 结构字段 | 入口、长度等 | 每项一个后继 | 每项两个方向 |

动态数组末尾追加的均摊分析、真实分配器和机器访存成本，还需要各自的假设，不能由这张表直接推出。

读完这一节，可以拿任意一种表示追问四件事：入口在哪里，空状态是什么，每次操作改哪些位置，操作完成后如何证明关系仍然正确。把这些问题回答清楚，代码中的指针和下标才有可检查的含义。
