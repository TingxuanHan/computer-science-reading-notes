# 【计算机程序设计艺术 TAOCP】卷1·2.4 多重链接结构：一个名字，可能需要多条查找路径

> 对应原书：§2.4，第 399—408 页。本文围绕原书的层次数据与限定名称解析整理，代码为简化教学模型，不是完整 COBOL 编译器。

一个节点属于一棵树，却未必只需要树上的父子链接。假如程序还要按名称寻找它、列出同名项、查找兄弟，单一的访问路径就不够方便。

§2.4 的具体应用是编译器中的层次数据描述。它把前面学过的树、链表和辅助入口组合起来，回答一个实际问题：**用户写下一个名字以后，程序如何判断他指的是哪个数据项？**

## 1. 同名不等于同一个对象

考虑两组自拟数据：

```text
ORDER
  ADDRESS
    CITY
    CODE
  PAYMENT
    CODE

SUPPLIER
  ADDRESS
    CITY
    CODE
```

这里有两个 `CITY`，三个 `CODE`。名称字符串相同，不代表它们是同一个字段。

`CITY OF ADDRESS` 仍有两个候选；`CITY OF ORDER` 则可以唯一确定订单地址中的城市。按照原书讨论的限定规则，中间层可以省略，只要剩余限定足以唯一识别，并且祖先的相对次序正确。

这与要求写出每一段的严格路径不同。解析器不能把它直接当成字符串拼接，也不能找到第一个同名节点就停止。

## 2. 原书给出了三个操作目标

原书第 401 页先列出需要完成的工作，再决定字段格式：

| 操作 | 需要回答的问题 |
|---|---|
| 构造数据表 | 如何把名称及层次描述变成内存结构 |
| 检查限定访问 | 名称能否匹配，是否恰好匹配一个数据项 |
| 找出对应项 | 两个数据组中哪些字段应按对应关系配对 |

这些操作需要不同的移动方向：构造时从父项连接孩子，限定查询时从候选向祖先走，对应匹配时又要访问两组内部的结构。

于是原书提出五类字段：

| 字段 | 含义 |
|---|---|
| `PREV` | 前一个同名数据项 |
| `PARENT` | 直接包含它的最小数据组 |
| `NAME` | 对应的符号表条目 |
| `CHILD` | 第一个孩子 |
| `SIB` | 下一个兄弟 |

符号表还为每个名称保存一条入口链接，指向最近加入的同名项。沿 `PREV` 就能枚举该名称的所有候选。

这里的 `PREV` 是“同名链的前一项”，不是前一个兄弟，更不是声明顺序中的前一个任意节点。一个字段对应哪种关系，必须固定下来。

## 3. 不同链接叠加在同一批节点上

在例子中，三个 `CODE` 同时出现在两种结构里：

```text
父子关系：ORDER → ADDRESS → CODE
          ORDER → PAYMENT → CODE
          SUPPLIER → ADDRESS → CODE

同名关系：最新 CODE → 上一个 CODE → 更早的 CODE → 空
```

并不需要复制三套完整数据。每个数据项只保存一份自身内容，另外增加不同含义的链接字段。

如果同名项有 $k$ 个，而全部数据项有 $N$ 个，按名称找到入口以后，可以把候选扫描范围从全部 $N$ 项缩小为这 $k$ 项。之后仍需检查各候选的祖先链；增加一个索引并不等于整个查询已经是常数时间。

同样，`PARENT` 可以从其他结构中重新找出，但显式保存它通常能让向上查询更直接。是否值得多占一个字段，应根据实际操作判断。

## 4. 构造时，栈记录当前的层次路径

原书算法 A 接收名称和层次号。层次号不必连续；它表达相对层次关系，并要求符合书中给出的同层规则。

可以用栈保存尚未结束的祖先。遇到更深层次就建立孩子关系；遇到同层则建立兄弟关系；层次回退时弹出已结束的部分，并检查回退后的层次是否合法。

同时，每加入一个新节点 `Q`，还要更新同名链：

```text
PREV(Q) ← 此名称原来的入口
此名称的入口 ← Q
```

因此，“构造了一棵正确的树”还不足以证明整个多重链接结构正确，同名索引也必须完整。

下面的示例直接传入父节点编号，省去层次号的语法解析，集中展示五类关系。为方便构造，另用 `last_child` 保存各组的最后一个孩子；`name` 直接保存字符串，没有实现独立的符号驻留表。

```python
class DataTable:
    def __init__(self):
        self.nodes = []
        self.by_name = {}
        self.last_child = {}

    def add(self, name, parent=None):
        if parent is not None and (type(parent) is not int
                                   or not 0 <= parent < len(self.nodes)):
            raise ValueError("父节点不存在")
        i = len(self.nodes)
        node = {"name": name, "parent": parent, "child": None,
                "sib": None, "prev": self.by_name.get(name)}
        self.nodes.append(node)
        self.by_name[name] = i
        if parent in self.last_child:
            self.nodes[self.last_child[parent]]["sib"] = i
        elif parent is not None:
            self.nodes[parent]["child"] = i
        self.last_child[parent] = i
        return i

    def candidates(self, name, qualifiers=()):
        result = []
        p = self.by_name.get(name)
        while p is not None:
            q = self.nodes[p]["parent"]
            matched = True
            for qualifier in qualifiers:
                while q is not None and self.nodes[q]["name"] != qualifier:
                    q = self.nodes[q]["parent"]
                if q is None:
                    matched = False
                    break
                q = self.nodes[q]["parent"]
            if matched:
                result.append(p)
            p = self.nodes[p]["prev"]
        return result

    def resolve(self, name, qualifiers=()):
        matches = self.candidates(name, qualifiers)
        if not matches:
            raise LookupError("没有匹配的数据项")
        if len(matches) != 1:
            raise ValueError("限定不足，仍有同名歧义")
        return matches[0]


table = DataTable()
order = table.add("ORDER")
address = table.add("ADDRESS", order)
city = table.add("CITY", address)
table.add("CODE", address)
payment = table.add("PAYMENT", order)
table.add("CODE", payment)
supplier = table.add("SUPPLIER")
other_address = table.add("ADDRESS", supplier)
table.add("CITY", other_address)
table.add("CODE", other_address)

print(table.resolve("CITY", ["ORDER"]) == city)
print(table.resolve("CITY", ["ADDRESS", "ORDER"]) == city)
print(len(table.candidates("CODE", ["ORDER"])))
print(table.candidates("CITY", ["ORDER", "ADDRESS"]))
```

输出：

```text
True
True
2
[]
```

最后一个查询把祖先顺序写反了。查到 `ORDER` 后再向上，无法找到它下面的 `ADDRESS`，所以没有候选。

## 5. 唯一性检查不能提前结束

查询首先从 `by_name[name]` 出发，沿同名链寻找候选；对每个候选，再从父节点开始匹配限定名称。

限定名称按“离目标较近的祖先在前”给出，可以跳过无关的中间层，但不能倒转顺序。同一祖先也不能重复消耗两次，所以匹配以后要继续向其父节点移动。

如果找到一个匹配项就返回，会错把 `CODE OF ORDER` 当作成功。它在订单中仍有两个解释：地址编码和付款编码。正确的解析应区分：

- 0 个匹配：名称或限定不存在。
- 1 个匹配：唯一解析成功。
- 多于 1 个匹配：仍有歧义。

设候选数为 $k$，最大祖先链长度为 $h$，限定项数为 $q$，这份实现的查询上界为 $O(k(h+q+1))$，不计字符串长度；每个候选的祖先指针只向上走，不为每个限定重新从头扫描。名称入口使用字典，其查找按通常的平均代价理解。

## 6. 对应字段不一定处于相同位置

原书还讨论 `MOVE CORRESPONDING` 一类操作。它要找的是两组中名称与限定层次相对应的数据项，而不是把两组叶节点按出现顺序逐一配对。

例如一个记录的日期顺序为 `MONTH、DAY、YEAR`，另一个是 `DAY、MONTH、YEAR`。按序号复制会交换月和日；按名称识别相应字段才符合问题语义。

进一步，如果不同子组里都有 `CODE`，只比较叶名称又不够，还需要考察组内相对限定路径。**限定访问中允许省略中间层，不表示对应字段匹配也能任意省略层次。** 原书对后者另外给出了更精确的定义。

本文代码只实现候选枚举与限定查询，没有实现完整的对应赋值、类型转换或语言语法检查。读原书算法时，先写下操作各自的定义，才能判断某条辅助链接是否必要。

## 7. 多存一条链接，也多了一项维护责任

如果把 `CITY` 改名，树上的父子关系也许完全不变，同名链却必须把它从旧名称下移走，再接到新名称下。

如果移动一个子树，名称索引可以仍然有效，但根节点的 `PARENT`、旧父节点的孩子链和新父节点的孩子链都要保持一致。

因此，可以为这类结构保留几条检查规则：

1. 同名链中的每个节点确实具有对应名称，且不重复、不成环。
2. 每个非根节点恰好出现在其父节点的孩子链中一次。
3. 兄弟链中的节点具有相同父节点。
4. 所有索引指向同一批真实数据项，不能留下已删除节点。

这些规则与具体语言无关。它们解释了本节最有用的设计方法：先列出要支持的查询与修改，再给每条链接一个明确用途，最后让操作同时维护这些关系。
