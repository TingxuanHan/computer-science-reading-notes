# 【计算机程序设计艺术 TAOCP】卷1·1.3 MIX：把算法放进一台具体的机器

> 对应原书：第 1 卷《基本算法》第 3 版，§1.3“MIX”，书内第 120—177 页，包含 MIX 的描述、MIX 汇编语言以及对排列的应用。底本为苏运霖译、国防工业出版社 2002 年版。本文用自拟小例子说明核心规则，不逐条重列全部指令。

上一节分析寻找最大值时，我们数了比较次数和更新次数。要继续计算运行代价，还得知道：一次比较对应哪些指令？变量保存在寄存器还是内存？跳转会修改哪些状态？

MIX 为这些问题提供了一个共同的机器模型。读这一节时，可以把目标定得具体一些：能够跟踪一段程序中的寄存器、有效地址和控制流，而不只是记住指令名字。

## 1. 先认识 MIX 的“字”

MIX 是原书定义的假想计算机。一个字由一个独立的正负号与五个字节组成：

```text
位置    0    1    2    3    4    5
内容   符号  b1   b2   b3   b4   b5
```

这里的字节不能直接套用现代常见的 8 位字节。原书要求一个字节至少容纳 64 种值，至多容纳 100 种值；二进制 MIX 可用 6 位表示一个字节，十进制 MIX 可用两位十进制数表示。

用 $B$ 表示一个字节的进制，则字的数值为

$$
\mathit{sign}\times
(b_1B^4+b_2B^3+b_3B^2+b_4B+b_5),
\qquad 0\le b_i<B.
$$

例如同样的字节序列 `(0, 0, 1, 2, 3)`，在 $B=64$ 时表示 4227，在 $B=100$ 时表示 10203。因此，不能一边把字节按十进制拼接，一边声称程序适用于所有 MIX 字节大小。

符号与数值部分分离，也意味着存在正零与负零的表示。只用一个普通 Python 整数保存字，会丢掉这种表示差异；模拟机器时需要意识到这一点。

## 2. 寄存器与内存各自保存什么

| 部件 | 容量或状态 | 主要用途 |
|---|---|---|
| `rA` | 符号 + 5 字节 | 累加器，算术与数据操作 |
| `rX` | 符号 + 5 字节 | 扩展寄存器，可与 `rA` 配合处理乘积、被除数等 |
| `rI1`—`rI6` | 各为符号 + 2 字节 | 计数、变址 |
| `rJ` | 2 字节，符号为正 | 保存有关跳转的返回位置 |
| 比较指示器 | 小于、等于、大于 | 为条件跳转提供依据 |
| 溢出开关 | 开或关 | 记录有关算术溢出状态 |
| 内存 | 4000 个字，地址 0—3999 | 保存指令与数据 |

`rJ` 不应被当作指向当前执行位置的通用程序计数器；它主要参与子程序链接等控制转移。不同跳转指令是否更新它，也有明确规则。

读一个程序时，先写出变量到存储位置的对应关系会很有帮助。例如累加和放在 `rA`，剩余元素个数放在 `rI1`。这样每条指令的动作就能接回算法中的变量变化。

## 3. 字段 `(L:R)`：一次可以只处理字的一部分

字段左右边界都包含在内，位置 0 表示符号。例如：

| 字段 | 选中内容 | 编码 $F=8L+R$ |
|---|---|---:|
| `(0:5)` | 整个字 | 5 |
| `(1:5)` | 全部数值字节，不含符号 | 13 |
| `(0:2)` | 符号与前两个字节 | 2 |
| `(4:5)` | 最右两个字节 | 37 |

注意字段编码使用固定的 $8L+R$，这里的 8 不是字节进制 $B$。

### 装载：选出的数值字节靠右

假设某内存字为

```text
- | 1 | 2 | 3 | 4 | 5
```

用 `LDA` 装入不同字段，结果为：

```text
字段 (0:3)  →  - | 0 | 0 | 1 | 2 | 3
字段 (2:4)  →  + | 0 | 0 | 2 | 3 | 4
字段 (0:0)  →  - | 0 | 0 | 0 | 0 | 0
```

选中的数值字节向右对齐，左侧补零。字段包含符号就复制符号，否则装入正号。最后一行也说明为什么需要保留负零表示。

### 存储：取寄存器右端，放入目标字段

如果 `rA` 为

```text
+ | 9 | 8 | 7 | 6 | 5
```

执行 `STA`，向上述内存字的 `(2:3)` 字段写入，得到

```text
- | 1 | 6 | 5 | 4 | 5
```

因为目标字段需要两个字节，所以使用寄存器最右侧的 `6,5`。未选中的数值字节和符号保留原样，寄存器自身也不改变。装载与存储的字段规则不同，不能把两者都理解成同一段位置的直接复制。

## 4. 一条指令怎么读

MIX 指令同样占一个字，其结构可写成：

```text
符号 | 地址部分 A（2 字节）| 变址 I | 修饰 F | 操作码 C
```

常用的可读表示为：

```text
OP ADDRESS,I(F)
```

对于使用内存地址的常见指令，有效地址为

$$
M=A+\begin{cases}
0,&I=0,\\
rI_I,&1\le I\le6.
\end{cases}
$$

例如 `rI2=7`，执行

```text
LDA 1000,2(1:3)
```

就是访问内存地址 1007，将其第 1—3 字节装入 `rA` 的右端，符号取正。字段编码为 $8\times1+3=11$。

`I` 是选择哪个变址寄存器，不是直接把数字 2 加到地址上。`F` 也并非总表示字字段：输入输出指令会用它表示设备编号，其他一些指令还把它作为操作变体的选择。

此外，地址部分的含义随指令变化。`ENTA 5` 把有效量 5 放入 `rA`，而 `LDA 5` 从地址 5 的内存字装载。把这两个动作混为一谈，程序就会从初始化开始出错。

## 5. MIXAL：符号名怎样连接到地址

MIXAL 是 MIX 的汇编语言。符号名使人不必手工维护每一条数字地址，但执行语义仍来自 MIX 指令。

常见伪操作需要与运行时指令区分：

| 写法 | 汇编阶段的含义 |
|---|---|
| `N EQU 5` | 将符号 `N` 定义为数值 5 |
| `ORIG 1000` | 设置后续内容的存放位置 |
| `CON 3` | 生成一个值为 3 的字 |
| `END START` | 结束汇编源程序，并指定启动位置 |

`EQU` 不会在程序运行时给某个变量执行赋值。`ORIG` 也不是 CPU 执行的一次跳转。

下面是本文自拟的求和示例。数据为五个小的正整数，避免本例涉及溢出；`N` 必须至少为 1，且与实际数据个数一致。

```text
N       EQU     5
        ORIG    1000
DATA    CON     3
        CON     1
        CON     4
        CON     1
        CON     5
SUM     CON     0
        ORIG    3000
START   ENTA    0
        ENT1    N
LOOP    ADD     DATA-1,1
        DEC1    1
        J1P     LOOP
        STA     SUM
        HLT
        END     START
```

开始时 `rA=0,rI1=5`。第一条 `ADD` 的有效地址为 $1000-1+5=1004$，因此先加最后一个元素。`DEC1 1` 使计数减一，`J1P LOOP` 在计数为正时继续循环。

| 加法前的 `rI1` | 访问地址 | 读出的值 | 加法后的 `rA` |
|---:|---:|---:|---:|
| 5 | 1004 | 5 | 5 |
| 4 | 1003 | 1 | 6 |
| 3 | 1002 | 4 | 10 |
| 2 | 1001 | 1 | 11 |
| 1 | 1000 | 3 | 14 |

最后将 14 写到 `SUM`。在不溢出、地址合法的前提下，进入循环时已经累计了右侧处理过的元素；每轮再加一个元素，计数从 $N$ 下降到 0。这就是上一节的循环证明在机器状态上的具体形式。

这个程序动态执行 $3N+4$ 条指令：两条初始化、每轮三条、最后存储与停机两条。**指令条数并不等于 MIX 时间单位数**，不同指令可能有不同代价。精确时间应把每种指令的执行次数乘以规定代价后求和。

原书 §1.3.2 的最大值程序则得到 $(5+5n+3A)u$，其中 $A$ 正是上一节分析的更新次数，$u$ 是模型时间单位。这个式子依赖书中那一份具体程序，不能直接套到其他实现或当作真实 CPU 的秒数。

上面的 MIXAL 示例按指令定义与地址表逐步核对；下方 Python 只演示特定字段语义，没有把它冒充为完整 MIX 汇编器或模拟器。

## 6. 用 Python 检查字段装载和存储

用 `(符号, 五个字节)` 保存一个字，符号取 `1` 或 `-1`。下面约定输入字已经合法，字段满足 $0\le L\le R\le5$。

```python
def load_field(word, left, right):
    sign, data = word
    chosen = data[max(1, left) - 1:right]
    result_sign = sign if left == 0 else 1
    return result_sign, (0,) * (5 - len(chosen)) + chosen


def store_field(memory_word, register_word, left, right):
    old_sign, old_data = memory_word
    reg_sign, reg_data = register_word
    start = max(1, left) - 1
    count = right - start
    result = list(old_data)
    if count:
        result[start:right] = reg_data[-count:]
    return (reg_sign if left == 0 else old_sign), tuple(result)


word = (-1, (1, 2, 3, 4, 5))
reg = (1, (9, 8, 7, 6, 5))
print(load_field(word, 0, 3))
print(load_field(word, 2, 4))
print(load_field(word, 0, 0))
print(store_field(word, reg, 2, 3))
```

输出为：

```text
(-1, (0, 0, 1, 2, 3))
(1, (0, 0, 2, 3, 4))
(-1, (0, 0, 0, 0, 0))
(-1, (1, 6, 5, 4, 5))
```

这些函数不处理指令译码、算术溢出、变址或 I/O；它们用于把一个容易混淆的机器规则拆开检查。

## 7. 对排列的应用：沿循环移动，先约定方向

§1.3.3 进一步研究排列，把抽象的重排落实为存储操作。这里用从 0 开始的映射

$$
p=[2,0,1,4,3]
$$

举例。它的循环结构为 $(0\ 2\ 1)(3\ 4)$，即 $0\mapsto2\mapsto1\mapsto0$，以及 $3\mapsto4\mapsto3$。

必须先约定数组重排的方向。本文采用

$$
\mathit{new}[i]=\mathit{old}[p[i]].
$$

因此 `[a,b,c,d,e]` 会变成 `[c,a,b,e,d]`。如果约定的是 `new[p[i]] = old[i]`，那是相反方向的移动，不能混用同一张箭头图。

沿一个循环逐个覆盖时，需要先暂存起点，否则原值可能尚未被使用就丢失。这与 §1.1 的赋值顺序问题完全呼应。

```python
def gather_by_cycles(values, p):
    n = len(values)
    if len(p) != n or sorted(p) != list(range(n)):
        raise ValueError("p 必须是 0 到 n-1 的排列")
    a = list(values)
    seen = [False] * n
    for start in range(n):
        if seen[start]:
            continue
        saved = a[start]
        i = start
        while True:
            seen[i] = True
            j = p[i]
            if j == start:
                a[i] = saved
                break
            a[i] = a[j]
            i = j
    return a


print(gather_by_cycles(list("abcde"), [2, 0, 1, 4, 3]))
```

输出为 `['c', 'a', 'b', 'e', 'd']`。这里为便于阅读，使用了结果副本和访问标记，额外空间为 $O(n)$；验证排列时还使用了排序。它展示循环移动，不宣称实现了原书中进一步压缩辅助空间的技巧。

逆排列 $q$ 则满足 $q[p[i]]=i$，可逐项填写。讨论排列的复合时也必须声明哪一个先执行；“从右向左应用”的数学记法与“按书写顺序依次执行”的程序描述容易交叉。

## 8. 读 MIX 程序时，先做这几件事

先把变量对应到寄存器和内存，再为每条访存指令算出有效地址；遇到字段操作，分别检查符号、对齐方向和未被修改的部分；遇到跳转，写出下一条执行位置，并检查 `rJ` 等状态是否改变。

然后选一个足够小的输入，把每轮状态列出来，最后才合并执行次数。这样读 MIX，算法中的抽象动作与机器中的具体动作就能相互校验。
