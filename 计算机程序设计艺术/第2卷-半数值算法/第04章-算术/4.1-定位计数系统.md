# 【计算机程序设计艺术 TAOCP】卷2·4.1 定位计数系统：同一个数，为什么有不同的运算法则

> 对应《计算机程序设计艺术》第 2 卷《半数值算法》第三版中文译本，§4.1，书内第 175-192 页。第 192 页同时开始 §4.2。本文围绕原书主线重新组织，例子和 Python 程序为自拟。

看到 `11110011`，还不能断定它是多少。若它是无符号八位整数，值为 243；若按八位二进制补码解释，值为 -13；若它只是某个大整数的一组数字，还需要知道它处在什么位置。

第四章从这个问题开始：计算机执行算术之前，必须先规定表示。位权、数字范围、字长和解释规则，共同决定一次进位究竟意味着什么。

## 1. 位权把一串符号变成一个数

在通常的整数基数 $b\ge 2$ 下，数字串表示

$$
(a_m\cdots a_1a_0.a_{-1}a_{-2}\cdots)_b
=\sum_k a_kb^k,\qquad 0\le a_k<b.
$$

例如

$$
(230.4)_5=2\cdot25+3\cdot5+\frac45=65.8.
$$

“逢 $b$ 进一”来自恒等式 $b\cdot b^k=b^{k+1}$。它不是附加在表示之外的技巧，而是保持数值不变的重写规则。

非负整数反复做欧几里得除法

$$
n=bq+r,\qquad 0\le r<b
$$

就能逐位取出最低位。余数的唯一性给出数字的唯一性；商逐步减小，保证过程结束。零单独写成一个零，其他数不保留前导零。

对于无限小数，唯一性要额外约定。十进制的 $0.999\ldots=1$ 就说明：允许无限尾部以后，同一个值可能有“有限展开”和“末尾全是最大数字”的两种写法。

## 2. 定点的小数点，是解释规则的一部分

存储整数 $I$，约定缩放量为 $b^{-s}$，就可以把它解释为

$$
x=Ib^{-s}.
$$

若两个操作数用同一个 $s$，整数相加后仍按同一比例解释；相乘则变成 $IJb^{-2s}$。如果结果还要使用原来的缩放量，就必须除去额外的 $b^s$，并规定怎样舍入。

所以，小数点未必占据一个存储位置，程序仍必须知道它在哪里。忽略这一约定，会使完全正确的整数乘法产生错误的业务数值。

基数之间也有结构上的捷径。因为 $16=2^4$，四个二进制位可合成一个十六进制数字；分组应从小数点向两侧展开。任意两个进制通常没有这种等长分组关系，§4.4 会专门处理一般转换。

## 3. 补码先做模运算，再选择有符号解释

原书比较了带符号的量表示法、基数补码和减一补码。以八位二进制为例，可以先看它们的表示范围：

| 表示方法 | 可表示范围 | 零的表示 |
|---|---|---|
| 符号与绝对值 | $-127$ 到 $127$ | 正零、负零 |
| 一的补码 | $-127$ 到 $127$ | 两种零 |
| 二的补码 | $-128$ 到 $127$ | 一种零 |

对 $w$ 位二的补码，先把位串看成 $0\le r<2^w$ 的无符号数，再解释为

$$
\operatorname{signed}(r)=
\begin{cases}
r,&r<2^{w-1},\\
r-2^w,&r\ge2^{w-1}.
\end{cases}
$$

编码负整数就是取模 $2^w$。八位中的 $-13$ 对应 $256-13=243$，即 `11110011`。按位取反再加一，是计算这个模意义下相反数的一种方式。

这里需要区分两个结果：$127+1$ 的整数值是 128；若只保留八位，再按有符号补码解释，得到 -128。模加法本身没有算错，但整数加法的结果已经超出约定范围，这叫有符号溢出。

最小负数的相反数也超出范围，因为正端少了一个位置。检测溢出不能只看最高位是否产生进位：无符号范围和有符号范围是两种不同的契约。

## 4. 负进制不需要额外的负号

基数也可以是负数。以 $b=-2$ 为例，仍只使用数字 0、1，但位权交替为正负：

$$
(110111)_{-2}=-32+16+0+4-2+1=-13.
$$

写表示时，仍然要求

$$
n=bq+r,\qquad 0\le r<|b|.
$$

要小心语言中的除法约定。Python 对负除数做 `divmod` 时，非零余数为负；它并不直接满足上面的数字范围。若初始余数 $r<0$，令

$$
q\leftarrow q+1,\qquad r\leftarrow r-b.
$$

等式保持不变，而且新余数进入正确范围。反复取余便得到从低位到高位的数字。

这个方法的关键是约束数字范围，而不是把普通正进制转换结果简单加上一个负号。解码则很统一：从最高位开始反复计算“当前值乘基数，再加下一位”。

## 5. 平衡三进制把符号分散到每一位

平衡三进制使用数字 $-1,0,1$，位权仍为 $3^k$。为了避免排版歧义，下面直接用数字列表书写：

$$
[1,0,-1]_3=9-1=8,\qquad [-1,-1,-1]_3=-9-3-1=-13.
$$

取余时若出现 2，就把它写成 $-1$，并向商进一，因为 $2=3-1$。其他余数保持不变。

这种表示有很直观的性质：对每个数字取相反数，就得到整个数的相反数。$p$ 位能够覆盖的整数范围为

$$
-\frac{3^p-1}{2}\ \le n\le\ \frac{3^p-1}{2}.
$$

范围关于零对称。最低位由模 3 的剩余类唯一决定，取出最低位后递归处理商，就能说明表示唯一，忽略无意义的前导零即可。

原书还讨论复数基数。这里不展开它的几何构造；阅读时可抓住同一个问题：给定一组位权和允许的数字，哪些值能够表示，表示是否唯一，进位如何保持数值不变？

## 6. 混合进制：每一位有自己的进位门槛

时间中的秒、分、小时已经是熟悉的例子。如果逐位基数为 $b_0,b_1,\ldots$，最低位权重为 1，那么更高位的权重依次为

$$
1,\ b_0,\ b_0b_1,\ b_0b_1b_2,\ldots
$$

每一位的合法范围也随基数改变。

阶乘数系取权重 $1!,2!,3!,\ldots$，对应数字满足 $0\le c_k\le k$。例如

$$
23=3\cdot3!+2\cdot2!+1\cdot1!.
$$

最高位以下各位的最大总和恰为下一位权重减一，因为

$$
\sum_{k=1}^{m}k\,k!=(m+1)!-1.
$$

这解释了为什么它能连续表示整数，也解释了进位边界为何恰好合适。排列编号等问题中会遇到这种表示；它与固定基数系统共享逐位除法的思想。

## 7. Python：把编码和解码分开验证

下面的程序只处理整数。数字列表按最高位在前排列；负进制和补码示例都使用明确的规则，不依赖机器整数的隐式溢出。

```python
def decode(digits, base):
    value = 0
    for digit in digits:
        value = value * base + digit
    return value


def negabase(n, base=-2):
    if base > -2:
        raise ValueError("base must be <= -2")
    if n == 0:
        return [0]
    digits = []
    while n:
        n, r = divmod(n, base)
        if r < 0:
            n += 1
            r -= base
        digits.append(r)
    return digits[::-1]


def balanced3(n):
    if n == 0:
        return [0]
    digits = []
    while n:
        n, r = divmod(n, 3)
        if r == 2:
            n += 1
            r = -1
        digits.append(r)
    return digits[::-1]


def signed_word(raw, width):
    if width < 1 or not 0 <= raw < (1 << width):
        raise ValueError("invalid word")
    return raw if raw < (1 << (width - 1)) else raw - (1 << width)


for n in range(-200, 201):
    for base in (-2, -3, -10):
        digits = negabase(n, base)
        assert all(0 <= d < -base for d in digits)
        assert decode(digits, base) == n
    assert decode(balanced3(n), 3) == n

print(negabase(-13))
print(balanced3(8))
print(signed_word((-13) % 256, 8))
print(signed_word((127 + 1) % 256, 8))
```

输出：

```text
[1, 1, 0, 1, 1, 1]
[1, 0, -1]
-13
-128
```

检查采用“先编码，再按位权解码”的方式。两部分分别实现，能发现余数符号、数字顺序和进位修正方面的错误。最后一行验证的是固定字长的解释规则，并不表示 Python 整数相加会自动变成 -128。
