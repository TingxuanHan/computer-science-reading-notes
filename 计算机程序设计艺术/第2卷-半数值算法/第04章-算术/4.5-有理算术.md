## 1. 分数的规范形式是一条程序不变量

用整数对 $(a,b)$ 表示 $a/b$，通常约定

$$
b>0,\qquad \gcd(|a|,b)=1.
$$

于是零只有一种表示 $(0,1)$，相等判断也可以直接比较两个规范整数对。例如 $(2,6)$、$(-1,-3)$ 都应整理成 $(1,3)$。

规范化不是输出时的装饰。若每次运算都留下公因子，后续乘法要处理的整数会越来越大。约分消耗一次最大公因子计算，却可能省下更多大整数运算。

以乘法为例，最直接的方法是先算 $ac$ 和 $bd$，再约分。对已经约成最简形式的 $a/b$ 与 $c/d$，可以先交叉消去

$$
g_1=\gcd(|a|,d),\qquad g_2=\gcd(|c|,b),
$$

然后计算

$$
\frac ab\frac cd
=\frac{(a/g_1)(c/g_2)}{(b/g_2)(d/g_1)}.
$$

原来每个分数内部已经互素，剩下可能的约分只发生在交叉位置。这解释了为什么处理完这两个公因子，乘积也已经最简。

例如 $35/22$ 乘 $33/14$，先约掉交叉的 $7$ 和 $11$，最后只需算 $5\cdot3$ 与 $2\cdot2$，得到 $15/4$。

## 2. 分数相加，为什么最后只需检查一个小公因子

设两个输入已经规范化，先令

$$
g=\gcd(b,d),\qquad b'=b/g,\qquad d'=d/g.
$$

那么

$$
\frac ab+\frac cd
=\frac{ad'+cb'}{gb'd'}.
$$

记 $t=ad'+cb'$。因为 $\gcd(b',d')=1$，且 $a$ 与 $b$、$c$ 与 $d$ 分别互素，所以

$$
\gcd(t,b')=\gcd(t,d')=1.
$$

例如模 $b'$ 考察 $t$，它与 $ad'$ 同余，而 $a$ 和 $d'$ 都与 $b'$ 互素。因此分子剩下的公因子只能来自 $g$。令

$$
h=\gcd(|t|,g),
$$

就得到最简结果

$$
\frac{t/h}{(b/g)(d/h)}.
$$

这里每个除法都能整除。最后一次 gcd 的一个输入只是 $g$，而不必是整个新分母。若 $t=0$，公式也能正确返回 $(0,1)$。

这个推导依赖“输入已经最简”的前提。忽略前提，只照搬最后的公式，会破坏结果的规范性。

## 3. gcd 无需先分解整数

从素因子分解出发，最大公因子可以通过各素数指数的最小值计算。但把两个大整数先完全分解，再求 gcd，通常把一个容易的问题变成了更难的问题。

欧几里得算法只需恒等式

$$
\gcd(a,b)=\gcd(b,a-qb).
$$

取 $q=\lfloor a/b\rfloor$，右边第二个参数就是余数。共同因子集合没有变化，而非零余数严格小于除数，所以算法终止。

程序中先取绝对值，可以统一处理负数；边界约定为

$$
\gcd(a,0)=|a|,\qquad \gcd(0,0)=0.
$$

如果同步记录每个余数如何由原输入线性组合得到，还能求出贝祖系数：

$$
ax+by=g,\qquad g=\gcd(a,b).
$$

当 $g=1$ 时，$x$ 就给出了 $a$ 模 $b$ 的逆元。求 gcd、求模逆、处理分数因此可以共享同一套整数运算基础。

原书还讨论了二进制 gcd 等变体。二进制方法利用偶数移位，以及两个奇数之差为偶数的性质，减少一般除法。选择哪种实现，需要看机器上的除法、移位和多精度操作成本。

## 4. 连续斐波那契数为何让欧几里得算法走得更久

令 $F_1=F_2=1$。对相邻斐波那契数，余数链几乎每次只退回一个斐波那契数：

$$
F_{k+1}=F_k+F_{k-1}.
$$

商长期为 $1$，意味着余数下降得慢。原书给出的精确结论是：对 $u>v>0$，若恰好需要 $n$ 次除法，满足条件的最小输入对为

$$
(u,v)=(F_{n+2},F_{n+1}).
$$

这里把最后一次得到零余数的除法也计入。比如 $(13,8)$ 的余数依次为 $5,3,2,1,0$，共五步。

由于斐波那契数随下标指数增长，反过来可知除法步数为 $O(\log v)$，对 $v=1$ 单独处理即可。若输入有 $L$ 个二进制位，这表示步数是 $O(L)$；它没有说全部计算只需 $O(L)$ 次位操作。大整数除法本身有成本。

平均情形也必须明确输入分布。原书先考察一个把余数近似当作均匀随机量的模型，再指出这个模型会高估步数。余数由除法结构产生，不能仅因输入随机，就把每一轮都当成独立均匀抽样。这与上一章讨论随机性时的警惕是一致的。

欧几里得算法产生的商还构成连分数展开。最坏情形中大量的 $1$，既是慢速下降的余数链，也是连分数结构的一种表现。

## 5. 因子分解比“会算 gcd”多了什么

试除法从小因子开始，找到因子后反复除去。当当前试除数的平方大于剩余整数时，若剩余数大于 $1$，它只能是素数。原因是任意合数都至少有一个不超过其平方根的因子。

这给出了简单、可靠的小规模算法，但对两个大素数的乘积，试除可能走得很远。

原书的 $\rho$ 方法则利用模未知因子的碰撞。设 $p\mid N$，若某两个迭代值满足

$$
x_i\equiv x_j\pmod p,
$$

那么 $p$ 整除它们的差。计算

$$
g=\gcd(|x_i-x_j|,N)
$$

就有机会发现因子。若 $1<g<N$，得到非平凡因子；若 $g=1$，尚未找到；若 $g=N$，本次碰撞没有分离出因子，需要调整或重启。发现的 $g$ 也可能是合数，还要继续处理。

这里 gcd 成为探测因子的工具，但 gcd 算法本身没有神奇地完成分解。素性判定也应另行区分：一次模幂等式成立，可能只是通过一项必要条件；要得到素性证明，还需要相应定理的全部条件。本文代码采用试除法，便于把正确性完整检验清楚。

## 6. Python：规范分数、贝祖系数与小整数分解

下面只使用标准库。整数对始终保持“分母为正、分子分母互素”。`Fraction` 用作独立的结果参照。

```python
from math import gcd, prod
from fractions import Fraction


def rational(a, b):
    if b == 0:
        raise ZeroDivisionError("denominator is zero")
    if b < 0:
        a, b = -a, -b
    g = gcd(a, b)
    return a // g, b // g


def multiply(x, y):
    a, b = rational(*x)
    c, d = rational(*y)
    g1, g2 = gcd(a, d), gcd(c, b)
    return (a // g1) * (c // g2), (b // g2) * (d // g1)


def add(x, y):
    a, b = rational(*x)
    c, d = rational(*y)
    g = gcd(b, d)
    t = a * (d // g) + c * (b // g)
    h = gcd(t, g)
    return t // h, (b // g) * (d // h)


def extended_gcd(a, b):
    r0, r1 = abs(a), abs(b)
    x0, x1, y0, y1 = 1, 0, 0, 1
    while r1:
        q, r = divmod(r0, r1)
        r0, r1 = r1, r
        x0, x1 = x1, x0 - q * x1
        y0, y1 = y1, y0 - q * y1
    return r0, x0 if a >= 0 else -x0, y0 if b >= 0 else -y0


def factor(n):
    if n < 1:
        raise ValueError("n must be positive")
    out = []
    d = 2
    while d * d <= n:
        while n % d == 0:
            out.append(d)
            n //= d
        d = 3 if d == 2 else d + 2
    if n > 1:
        out.append(n)
    return out


print(multiply((35, 22), (33, 14)))
print(add((7, 66), (17, 12)))
g, x, y = extended_gcd(240, 46)
print(g, x, y, 240 * x + 46 * y)
print(factor(360))

for a in range(-12, 13):
    for b in range(1, 13):
        left, right = (a, b), (7, 15)
        assert Fraction(*add(left, right)) == Fraction(*left) + Fraction(*right)
        assert Fraction(*multiply(left, right)) == Fraction(*left) * Fraction(*right)
assert factor(1) == []
assert prod(factor(360)) == 360
```

输出为：

```text
(15, 4)
(67, 44)
2 -9 47 2
[2, 2, 2, 3, 3, 5]
```

除了数值相等，还应检查返回分母为正、结果已约分；否则一个永远返回未约分结果的程序也能通过单纯的数值比较。对分解结果，也应同时检查乘积与每个因子的素性，而不只看列表是否“像素数”。

## 7. 读完这一节可以抓住的联系

精确分数需要 gcd 来控制规模；扩展 gcd 又提供模逆；欧几里得算法的商把程序连接到连分数与最坏情形分析；因子分解则反过来把 gcd 用作发现隐藏因子的探针。
