# 【计算机程序设计艺术 TAOCP】卷2·4.2 浮点算术：误差从哪里来，又怎样被放大

> 对应《计算机程序设计艺术》第 2 卷《半数值算法》第三版中文译本，§4.2，书内第 192-239 页，包含单精度计算、精确度、双精度计算和浮点数的分布。第 239 页同时开始 §4.3。

把一行公式翻译成程序，最容易被忽略的变化，是每个中间结果都可能已经舍入。数学上的结合律允许我们任意加括号，有限精度计算却需要为每一种顺序分别负责。

这一节不只是解释“小数为什么存不准”。原书沿着表示、基本运算、误差传播和输入分布，逐步追问一个数值程序为什么可信。

## 1. 范围和精度是两个维度

为了便于推导，本文把非零正规化浮点数写成

```math
x=\pm m b^e,\qquad 1\le m\lt b,
```

其中有效数 $m$ 只有 $p$ 位 $b$ 进制数字。指数控制数量级，$`p`$ 控制每个数量级内能分辨多少位置。

原书第三版采用小数部分绝对值在 $[1/b,1)$ 内的记号，并包含 MIX 的指数偏置；把小数部分乘以 $b$、相应调整指数，就能与这里的形式对应。不要直接比较两种记号的指数数字。

在区间 $[b^e,b^{e+1})$ 内，相邻正数之间的间距为

$$
\Delta=b^{e-p+1}.
$$

越大的数，绝对间距越大。扩大指数范围，并不会让每一个数携带更多有效数字；增加 $p$，也不等同于扩大允许的指数范围。

本文的教学模型暂时不限制指数。真实格式中的溢出、下溢、非正规数和特殊值，需要按具体格式另外分析。

## 2. 一次加法包含四件事

原书的浮点加法流程可以理解为：比较指数、对阶、相加、正规化并舍入。

例如只保留三位十进制有效数字，计算 $1000+1$。把两者放到相同指数后，精确结果为 1001；但这一数量级可表示的相邻三位有效数是 1000、1010 等，所以最近的结果仍是 1000。

减法也沿用这一流程，只是符号不同。若相消后前面出现许多零，就要向左移动有效数并调整指数。

乘法先乘有效数、相加指数，再做正规化；除法先除有效数、相减指数，再处理商和舍入。中间保留多少附加位很关键：若提前丢掉的信息不足以判断最后一次舍入方向，就可能得到错误的末位。

因此，“最终保留 $p$ 位”不意味着所有中间步骤只能保留 $p$ 位。原书讨论附加位和具体实现，正是为了使基本运算满足一个清楚的理想：先计算精确结果，再按规定舍入一次。

## 3. 单次相对误差界，需要写清前提

用 $`\mathop{\mathrm{fl}}\nolimits(x)`$ 表示最近舍入。若精确结果非零、处于适用的正规范围，且不发生指数溢出或下溢，则有

```math
\mathop{\mathrm{fl}}\nolimits(x)=x(1+\delta),\qquad
|\delta|\le u,\qquad u=\frac12 b^{1-p}.
```

推导很直接。对 $b^e\le |x|<b^{e+1}$，最近舍入的绝对误差不超过相邻间距的一半：

```math
|\mathop{\mathrm{fl}}\nolimits(x)-x|\le\frac12 b^{e-p+1}.
```

再除以 $|x|\ge b^e$，得到上述相对界。靠近相邻数量级的边界时，可以使用局部间距来得到更细的界，这里采用统一上界。

对一次基本运算，模型作用于它的精确结果，例如

```math
\mathop{\mathrm{fl}}\nolimits(a+b)=(a+b)(1+\delta).
```

这里的 $a,b$ 是实际送入运算的数。若它们已经是原始数据的近似值，前面的误差不会被这条公式自动消除。

## 4. 消去可能放大旧误差，而不产生新的舍入误差

设真实输入是 $x,y$，存储时变成 $x+e_x,y+e_y$。即使减法本身精确，差值也已经变成

$$
(x-y)+(e_x-e_y).
$$

当 $x-y$ 很小时，相对误差

$$
\frac{|e_x-e_y|}{|x-y|}
$$

可能很大。若 $|e_x|\le\eta|x|$、$`|e_y|\le\eta|y|`$，就得到上界

$$
\frac{|e_x-e_y|}{|x-y|}
\le\eta\frac{|x|+|y|}{|x-y|}.
$$

后面的比例说明减法问题对输入扰动有多敏感。

例如把 1.234 和 1.2335 先分别舍入为三位有效数字，两者都变成 1.23。相减精确地得到 0，而真实差值是 0.0005。不能把这件事概括成“减法器把结果算错了”：信息在输入舍入时已经丢失，随后相消使它显得格外严重。

## 5. 运算顺序会改变答案

仍在三位十进制有效数字模型中，令

$$
a=1000,\qquad b=1,\qquad c=-1000.
$$

如果每次加法后都舍入，那么

```math
\mathop{\mathrm{fl}}\nolimits(\mathop{\mathrm{fl}}\nolimits(a+b)+c)=0,
```

而

```math
\mathop{\mathrm{fl}}\nolimits(a+\mathop{\mathrm{fl}}\nolimits(b+c))=1.
```

第一条路径先把 1 丢掉了；第二条路径中的 -999 可以精确表示。

换一种顺序可能改善某个例子，却不构成对所有输入的保证。实际需要结合问题结构选择算法，并分析累计误差。原书还用方差计算说明，两个很大的近似量相减可能把一个很小的非负结果破坏掉；适当的递推形式可以减少这类相消。

类似地，判断迭代是否结束，不能默认一定会出现两次结果完全相等。需要结合问题量纲、绝对误差、相对误差和迭代上限设计停止条件。只设相对误差阈值，在结果接近零时也可能失效。

## 6. “双精度”要放回原书的实现背景

§4.2.3 讨论用两个机器字承载更高精度浮点数的办法。原书也明确交代了其中部分程序的历史背景：它们有具体的截断和精度取舍。

阅读时可分成三个问题：用了多少位有效数字，指数范围多大，基本运算是否按规定正确舍入。仅仅把结果放进两个字，不能保证这三个问题同时得到最理想的答案。

这些程序适合研究“有限机器操作怎样组合出更精细的算术”。若要实现某个现成格式，则应按该格式的完整规则检验，不能只凭名称相同就认定行为相同。

## 7. 浮点数的输入分布也会影响平均分析

§4.2.4 讨论浮点运算的统计特征，例如对阶所需的移动次数，以及有效数的首位数字分布。

一个常见误区，是把十进制首位 1 到 9 都视为等概率。在假定 $`\{\log_{10}X\}`$ 均匀分布于 $[0,1)$ 的模型下，首位为 $d$ 的概率是

$$
\Pr(D=d)
=\log_{10}(d+1)-\log_{10}d
=\log_{10}\left(1+\frac1d\right).
$$

推导来自区间：首位为 $d$ 恰好对应对数小数部分落在 $[\log_{10}d,\log_{10}(d+1))$。

这是一条带分布前提的结论。均匀抽取 1 到 9，首位当然各占九分之一；程序生成的数、带编号意义的数据，也不能未经检查套用对数模型。平均运行时间和平均误差的分析，应先说明输入从哪里来。

## 8. Python：不用宿主浮点数模拟舍入

下面使用 `Fraction` 保存精确有理数，模拟 $p$ 位十进制有效数字，采用最近舍入，正好居中时取偶数。它不模拟指数边界或任何完整硬件格式。

```python
from fractions import Fraction


def round_decimal(x, p=3):
    if p < 1:
        raise ValueError("p must be positive")
    x = Fraction(x)
    if not x:
        return x
    sign = -1 if x < 0 else 1
    x = abs(x)
    scale = Fraction(1)
    while x < scale:
        scale /= 10
    while x >= 10 * scale:
        scale *= 10
    step = scale / (10 ** (p - 1))
    t = x / step
    q, r = divmod(t.numerator, t.denominator)
    twice = 2 * r
    if twice > t.denominator or (twice == t.denominator and q % 2):
        q += 1
    return sign * q * step


def add(a, b):
    return round_decimal(Fraction(a) + Fraction(b))


a, b, c = map(Fraction, (1000, 1, -1000))
print(add(add(a, b), c), add(a, add(b, c)))
x, y = Fraction("1.234"), Fraction("1.2335")
print(x - y, add(round_decimal(x), -round_decimal(y)))
print(round_decimal(Fraction("1.245")))
print(round_decimal(Fraction("1.255")))

for numerator in range(-500, 501):
    x = Fraction(numerator, 37)
    rounded = round_decimal(x)
    assert round_decimal(rounded) == rounded
    if x:
        assert abs((rounded - x) / x) <= Fraction(1, 200)
```

输出：

```text
0 1
1/2000 0
31/25
63/50
```

最后两行分别是 1.24 和 1.26，展示居中取偶。输入十进制小数时使用字符串，避免先经过宿主浮点数而引入另一层舍入。

程序中的范围检查是有限验证；统一的相对误差界由前面的间距推导支持。二者各自承担不同任务。

## 9. 数值结果值得信任，需要一条完整理由

先明确表示和舍入，再把输入误差、单步舍入、误差传播分开分析。遇到不稳定的公式，考虑改变计算过程；需要更多精度时，说明增加的是哪些位、哪些中间步骤。

下一节转向多精度整数。它可以避免这里的浮点舍入，却仍要认真处理进位、借位、乘法结构和除法估商。
