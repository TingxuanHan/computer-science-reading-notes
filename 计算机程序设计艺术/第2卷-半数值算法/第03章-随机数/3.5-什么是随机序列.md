# 【计算机程序设计艺术 TAOCP】卷2·3.5 什么是随机序列：均匀、不可预测和不可压缩

> 对应原书：第2卷《半数值算法》第3版，§3.5，书页131至163。原书本节带星号，涉及无限序列、可计算性和拟随机数理论。本文保留不同定义之间的区别，用有限例子说明它们为何不能相互替代。

前几篇已经使用了“随机”这个词：随机数生成器、随机抽样、随机排列。到了§3.5，Knuth停下来追问它的含义。

一个序列看起来杂乱，是否就随机？如果所有数字出现得一样多呢？如果每一种短模式的频率都正确呢？本节不断加强定义，又不断检查加强后的要求是否过头。

## 1. 一维均匀分布只限制频率

对位于 $[0,1)$ 中的无限序列 $U_0,U_1,\ldots$，取任意区间 $[a,b)$，统计前 $N$ 项中落入该区间的个数：

$$
N_{a,b}(N)=\#\{0\leq n<N:a\leq U_n<b\}.
$$

如果对每个这样的区间都有

$$
\lim_{N\to\infty}\frac{N_{a,b}(N)}N=b-a,
$$

就称这个序列等分布。

这是给一个确定的无限序列规定长期频率，并不是说我们已经给它的每一项引入了随机抽取过程。概率模型中的随机变量与某个固定序列的极限频率，属于不同的描述。

一维频率还会漏掉次序。原书构造了这样的反例：让低于1/2的数和不低于1/2的数严格交替，同时让两个半区内部的数各自分布均匀。整个序列可以等分布，但下一项在哪个半区一眼就能判断。

因此，等分布只是一个起点。

## 2. 把要求扩展到所有固定长度的块

对于取值为0至 $b-1$ 的数字序列，可以要求每个长度为 $k$ 的固定模式，都以极限频率 $b^{-k}$ 出现。

例如在二进制中，$k=1$ 要求0和1各占一半；$k=2$ 还要求`00`、`01`、`10`、`11`各占四分之一。这里按连续起点统计模式，允许窗口重叠，讨论的是极限频率定义，不是在直接套独立样本的卡方分布。

如果对所有正整数 $k$ 都满足这一条件，原书称它为 $\infty$ 分布。对实数序列，对应要求连续 $k$ 项在 $k$ 维单位立方体的每个长方体内具有正确的极限频率。

这是很强的条件，却仍只约束固定长度窗口的长期表现。它不保证某个有限前缀好看：改动有限多个位置不会改变这些极限。

所以，一个具有这种性质的无限序列也可以以一百万个0开头。理论上的长期性质，不能直接替一个只运行一百万步的模拟作保证。

## 3. 一个能骗过短模式计数的八位循环

考虑循环块

```text
00010111
```

把它首尾相接。跨越末尾时继续从开头读，八个三位窗口依次是

```text
000 001 010 101 011 111 110 100
```

恰好包含全部八种三位模式，每种一次。这是一个三阶二进制 de Bruijn 循环的例子。它的一位、两位计数也完全平衡。

然而，把这个块反复复制，就得到周期为8的序列。知道前8位以后，所有后续位都可以预测。长度为4时，16种模式中只有8种能出现。

下面做精确计数，不需要用随机抽样来验证这一点：

```python
from collections import Counter
from itertools import product


def cyclic_counts(word, k):
    if not word or k <= 0 or any(bit not in "01" for bit in word):
        raise ValueError("need a binary word and positive k")
    return Counter(
        "".join(word[(i + j) % len(word)] for j in range(k))
        for i in range(len(word))
    )


word = "00010111"
for k in (1, 2, 3, 4):
    counts = cyclic_counts(word, k)
    all_words = ["".join(bits) for bits in product("01", repeat=k)]
    frequencies = [counts[w] for w in all_words]
    print(k, len(counts), min(frequencies), max(frequencies))

sequence = word * 9
correct = sum(sequence[i] == sequence[i - 8]
              for i in range(8, len(sequence)))
print("period-8 predictor:", correct, "/", len(sequence) - 8)
assert set(cyclic_counts(word, 3).values()) == {1}
```

输出：

```text
1 2 4 4
2 4 2 2
3 8 1 1
4 8 0 1
period-8 predictor: 64 / 64
```

这不是说短模式计数没有用，而是要把它的结论留在实际检查的范围里：这里确实证明了一至三位的循环计数平衡，同时也展示了四位缺失和完全可预测的周期。

循环窗口和普通有限串窗口也不同。后者有 $N-k+1$ 个起点，前者有 $N$ 个。实现测试时必须写清楚边界，否则“每种模式恰好一次”可能只是统计口径变了。

## 4. 不能要求躲开所有概率为零的集合

一个看似强有力的定义是：随机序列应满足独立随机抽取时，以概率1成立的所有性质。

问题在于“所有”没有限制。以公平独立比特为例，任意一个预先指定的无限序列，其出现概率都为0。若允许事后针对观察到的序列，提出“不要等于这个序列”这一性质，那么每个序列都会被某个概率1性质排除。

这不是概率论矛盾。可数并与任意不可数并不能混用：不能把“每个单点概率为0”直接累加成“所有可能结果的总概率为0”。

原书通过若干定义和反例，说明随机性标准必须限制允许使用的检验方式。否则标准可能过弱，也可能强到没有任何序列能满足。

## 5. 选择子序列时，能使用哪些信息

一种加强方法是要求：不仅原序列频率正常，按某些规则取出的无限子序列也应频率正常。

但如果允许“看到当前位是1就留下”，选出的子序列当然全是1。这样的规则把答案本身用于选择，不能用来衡量预测以前是否存在可利用的偏差。

因此需要明确规则的可用信息。例如，在读第 $n$ 位以前，只允许根据位置和已经看到的前缀，决定是否选取这一位。规则还需要有可计算性限制，并且结论只针对选出了无限多项的情况。

对前面的八位周期串，一个简单规则是每隔8位取同一个位置。选择只依赖下标，完全不必偷看当前值，得到的子序列却是常数。这给出了比总体频数更强的反例。

原书从固定可计算位置序列，推进到依赖已见数据的选择规则，再讨论更一般的重排与选择。它们对应的形式化定义并非自动等价，文章中的简化解释也不能当作这些定理的替代证明。

还需区分一个存在性问题：证明某种意义下的随机序列存在，并不意味着已经有一个能按位算出它的实际生成程序。原书在讨论可计算规则的枚举时，专门解释了这类差别。

## 6. 短程序能描述的串，与难以区分的输出

本节后半部分转向有限序列。一个思路是看描述长度：若一个很长的串可以用“把`00010111`重复一百万遍”描述，那么它具有明显的可压缩结构。

严格的算法信息论需要先固定程序描述系统，再讨论生成该串的最短程序长度。短描述给出了“它可以被压缩”的证据；普通压缩软件没压短，却不证明已经找到了最短描述。最短程序长度也不是一个可以靠通用搜索总能算出的实用评分器。

另一个更接近生成器使用方式的思路，是比较两个输出分布。

设 $S$ 为随机种子，$G(S)$ 输出 $N$ 位；另设 $U_N$ 为真正独立公平的 $N$ 位。给定输出0或1的测试程序 $A$，考察

$$
\left|\Pr[A(G(S))=1]-\Pr[A(U_N)=1]\right|.
$$

若这个差值很小，测试程序就难以利用输出区分两种来源。原书借此讨论检验、预测下一位和计算时间之间的联系。

这里必须给测试者的计算能力或运行时间设定范围。若种子只有 $s$ 位，而输出有 $N>s$ 位，则输出最多有 $2^s$ 种。一个能够穷举全部种子的测试，可以检查输入是否属于这张输出表。

在生成器分布下它总接受；在均匀 $N$ 位分布下，接受概率至多为 $2^{s-N}$。因此，无限计算能力总能发现这种支持集的差别。实际问题在于：给定资源的测试能不能有效找到差别。

这个论证也说明，确定性扩展没有凭空制造更多独立信息。一个短种子却可能支持大量对某类应用足够难以区分的输出，这才是拟随机数理论关心的方向。

## 7. 回到有限程序，该怎样表达结论

不同语境中的“随机”最好具体写成可检查的陈述：

| 陈述 | 能够支持的内容 | 不能顺带推出什么 |
|---|---|---|
| 一维频数接近理论值 | 这次观察的边缘分布没有明显偏差 | 相邻值独立 |
| 某些块计数平衡 | 指定长度、指定边界规则下的模式分布 | 所有长度都平衡 |
| 无限序列等分布 | 长期极限频率 | 有限前缀满足应用误差要求 |
| 给定选择规则下仍均匀 | 这些规则没有提取出偏差 | 任意更强规则也不能 |
| 某类计算测试难以区分 | 指定资源和误差条件下的区分能力 | 对无限算力完全等同于真随机 |

本节的困难就在这些限定条件里。省略它们以后，听起来更简洁，却很容易把不同定理说成同一件事。

最后的§3.6将回到程序员的工作：在这些理论与实际限制下，怎样选择方法、保存状态，并检查自己的应用。
