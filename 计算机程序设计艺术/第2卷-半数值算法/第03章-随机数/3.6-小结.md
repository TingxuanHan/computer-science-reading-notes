读到第三章最后，最自然的疑问是：知道了周期、检验、转换和随机性定义以后，实际写程序时到底该怎么做？

## 1. 一次随机调用经过了哪些层

应用里的 `random()` 看起来只有一行，实际包含一条链：

```text
初始化状态 → 更新状态 → 映射输出 → 转换分布 → 应用消费
```

每一层都可能出问题。

如果初值进入零固定点，状态更新就没有机会发挥作用。如果递推正确，但整数映射到目标范围时出现取模偏差，抽样仍然不公平。如果每次调用的边缘分布没问题，但应用总以某种特殊步长取值，也可能暴露联合结构。

因此，记录一个“随机种子”不足以完整说明一次实验。还需要生成方法、参数、初始化规则、输出映射，以及谁在什么次序调用它。

例如新增一行调试代码，如果也从同一个发生器取数，就会改变后续所有应用输入。并行任务若共享一个发生器，调度顺序也可能影响各任务拿到哪一段输出。

## 2. 原书的几类实现，分别付出什么代价

§3.6 先回顾单状态线性同余法，随后讨论素数模的乘法形式、两个生成器的组合，以及保存更多状态的延迟递推。

| 方法 | 状态与实现特点 | 读代码时应追问 |
|---|---|---|
| 混合线性同余 | 一个整数状态，更新简单 | 满周期条件、低位问题、乘法溢出 |
| 素数模乘法同余 | 非零状态，按模乘法更新 | 合法种子、准确算术、联合分布 |
| 组合生成器 | 多个状态与组合规则 | 参数配合、输出范围、组合后的性质 |
| 延迟递推 | 一组历史状态，适合批量生成 | 初始化、数组更新顺序、批次边界 |

原书的一个素数模例子使用

$$
m=2^{31}-1=2147483647,\qquad a=48271,
$$

以及 $X_{n+1}=aX_n\bmod m$。这里 $X_0$ 必须在1至 $m-1$ 之间。把0当成“普通种子”会让全部后继值变成0。

原书还给出

$$
X_j=(X_{j-100}-X_{j-37})\bmod2^{30}
$$

形式的延迟递推与初始化程序。它的状态、批量输出和流之间的关系需要一起理解，不能只抄这一行式子、随便填100个整数，就认为复现了完整方案。

本节也明确讨论了某些方法在特定经验检验和应用中的缺陷。它并没有把“本章给出了实现”当成“不必再检查”的理由。

## 3. 乘法溢出会改变你以为正在使用的递推

数学中的 $aX\bmod m$ 要先算精确乘积再取余。固定字长机器上的乘法可能先发生溢出，这时程序执行的是另一种运算。

对上面的参数，原书采用分解

$$
m=aq+r,\qquad q=44488,\quad r=3399.
$$

写 $X=q\lfloor X/q\rfloor+(X\bmod q)$，则

$$
aX\equiv a(X\bmod q)-r\lfloor X/q\rfloor\pmod m.
$$

先计算右边，如果为负就加上 $m$。对这里的参数和合法状态，中间两项都能受到适当控制，从而避免直接形成很大的 $aX$。

下面在 Python 中实现这个分解形式。Python 自身有任意精度整数，所以可以用直接的模乘法作独立对照。将同一公式移到其他语言时，仍要核对该语言的整数范围、除法和负数取余规则。

## 4. 保存完整状态，才能从中间继续

程序调试通常有两个不同需求：从相同种子重跑整段实验；从一个中间位置准确恢复。后者需要保存当前状态。

如果生成器还有输出缓冲、缓存的正态数或其他内部索引，这些信息也必须一并保存。下面的教学实现只有一个递推状态，另外记录已经输出多少项，便于检查调用过程。

```python
class ReplayLCG:
    M = 2147483647
    A = 48271
    Q = 44488
    R = 3399
    NAME = "lcg-48271-mod-2147483647-v1"

    def __init__(self, seed):
        if type(seed) is not int or not 0 < seed < self.M:
            raise ValueError("seed must be an integer in 1..M-1")
        self.x = seed
        self.draws = 0

    def next_int(self):
        value = self.A * (self.x % self.Q) - self.R * (self.x // self.Q)
        if value < 0:
            value += self.M
        self.x = value
        self.draws += 1
        return value

    def uniform(self):
        return self.next_int() / self.M

    def checkpoint(self):
        return {"algorithm": self.NAME, "state": self.x, "draws": self.draws}

    @classmethod
    def restore(cls, data):
        if data.get("algorithm") != cls.NAME:
            raise ValueError("incompatible algorithm")
        count = data.get("draws")
        if type(count) is not int or count < 0:
            raise ValueError("invalid draw count")
        obj = cls(data.get("state"))
        obj.draws = count
        return obj


rng = ReplayLCG(1)
prefix = [rng.next_int() for _ in range(3)]
saved = rng.checkpoint()
suffix = [rng.next_int() for _ in range(5)]
restored = ReplayLCG.restore(saved)
replayed = [restored.next_int() for _ in range(5)]
print(prefix)
print(suffix == replayed)
print(restored.draws)

x = 1
reference = []
for _ in range(3):
    x = 48271 * x % 2147483647
    reference.append(x)
assert prefix == reference
assert rng.checkpoint() == restored.checkpoint()
```

输出：

```text
[48271, 182605794, 1291394886]
True
8
```

这个例子验证了递推实现与恢复行为，没有据此证明生成器适用于任意模拟，也没有把它当成安全用途的随机源。

注意 `uniform()` 的范围是严格的 $(0,1)$，因为状态永远非零。它与某些提供 $[0,1)$ 的接口并不完全相同。把它接进§3.4的转换函数时，端点约定应继续保留。

## 5. 多个种子，并不自动意味着多个独立流

一个满周期发生器的不同种子，可能只是同一个循环上的不同起点。如果两个起点距离很近，两个任务的输出段就可能重叠。

§3.2 的跳步运算可用来安排互不重叠的状态段。例如总周期为 $P$，每个任务最多使用 $L$ 个状态，分配第 $j$ 个任务从第 $jL$ 步开始，且总使用范围不超过周期。这样能控制状态段的重叠。

不过，不重叠本身并不等于统计独立。不同段仍然来自同一个确定递推；一个方案的并行流性质要根据它的具体构造分析。

还要注意“最多用 $L$ 个数”到底指哪一层。拒绝采样可能为了生成一个目标值消耗多个底层输出，缓存算法也可能一次产生多个目标值。若按最终样本数分段，却没有限制底层消耗量，预留的状态段可能被用穿。

这说明流分配与分布转换需要共同设计，不能各自写完后才假设它们自然兼容。

## 6. 对照实验要更换什么

原书在本节末尾建议，在相信模拟结论以前，使用不同的随机数来源检查稳定性。只把同一方法的种子从1改成2，主要检查的是不同起点的表现，未必能暴露这一方法共有的结构缺陷。

一份有用的验证记录可以包含两类证据。

第一类是确定性的实现检查：合法状态是否始终保持，边界参数是否被拒绝，恢复后输出是否完全相同，小规模洗牌与抽样是否对所有选择路径公平。这些检查不需要依赖“多跑几次看起来没问题”。

第二类是应用结果检查：在已有解析答案的小问题上对照结果，改变样本规模，检查多次重复的波动，再比较不同生成方法。这里要报告观察到的差异及不确定性，不能把单次接近理论值视为整个系统正确。

例如估计 $\mathbb E[U^2]$ 与估计 $\mathbb E[U_nU_{n+1}]$，检验的是不同层次。独立一致模型下，前者为 $1/3$，后者为 $1/4$。一个一维覆盖良好但相邻值高度依赖的序列，可能在前者表现正常、在后者产生系统偏差。

如果实际输出位于有限网格上，还要先计算该网格对应的理论目标，不能把离散化误差全算成发生器的统计缺陷。
