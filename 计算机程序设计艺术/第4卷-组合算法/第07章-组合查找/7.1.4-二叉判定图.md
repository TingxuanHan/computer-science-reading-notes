# 【计算机程序设计艺术 TAOCP】卷4·7.1.4 二叉判定图：共享子函数、计算解的个数与变量顺序

一张$n$变量真值表有$2^n$行。如果许多行在固定一部分输入之后，剩下的行为完全一样，我们有必要把它们各自存一遍吗？

二叉判定图的出发点就是共享这些相同的子函数。它把“依次问几个0／1问题”组织成有向无环图。只要图足够小，就可以在图上做求值、计数、优化和布尔合成；而图是否足够小，往往取决于先问哪个变量。

## 1. 从一次选择开始：Shannon展开

固定一个变量$x$，令

$$
f_0=f\big|_{x=0},\qquad f_1=f\big|_{x=1}.
$$

则任意布尔函数都可以写成

$$
f=(\neg x\land f_0)\lor(x\land f_1).
$$

一个判定节点正好保存这件事：节点测试变量$x$，0边指向$f_0$，1边指向$f_1$。沿输入指定的边向下走，最终到达终端0或1，就是函数输出。

如果不停展开，会得到完整决策树：第一层测试第一个变量，第二层测试第二个变量，直到所有变量确定。它仍然可能有指数规模。BDD节省空间，需要再做两件事。

第一，若两条边都指向同一个子函数，测试当前变量没有意义，可以删除该节点。第二，若两个节点测试同一变量，而且0、1后继分别相同，就把它们合并。

合并后，不同路径可以汇合到同一节点，因此它是一张图，不再是一棵树。节点表示的是一个剩余问题，不是“这一条路径过去发生了什么”的完整历史。

## 2. 本节说的BDD，包含“有序”和“约简”两个条件

先固定变量顺序，例如

$$
x_1\prec x_2\prec\cdots\prec x_n.
$$

任何从根到终端的路径都按这个顺序测试变量，可以跳过某些变量，但不能倒回去。然后应用上面的删除与合并规则。这就是常说的ROBDD，约简有序二叉判定图。原书在本节通常把它简称为BDD。

固定顺序之后，同一个函数的约简图在结构上唯一。证明可以从最早真正影响输出的变量开始：它的两个余因子是函数本身确定的；递归地，它们的约简图也已经唯一；最后把相同三元组$(变量,0后继,1后继)$合并，父节点就确定了。

这个唯一性有前提：变量顺序必须一致。若改变顺序，同一个函数可能得到完全不同的图。即使顺序相同，两个独立管理器给节点分配的数字编号也可能不同；直接比较整数ID只在共享同一唯一表的管理器内有意义。

## 3. 两张表，各自解决一种重复

构造一个节点时，使用

$$
\operatorname{mk}(i,l,h).
$$

若$l=h$，直接返回$l$；否则查询是否已有相同三元组$(i,l,h)$。存在就返回已有节点，不存在才分配。这张字典称为**唯一表**。

另一张表保存“某个运算已经对某对函数算过，结果是什么”，例如

$$
(\land,u,v)\mapsto r.
$$

它是计算结果缓存。唯一表避免重复结构，计算缓存避免重复工作，两者不能互相替代。

唯一表发生错误，会破坏约简图的结构与节点同一性；计算缓存忘掉一个有效结果，通常只是导致重新计算。但缓存若返回过期节点，也会影响正确性，因此真正的库需要把缓存、节点生命周期和垃圾回收一起设计。

文末教学实现一直保留已分配节点，便于说明核心算法。统计某个函数的规模时，要从它的根遍历可达节点，而不能使用整个管理器数组的长度。后者还包含其他函数和过往中间结果。

## 4. 求值很容易，计数却不能只数路径

给定输入，从根沿相应边走到终端即可。由于变量顺序严格递增，一次求值最多测试$n$个变量。

求满足$f=1$的输入个数时，容易犯的错误是数“到达终端1的路径条数”。图会跳过不影响当前子函数的变量，这些变量可以自由取0或1，每跳过一个就多出一倍赋值。

例如，四变量函数$f=x_1\land x_3$的约简图只测试$x_1,x_3$。通向1的测试路径只有一条，但$x_2,x_4$均可自由选择，所以有4个满足赋值。

用从0开始的层号$\ell(u)$表示节点测试哪个变量，并把两个终端的层号设为$n$。令$C(u)$表示从该节点所处层开始的满足赋值数，终端初值为

$$
C(0)=0,\qquad C(1)=1.
$$

对于层号$i$、后继$l,h$的内部节点：

$$
C(u)=2^{\ell(l)-i-1}C(l)+2^{\ell(h)-i-1}C(h).
$$

两个指数分别数清当前节点与孩子之间被跳过的变量。若根也跳过最前面一些变量，还要乘上

$$
\#f=2^{\ell(\mathrm{root})}C(\mathrm{root}).
$$

这个公式连常量函数也能处理：根为1时，结果是$2^n$；根为0时，结果是0。实现中使用Python整数保存精确计数，不把大整数加法与移位的成本误认为永远固定。

## 5. 计数之后，还能抽样、求概率和优化

如果已得到每个子问题的计数，就可以按两个分支代表的赋值数比例选择下一条边，再独立填入被跳过变量的0／1值，得到均匀的满足赋值。每个完整输入的概率沿路径相乘，恰好化为$1/\#f$。只按图中的两条边各掷一次公平硬币，通常并不均匀。

如果输入变量独立，且$P(x_i=1)=p_i$，可以用另一种自底向上的递推：

$$
P(u)=(1-p_i)P(l)+p_iP(h),
$$

终端概率分别为0和1。被跳过的变量贡献$P(x=0)+P(x=1)=1$，所以这里不再出现计数公式中的$2^k$。独立性是前提；有关联的输入不能直接套用这条局部乘权递推。

再把每个变量选为1的得分设为$w_i$，就可以在满足$f=1$的条件下最大化$\sum_iw_ix_i$。分支之间取最大值，1边额外加当前变量得分；无法满足的终端用负无穷表示。被跳过的自由变量也要处理：正权变量选1，负权变量选0，各贡献$\max(0,w_i)$。

计数、概率、最优化看起来是三类任务，但都在利用同一张图上的共享子问题。原文还将它们推广到生成函数及代数化的求值框架。换掉聚合与组合运算时，终端值、跳层贡献以及相关代数性质也要一起调整。

## 6. Apply：不展开整张真值表，也能合成函数

已经有$f$与$g$的BDD，想构造$f\land g$或$f\oplus g$，可以同时查看两个根。在它们当前测试变量中，选顺序更早的那个$x_i$。

若某张图当前没有测试$x_i$，则该函数此时与$x_i$无关，把它的两个余因子都视为原节点即可。随后递归计算

$$
r_0=f_0\mathbin{\circ}g_0,\qquad r_1=f_1\mathbin{\circ}g_1,
$$

再返回$\operatorname{mk}(i,r_0,r_1)$。当两个参数都为终端时，直接根据二元运算真值表给出结果。

没有缓存的递归可能反复遇到相同节点对。缓存$(\circ,u,v)$之后，每对只需处理一次；固定运算下，不同节点对至多有$|f|\,|g|$个。因此，在节点操作和字典访问按常数时间计的模型下，有一个乘积规模的上界。

这个上界是相对于**输入图的大小**而言。若输入图本身已经很大，或者中间结果比最后结果大很多，仍然会耗尽内存。把多个条件依次相与时，先合成哪一对也会影响中间规模。

原书的算法S着重讨论按层合成、模板、局部性和紧凑存储；后面的BDD base则适合长期保留很多相互共享的函数。本文用递归和两个Python字典说明后者的核心机制，没有复现书中的全部内存布局。

## 7. 固定变量、消去变量与代入函数

限制操作是把某些变量固定为常量。例如对选择函数

$$
F(s,a,b)=(\neg s\land a)\lor(s\land b)
$$

固定$s=0$得到$a$，固定$s=1$得到$b$。递归到被固定变量时，选择指定后继；其他节点递归处理两个孩子，再经过`mk`约简。

存在量化与全称量化分别满足

$$
\exists x\,f=f_0\lor f_1,\qquad
\forall x\,f=f_0\land f_1.
$$

对选择函数消去$s$，便得到$\exists sF=a\lor b$，$\forall sF=a\land b$。这让BDD能够表示关系组合、可达状态和带量词约束。

文末管理器固定了变量全集。因此，对量化后的图调用`count`时，返回的仍是**整个原变量全集**上的赋值数；被消去变量成为自由变量，会贡献一个2的因子。若想数剩余变量的赋值，需要明确改变统计域，或按已消去的独立维度修正，不能把两种计数混在一起。

把一个变量替换成另一个布尔函数则更复杂。替换函数可能依赖原来更早的变量，直接把它当成节点标签或拼接孩子会破坏顺序。一般应通过选择运算

$$
\operatorname{ITE}(g,r_1,r_0)=(g\land r_1)\lor(\neg g\land r_0)
$$

重新合成。原文将这类操作继续推广为函数复合。

## 8. 变量顺序为什么能造成指数差异

考虑两个$m$位向量是否完全相等：

$$
E(X,Y)=\bigwedge_{i=0}^{m-1}[x_i=y_i].
$$

若顺序是$x_0,y_0,x_1,y_1,\ldots$，测试$x_i$后只需记住一个比特，马上用$y_i$核对；一旦不等就到终端0。每对变量贡献三个内部节点，总计$3m$。

若先读完所有$x_i$，再读所有$y_i$，图必须记住前半段读到的整个$X$，因为后面需要判断$Y$等于哪一个值。前半段有$2^m-1$个内部节点；后半段对应不同长度的相等性余因子，共$2^{m+1}-2$个内部节点，总计

$$
3\cdot2^m-3.
$$

下面是本文程序实际得到的数量，**仅统计从根可达的非终端节点**，不含两个常量终端；原书某些规模记号会把终端也计入，比较时要先统一口径。

| 相等位对数m | 交替读取X、Y | 先全部X，再全部Y |
|---:|---:|---:|
| 2 | 6 | 9 |
| 4 | 12 | 45 |
| 6 | 18 | 189 |
| 8 | 24 | 765 |

两个顺序表示的函数完全相同，满足赋值数也同为$2^m$。差别在于扫描到某个位置时，还必须记住多少不同的剩余任务。

这与7.1.2的列类型分解呼应：先读变量的不同取值，诱导出多少种不同的后缀函数，就决定了图在这一带需要保留多少状态。

## 9. 重排能够改进图，却不是万能压缩

原书用各层节点数形成profile，分析一张图的规模和变量顺序。相邻变量交换只会改变局部层的连接结构，因此可以作为重排的基本操作。

常见的sifting做法是把一个变量向上、向下移动，观察图规模，最后停在本次尝试中最好的位置，再处理其他变量。它利用了结构局部变化，却仍是启发式：停在一个无法通过当前局部移动改进的顺序，不等于达到全局最优。

另一个边界更根本。有些函数在任何顺序下都需要很大的BDD。原文讨论隐含加权位、排列矩阵和乘法相关函数，说明某些简单的数学定义会诱导大量难以共享的余因子。

因此，输入描述短、公式树短、布尔链短、BDD小，是不同性质。选择BDD前，可以在问题中寻找：局部约束、重复子函数、良好的变量分组，以及扫描前缀后只需记住少量信息的结构。图增长迅速时，调整顺序值得尝试，但也需要考虑其他表示或求解方法。

## 10. ZDD：把图解释为一个集合族

BDD中的跳过变量，表示该变量取0或1都不影响当前子函数。零压缩判定图ZDD采用另一种约定：跳过的元素不属于当前集合，也就是相应变量固定为0。

因此，两者的约简规则不同：

| 结构 | 可删除节点的条件 | 返回什么 |
|---|---|---|
| BDD | 0后继与1后继相同 | 共同后继 |
| ZDD | 1后继是空族终端0 | 0后继 |

ZDD中即使两个后继相同，也不能直接删除节点：走1边意味着把当前元素加入集合，走0边则不加入，两类结果仍然不同。

从集合族角度看，终端0表示空族$\varnothing$，终端1表示仅包含空集的族$\{\varnothing\}$。它们一个有0个成员，一个有1个成员，绝不能混淆。

例如

$$
\mathcal F=\{\varnothing,\{1\},\{1,3\}\}.
$$

第一层按是否包含元素1分成两族：不包含的一侧只有空集；包含的一侧剥去1后，剩下$\{\varnothing,\{3\}\}$。递归继续即可。将全集从$\{1,2,3\}$扩充到更多元素，不会改变这三个集合，ZDD通常也不必为始终缺席的新元素添加链条。

ZDD的计数直接满足

$$
C(u)=C(l)+C(h),
$$

因为两边按是否包含当前元素划分成互不相交的集合族，被跳过元素没有自由选择，不需要BDD中的跳层乘数。

## 11. 集合族压缩如何连接组合问题

精确覆盖可以把每个候选行当作一个元素，目标集合表示选中的行。对矩阵的每一列，要求所选行中恰有一个1覆盖它：

$$
\bigwedge_j\left[\sum_{i:\,A_{ij}=1}x_i=1\right].
$$

这类解通常从许多候选行中只挑一小部分，ZDD的零压缩约定很自然。原文还讨论棋盘覆盖、路径、字典与基本蕴涵项等集合族。其优势在于许多不同解可能共享相同的剩余子族。

但“最终图很小”并不保证“建图过程很便宜”。逐个列出全部解再压缩，可能在生成输入时就付出指数代价；按约束逐步合成，也可能产生庞大的中间图。文末ZDD构造器接收显式集合族，只用于验证结构与约简语义，不声称解决了从隐式约束高效建图的问题。

BDD与ZDD还可以配合：前者表示一个布尔函数，后者表示满足某种性质的项或集合。若底层共享节点存储，缓存和运算入口仍必须区分两种语义；外观相同的三元组，在不同解释下未必表示同一个对象。

## 12. 一个能跑通核心概念的Python实现

下面完整代码只依赖标准库。`build`从全部赋值建图，适合作为小规模检查基准，运行时间本来就是指数级；实际组合约束更适合从变量图开始用`apply`逐步合成。教学实现未包含补边、动态重排、缓存容量控制或垃圾回收。

操作码按第$2a+b$位定义二元函数，与上一节检查程序一致：AND为8、OR为14、XOR为6。所有节点ID只能在所属管理器内部使用。

```python
"""Small educational ROBDD/ZDD managers; no complement edges or GC."""
from functools import cache
from itertools import product


class BDD:
    def __init__(self, order):
        self.order = tuple(order)
        assert len(set(self.order)) == len(self.order)
        self.n = len(self.order)
        self.rank = {v: i for i, v in enumerate(self.order)}
        self.nodes = [None, None]  # terminal false / true
        self.unique = {}
        self.memo = {}

    def level(self, u):
        return self.n if u < 2 else self.nodes[u][0]

    def mk(self, level, lo, hi):
        assert 0 <= level < self.n
        assert level < self.level(lo) and level < self.level(hi)
        if lo == hi:
            return lo
        key = (level, lo, hi)
        if key not in self.unique:
            self.unique[key] = len(self.nodes)
            self.nodes.append(key)
        return self.unique[key]

    def var(self, name):
        return self.mk(self.rank[name], 0, 1)

    def build(self, f):
        # Enumerates all assignments: suitable only as a small-input oracle.
        def visit(i, assignment):
            if i == self.n:
                return int(bool(f(assignment)))
            v = self.order[i]
            assignment[v] = 0
            lo = visit(i + 1, assignment)
            assignment[v] = 1
            hi = visit(i + 1, assignment)
            del assignment[v]
            return self.mk(i, lo, hi)
        return visit(0, {})

    def evaluate(self, u, assignment):
        while u >= 2:
            i, lo, hi = self.nodes[u]
            u = hi if assignment[self.order[i]] else lo
        return u

    def apply(self, op, u, v):
        # op bit 2*a+b specifies the result on Boolean arguments a,b.
        assert 0 <= op < 16
        key = (op, u, v)
        if key in self.memo:
            return self.memo[key]
        if u < 2 and v < 2:
            return (op >> (2 * u + v)) & 1
        i = min(self.level(u), self.level(v))
        ul, uh = self.nodes[u][1:] if self.level(u) == i else (u, u)
        vl, vh = self.nodes[v][1:] if self.level(v) == i else (v, v)
        result = self.mk(i, self.apply(op, ul, vl), self.apply(op, uh, vh))
        self.memo[key] = result
        return result

    def restrict(self, root, fixed):
        assert all(v in self.rank and b in (0, 1) for v, b in fixed.items())
        @cache
        def visit(u):
            if u < 2:
                return u
            i, lo, hi = self.nodes[u]
            v = self.order[i]
            if v in fixed:
                return visit(hi if fixed[v] else lo)
            return self.mk(i, visit(lo), visit(hi))
        return visit(root)

    def quantify(self, root, variable, universal=False):
        lo = self.restrict(root, {variable: 0})
        hi = self.restrict(root, {variable: 1})
        return self.apply(0b1000 if universal else 0b1110, lo, hi)

    def count(self, root):
        @cache
        def below(u):
            if u < 2:
                return u
            i, lo, hi = self.nodes[u]
            return ((1 << (self.level(lo) - i - 1)) * below(lo)
                    + (1 << (self.level(hi) - i - 1)) * below(hi))
        return (1 << self.level(root)) * below(root)

    def probability(self, root, probabilities):
        assert all(0 <= probabilities[v] <= 1 for v in self.order)
        @cache
        def visit(u):
            if u < 2:
                return u
            i, lo, hi = self.nodes[u]
            p = probabilities[self.order[i]]
            return (1 - p) * visit(lo) + p * visit(hi)
        return visit(root)

    def nonterminals(self, root):
        seen = set()
        def visit(u):
            if u < 2 or u in seen:
                return
            seen.add(u)
            _, lo, hi = self.nodes[u]
            visit(lo)
            visit(hi)
        visit(root)
        return len(seen)


class ZDD:
    def __init__(self):
        self.nodes = [None, None]  # empty family / family containing empty set
        self.unique = {}

    def mk(self, element, lo, hi):
        if hi == 0:
            return lo
        key = (element, lo, hi)
        if key not in self.unique:
            self.unique[key] = len(self.nodes)
            self.nodes.append(key)
        return self.unique[key]

    def build(self, family):
        family = frozenset(frozenset(s) for s in family)
        @cache
        def visit(f):
            if not f:
                return 0
            elements = set().union(*f)
            if not elements:
                return 1
            v = min(elements)
            lo = visit(frozenset(s for s in f if v not in s))
            hi = visit(frozenset(s - {v} for s in f if v in s))
            return self.mk(v, lo, hi)
        return visit(family)

    def count(self, root):
        @cache
        def visit(u):
            if u < 2:
                return u
            _, lo, hi = self.nodes[u]
            return visit(lo) + visit(hi)
        return visit(root)


if __name__ == '__main__':
    b = BDD(('s', 'a', 'b'))
    s, a, v = (b.var(x) for x in b.order)
    mux = b.apply(6, a, b.apply(8, s, b.apply(6, a, v)))
    direct = b.build(lambda x: x['b'] if x['s'] else x['a'])
    assert mux == direct and b.count(mux) == 4
    assert b.restrict(mux, {'s': 0}) == a
    assert b.quantify(mux, 's') == b.apply(14, a, v)
    assert b.probability(mux, dict.fromkeys(b.order, 0.5)) == 0.5
    for n in (2, 4, 6):
        xs, ys = [f'x{i}' for i in range(n)], [f'y{i}' for i in range(n)]
        sizes = []
        for order in (sum(zip(xs, ys), ()), tuple(xs + ys)):
            manager = BDD(order)
            root = manager.build(lambda a: all(a[x] == a[y] for x, y in zip(xs, ys)))
            assert manager.count(root) == 1 << n
            sizes.append(manager.nonterminals(root))
        print('equality pairs / interleaved / grouped:', n, *sizes)
    z = ZDD()
    root = z.build([set(), {1}, {1, 3}])
    assert z.count(root) == 3
    print('BDD construction, Apply, restriction, quantification, counting: passed')
```
