> 阅读位置：第4卷第2册双语版，§7.2.1.2，中文书页170—204（PDF第175—209页，源节含习题）。本文围绕字典序后继、多重集合、相邻交换、排名和受限排列展开；源节中的群论构造与机器级优化仅作阅读导航。

## 1. 同样是六个排列，访问顺序可以不同

三个不同元素的排列有$`3!=6`$个。字典序列出`012, 021, 102, 120, 201, 210`；相邻交换的一种顺序则是`012, 021, 201, 210, 120, 102`。

前者便于比较、编号、恢复进度；后者每次只交换相邻位置，便于维护与相邻关系有关的目标值。判断一个生成器是否正确，要看对象集合是否完整且无重复；评价它是否合用，还要看输出顺序和消费者的更新成本。

有重复元素时，要先确定对象身份。`[1,1,2]`的不同值排列只有`112,121,211`三种。如果把两个1当成不同位置的物件，则是六个排列。这两种计数都可能正确，但不能用一个接口含混地表达。

## 2. 字典序后继：尽量晚改，尽量少增，后缀尽量小

给定`[1,3,4,2,2]`，从右向左找最后一个满足$`a_j<a_{j+1}`$的位置，得到j=1，值为3。它右侧的`[4,2,2]`已经非递增，是这个前缀下最大的后缀。保持前缀`[1,3]`不动，不可能再找到更大的排列。

因此必须增大$`a_j`$。为了让新排列尽可能小，在右侧找严格大于3的最小值4，交换后得到`[1,4,3,2,2]`。再把后缀反转成非递减序列，得到`[1,4,2,2,3]`。

这三个动作分别保证：

1. 尽量保留左边的长前缀，所以不会跳过只需修改更晚位置的候选。
2. 枢轴只增到可用的最小值，不跨过中间排列。
3. 后缀取最小排列，落到新前缀的第一个对象。

当整段已经非递增时，没有后继。输入先排序，再反复使用这个规则，就得到完整字典序。严格比较号非常重要：找枢轴用`<`，找交换对象也必须严格大于枢轴。否则重复元素会制造重复访问或错误停止。

后缀交换后仍为非递增，因此反转即可，不需要重新排序。单次后继最坏O(n)，辅助状态O(n)用来存排列；若只考虑后继的原地修改，额外空间可以做到O(1)。代码为可读性使用切片，并交付不可变元组快照，这两处都有复制开销。

## 3. 多重集合为什么不该先生成n!再去重

若某些值出现次数为$`m_1,\ldots,m_t`$，不同值排列数是

$$
\frac{n!}{m_1!m_2!\cdots m_t!}.
$$

这是因为同值元素的内部互换不会改变结果。字典序后继直接在值序列上工作，自然越过这些不可区分的交换。先给重复值加标签生成n!项，再放入集合去重，会把本来不必发生的工作全部做一遍，也会失去流式输出的优势。

不过，下面用于排名的函数只处理`range(n)`上的不同元素排列。多重集合排名要在每个候选前缀下计算剩余重数对应的多项式系数；不能直接把不同元素的阶乘公式搬过去。

## 4. 阶乘数制：一个排列为什么能变成整数

从左向右看一个排列，在尚未使用的有序元素中，记录当前元素的下标$`c_i`$。它等于“右边比当前元素小的元素有多少个”，满足

$$
0\le c_i\le n-1-i.
$$

这是Lehmer编码。字典序排名从0开始：

$$
R=\sum_{i=0}^{n-1}c_i(n-1-i)!.
$$

为什么乘阶乘？某一位置若选了一个更小的可用值，剩下n−1−i个元素可以任意排列，形成完整的一块$`(n-1-i)!`$个对象。把此前所有整块的大小相加，就得到当前排列的位置。

例如`[2,0,3,1]`的编码为`[2,0,1,0]`，排名是$`2\cdot3!+0\cdot2!+1\cdot1!=13`$。反排名先用13除以3!，选择剩余列表中下标2的元素，再处理余数。每一步都在一个越来越短的有序列表中选元素。

本文使用列表查找与删除，所以排名和反排名都是O(n²)量级。树状数组能更快地完成秩查询与选择，但那是数据结构层面的优化，不改变这里的块划分证明。

## 5. 相邻交换：最大的可移动元素先走

给每个元素一个方向，初始全部向左。若一个元素按自身方向前进一格不会越界，并且相邻元素比它小，就称它可以移动。每步选最大的可移动元素，交换它和该邻居，然后把所有比它大的元素方向反转。

为什么会遍历所有排列？可以按最大元素n−1的位置观察：它从一端逐格扫到另一端，在固定的n−1个较小元素顺序中经过所有n个位置。到达边界后，较小元素进行下一步变化，最大元素改变方向再扫回来。递归地看，较小元素也按同样规则遍历各自排列，因此每个较小排列都扩展为n个不同插入位置。

这是Steinhaus–Johnson–Trotter方式的直观实现。我们的程序每次扫描全部元素寻找最大可移动项，所以虽然每步只发生一次相邻交换，控制开销仍为O(n)。“只交换一次”和“常数时间找出该交换谁”是两个不同结论。

相邻交换还提供一个便宜的检查：每一步的逆序数奇偶性必然翻转。它适合发现某些错误，却不能证明所有排列都出现过。只在两个排列间来回交换，也满足奇偶翻转，但显然没有完成枚举。

## 6. 增量目标、群构造与受限排列

若目标是路径长度$`\sum_i d(a_i,a_{i+1})`$，交换相邻两项只影响附近少数边；无需重算整条路径。但对于有向距离，交换内部那条边的方向也会改变，必须把它算进去。

原节进一步用交换、循环和群的生成元统一若干排列顺序。此时需要分清：一组操作能到达全部群元素，和按某种固定操作序列恰好访问每个元素一次，不是同一命题。后者要求更强的路径结构。机器级优化又依赖排列存储布局和访问例程，不能把某一平台上的每排列指令数当成所有语言的成本。

若还有先后约束，例如a必须在c之前、b必须在c之前，目标对象是偏序的线性扩张。先生成全部n!个排列再筛选当然正确，却常常浪费巨大。更自然的做法是每步只选择当前入度为零的未用元素，选择后更新约束，回退时恢复。这样枚举过程本身就遵守约束，也自然引向后面的回溯程序设计。

## 7. 可运行实现

核验覆盖n=0至7的不同元素排列，对照标准库的完整对象集合；对重复值单独核验；每个排名均反排名还原；相邻交换逐项检查变化的确只发生在两个相邻位置。

```python
from itertools import permutations
from math import factorial


def lex_permutations(items):
    a = sorted(items)
    while True:
        yield tuple(a)
        j = len(a) - 2
        while j >= 0 and a[j] >= a[j + 1]:
            j -= 1
        if j < 0:
            return
        k = len(a) - 1
        while a[k] <= a[j]:
            k -= 1
        a[j], a[k] = a[k], a[j]
        a[j + 1:] = reversed(a[j + 1:])


def rank_permutation(a):
    n = len(a)
    if sorted(a) != list(range(n)):
        raise ValueError('expected a permutation of range(n)')
    pool, r = list(range(n)), 0
    for i, value in enumerate(a):
        j = pool.index(value)
        r += j * factorial(n - i - 1)
        pool.pop(j)
    return r


def unrank_permutation(n, r):
    if n < 0 or not 0 <= r < factorial(n):
        raise ValueError('invalid n or rank')
    pool, a = list(range(n)), []
    for width in range(n, 0, -1):
        j, r = divmod(r, factorial(width - 1))
        a.append(pool.pop(j))
    return tuple(a)


def adjacent_permutations(n):
    if n < 0:
        raise ValueError('n must be nonnegative')
    a, direction = list(range(n)), [-1] * n
    while True:
        yield tuple(a)
        mobile = [(v, i) for i, v in enumerate(a)
                  if 0 <= i + direction[v] < n and v > a[i + direction[v]]]
        if not mobile:
            return
        value, i = max(mobile)
        j = i + direction[value]
        a[i], a[j] = a[j], a[i]
        for v in range(value + 1, n):
            direction[v] *= -1


def verify():
    tested = 0
    for n in range(8):
        want = list(permutations(range(n)))
        got = list(lex_permutations(range(n)))
        assert got == want
        for r, a in enumerate(got):
            assert rank_permutation(a) == r
            assert unrank_permutation(n, r) == a
        adjacent = list(adjacent_permutations(n))
        assert len(adjacent) == len(set(adjacent)) == factorial(n)
        assert set(adjacent) == set(want)
        for a, b in zip(adjacent, adjacent[1:]):
            diff = [i for i in range(n) if a[i] != b[i]]
            assert len(diff) == 2 and diff[1] == diff[0] + 1
            i, j = diff
            assert a[i] == b[j] and a[j] == b[i]
        tested += len(want)
    for items in [[], [2], [1, 1, 2], [0, 0, 1, 1, 2], [3, 3, 3]]:
        assert list(lex_permutations(items)) == sorted(set(permutations(items)))
    return {'distinct_permutations_checked': tested, 'multiset_cases': 5}


if __name__ == '__main__':
    print(verify())
```

## 8. 读完后应该能区分的三件事

字典序后继回答“下一个更大的对象是什么”；排名回答“它位于哪一个整块之后”；相邻交换回答“怎样让消费者只更新局部状态”。三者可以分别设计，也有不同的复杂度。实际任务先确定需要哪一种能力，再选生成算法，往往比只追求最短代码更有效。
