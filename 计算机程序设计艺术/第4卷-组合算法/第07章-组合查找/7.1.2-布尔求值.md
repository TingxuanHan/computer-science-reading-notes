## 1. 先规定什么算一步

设输入为$x_1,\ldots,x_n$。一个布尔链逐步构造中间结果：

$$
t_i=\phi_i(u_i,v_i),
$$

其中$u_i,v_i$只能引用输入或已经计算出的值，$\phi_i$可以是16种二元布尔函数之一。输出引用某个已有值；已算出的结果可以多次读取。

这个模型有三个关键约定：每个门至多两个输入；所有二元门按相同代价计数；中间结果的复制、连线没有另收费用。若门本身可以计算“第一个输入取反后再与第二个输入相与”，就不必额外放置一个非门。

因此，“三步”首先是这个数学模型中的三步。换成只允许与非门的电路、具有特殊指令的处理器，或者存在昂贵访存的程序，需要重新计算代价。即使逻辑正确，把书中的最短链长度直接当成某台机器的运行周期，也会失去依据。

本篇继续使用上一节的选择函数：

$$
F(s,a,b)=(\neg s\land a)\lor(s\land b),
$$

即$s=0$取$a$，$s=1$取$b$。它有两种三门实现：

$$
\begin{aligned}
u&=\neg s\land a,&v&=s\land b,&F&=u\lor v;\\
p&=a\oplus b,&q&=s\land p,&F&=a\oplus q.
\end{aligned}
$$

第二种写法可以直接验证：当$s=0$时$q=0$；当$s=1$时，$a\oplus(a\oplus b)=b$。后续位运算中的掩码选择，正是这个恒等式的逐位版本。

## 2. 长度、深度和内存：三个指标要分别看

**公式长度$L(f)$**计算公式树中的二元运算数。一个子式出现两次，就在树中占两份。

**链复杂度$C(f)$**计算允许复用中间结果时，最短布尔链需要多少个门。公式树本身也是一种链，因此

$$
C(f)\le L(f).
$$

**深度$D(f)$**关心输入到输出最长的依赖路径。在忽略通信代价、同层门能够并行的模型中，它描述延迟。若每个门只依赖前面的门，一条有$m$个门的链的深度至多为$m$；但门最少的实现不一定深度最小。

例如，上面的与或实现有两层：两个与类门先同时计算，最后求或。异或实现虽然也是三个门，却形成三层依赖。这不说明异或实现总是更慢；具体指令代价可能不同。它说明“操作次数相同”还没有描述计算安排。

再加上有限寄存器，问题会变一次。覆盖一个输入之后，后面若还需要它，就必须提前保留副本或重新计算。书中的原地求值讨论正是在研究这种限制。若记相应最优代价为$C_m(f)$，其中$m$表示允许的工作空间约束，那么受限实现的最优代价不会优于允许无限复用的模型。优化时必须同时说明允许保留什么。

## 3. 一个中间结果为什么值得保留

考虑四个输入中“恰好有两个1”的函数：

$$
E(a,b,c,d)=[a+b+c+d=2].
$$

这里方括号表示条件成立时取1，内部加号是普通整数加法。下面是一条六门链：

$$
\begin{aligned}
t_1&=a\oplus c,&t_2&=a\oplus b,&t_3&=c\oplus d,\\
t_4&=t_1\lor t_2,&t_5&=t_2\oplus t_3,&E&=t_4\land\neg t_5.
\end{aligned}
$$

为什么成立？$t_5=a\oplus b\oplus c\oplus d$检查总数的奇偶性，因此$\neg t_5$只保留0、2、4个1的输入。另一方面，$t_4=0$意味着$a=c$且$a=b$。在偶数个1的前提下，$d$也必须与它们相同；这就剔除了全0和全1，剩下恰好两个1。

注意$t_2$被用了两次。链里只算一次；若展开成没有共享节点的公式树，这个异或就要重复。差别来自**计算结构**，而不是表达式的字符数。

书中进一步给出了这个函数的最优性讨论。本文的16行真值表检查只能证明上述六门链正确，不能单独证明不存在五门链。验证一个候选解与证明它最优，是两个任务。

## 4. 小函数可以穷举，但要枚举正确的对象

三个变量只有$2^{2^3}=256$个布尔函数，可以把每个函数的真值表压成一个8位整数。若输入组合编号为

$$
k=x_0+2x_1+4x_2,
$$

就让整数的第$k$位保存函数输出。随后对整张真值表做按位与、或、异或，相当于同时检查全部输入。

这个编号与把$x_0$写成最左边、再按字典序排列的纸面表不同。两种表示都有效，但转换时必须明确顺序。文末程序始终用上式，不把显示出来的二进制字符串直接当作书中的输出串。

想证明选择函数不能用两个门计算，可以进行完整的有限搜索：

1. 初始可用信号为三个输入及常量0、1。
2. 枚举第一个门的两个输入及16种运算。
3. 把第一个结果加入可用信号，再枚举第二个门。
4. 同时检查不经过门、只经过一个门的情况。

程序没有找到选择函数，而前面已经给出三门实现，因此在这个门模型下，最短长度确实为3。即使某次枚举得到的第一门函数已经能由另一条链得到，只保留函数值也足够：这里只有一个中间结果，后续可用输入完全相同。

把搜索扩展到很多门时，就不能只记住“最后一个函数是什么”。两条链最后的输出相同，沿途留下的中间结果可能不同，下一步能够复用的材料也就不同。完整状态应描述可用函数集合及必要的成本信息，搜索空间会很快膨胀。

## 5. 公式的动态规划，为什么不能直接替代链搜索

如果根门把两个子公式合起来，可以按总长度分层：长度$m$的公式，其两个子公式的长度之和为$m-1$。枚举所有长度拆分、两侧函数及根运算，就能逐层发现新的函数表示。

书中的算法L沿着这条路线工作，并通过规范化消除互补表示中的重复。若把输出与$f(0,\ldots,0)$异或，便可把函数转为在全0输入上取0的代表。互补函数之间的关系，又可吸收到相邻门的选择中，减少重复搜索。

但公式动态规划的两个子问题通常被看成独立的树。它不会自动看见两个子公式原本可以共同引用一个更早的节点。因此，对公式长度的最优递推，不等于对一般有向无环计算图的最优递推。

一个实用折中是先求局部表示，再寻找共同“脚印”：如果多个目标都可以利用某个已有函数，就把它当作共同输入重新综合。它常能改进结果，却仍然需要区分：这是一个可行上界，还是已证明的最小值。

## 6. 多个输出一起算：全加器的五个门

全加器接收$a,b,c$三个比特，输出和位$s$与进位$r$，满足

$$
a+b+c=s+2r.
$$

先算$t=a\oplus b$，则

$$
s=t\oplus c,\qquad r=(a\land b)\lor(t\land c).
$$

当$a=b=1$时，第一个与项提供进位；当$a,b$恰有一个1时，是否进位由$c$决定；当两者都是0时，不进位。这给出五门实现：一个共享异或、和位的一个异或、两个与、一个或。

若分别写一条计算$s$的两门链和一条计算$r$的四门链，再机械拼接，会重复计算$a\oplus b$。共同求值只需五门。多输出综合的目标应是整张共享计算图的总代价，而不是各个单输出最优值之和。

这种结构还可以纵向连接成加法器，也可以横向用于统计一排比特中有多少个1。三个同权比特变成一个同权和位和一个两倍权进位，最终再整理各权位。这里的“计数”已经开始连接下一节的population count。

并行进位结构会用更多组织工作缩短依赖路径。是否值得，要看我们关心的是门总数、延迟、寄存器还是实际机器上的吞吐量。

## 7. 不关心的输入，也必须有理由

有些电路只会接收输入空间的一部分。例如，用四位二进制编码十进制数字时，只使用0到9，其余6种编码不会出现。如果规格确实不规定这些编码的输出，那么它们就是don't-care。

给定待检查函数$f$、候选实现$g$以及有效输入的掩码$M$，正确性条件是

$$
(f\oplus g)\land M=0.
$$

这比要求全部输入都一致弱，通常给化简留下更多空间。代价是我们必须明确维护有效域。若系统后来允许新编码进入，原先正确的化简可能失效。

内部节点也可能存在不可达的输入组合，但不能因为“测试中没见过”就把它标为不关心。必须由前面的逻辑、输入约束或状态不变量证明不可达。

多输出系统还要防止局部规格丢掉相互关系。例如，多个行动输出各自表示“这是一个好选择”，不代表能把所有为1的行动同时执行。若规格要求恰选一个，需要把互斥或优先选择规则加入共同验证。

## 8. 函数分解：一组输入究竟需要向外传几比特

把变量分成不相交的两组$Y,Z$，尝试把函数写成

$$
f(Y,Z)=g(Y,h(Z)).
$$

这表示先把$Z$压缩成一个摘要，再让外部计算只读取这个摘要。什么时候一个比特的$h$就足够？

把真值表排成矩阵：每行固定一个$Y$，每列固定一个$Z$。同一列完整描述“给定这一组$Z$之后，函数如何随$Y$变化”。如果两个$Z$被$h$映射到相同值，那么它们对应的两列必须相同，否则$g$无法区分。

因此，完全指定的函数存在一比特分解，当且仅当矩阵最多有两种不同的列。推广到$r$比特摘要，就是不同列数$d$满足

$$
d\le2^r.
$$

最少摘要位数为$\lceil\log_2 d\rceil$；当$d=1$时连摘要位都不需要。

例如，令

$$
f(y,z_0,z_1)=y\oplus(z_0\land z_1).
$$

按$z_0+2z_1$排列四列，前面三列都是$(0,1)^T$，最后一列是$(1,0)^T$。所以只需把“是否同时为1”传出去，即$h=z_0\land z_1$。

这并不保证总门数一定减少。构造$h$和$g$本身也要成本；一个有很多不同列的分组可能毫无收益；枚举整张矩阵也仍是指数级工作。分解定理回答的是可表示性，随后还要评价实现成本。

## 9. 部分函数的分解，要把“相同”换成“兼容”

若列中存在不关心值，两个不同的列也可能被补全成同一列。例如$(0,*)^T$与$(*,1)^T$可以共同补为$(0,1)^T$。

构造一个不兼容图：每个顶点是一列；只要两列在某一行分别明确要求0和1，就连一条边。同一摘要类别中的列不能有冲突，因此一比特分解等价于给这个图进行二着色。

二着色成功后，同色列可以逐行合并：指定值若出现，必须全部相同；没有指定值时任选0或1。于是颜色定义$h$，两种合并列定义$g$。若图存在奇环，就无法用一个比特区分这些要求。

更一般地，$r$比特对应至多$2^r$种颜色。但从二着色推广到任意给定颜色数，求解难度会改变；不能因为两种颜色可用线性时间检查，就认为一般情况也同样容易。

书中还讨论通过冲突和局部约束寻找合适分组的办法。找到候选分组后，仍要回到完整规格核对。抽样没有碰到冲突，只能提供搜索线索，不能替代正确性证明。

## 10. 大多数函数很难，与某个具体函数很难，不是一回事

真值表说明$n$变量函数有$2^{2^n}$个。与之相比，短计算链的描述数量有限。每个门要描述两个先前信号的编号及门类型，所以一条$m$门链可用大约$O(m\log(n+m))$位描述。

这个粗计数已经能说明：所有函数不可能都拥有很短的计算链。书中更精细的计数和构造给出经典的Shannon—Lupanov尺度：最坏情况下的链长度具有约$2^n/n$的规模，精确表述依赖规定的门模型与渐近条件。

上界的思路是把真值表分块，预先计算并共享经常出现的局部模式，再拼接目标。它把“每行各自构造一个最小项”的大量重复压缩掉。

下界的计数说明多数函数无法由短链表示，却不会自动指出哪一个简洁描述的函数特别难。对一个指定函数证明强下界，需要额外结构。固定一个输入、观察哪些门因此变得无用，再把剩余问题归约到较小函数，是其中一类思路。

## 11. 可运行检查：三门最优性、共享结果与分解

下面代码只用Python标准库。`gate`的操作码第$2a+b$位表示输入$(a,b)$的输出，因此AND为`0b1000`，OR为`0b1110`，XOR为`0b0110`。所有按位取反最终都被真值表宽度掩码截断。

```python
"""Original executable examples for TAOCP 7.1.2 (Python 3.10+)."""
from itertools import product


def truth(n, f):
    # Bit k represents x_i = (k >> i) & 1.
    return sum(int(bool(f(*((k >> i) & 1 for i in range(n))))) << k
               for k in range(1 << n))


def gate(op, a, b, mask):
    # op's bit 2*a+b is the binary gate's output.
    terms = (~a & ~b, ~a & b, a & ~b, a & b)
    out = 0
    for k, term in enumerate(terms):
        if (op >> k) & 1:
            out |= term
    return out & mask


def possible_in_two_gates(n, target):
    mask = (1 << (1 << n)) - 1
    base = {0, mask}
    for i in range(n):
        base.add(truth(n, lambda *xs, i=i: xs[i]))
    one = {gate(op, a, b, mask)
           for a in base for b in base for op in range(16)}
    if target in base | one:
        return True
    for first in one:
        available = base | {first}
        for a, b in product(available, repeat=2):
            for op in range(16):
                if gate(op, a, b, mask) == target:
                    return True
    return False


def exact_two(a, b, c, d):
    t1 = a ^ c
    t2 = a ^ b
    t3 = c ^ d
    t4 = t1 | t2
    t5 = t2 ^ t3
    return t4 & (1 ^ t5)


def full_adder(a, b, c):
    t = a ^ b
    s = t ^ c
    u = t & c
    v = a & b
    return s, u | v


def column_types(n, f, z_indices):
    """Return Y coordinates, Z coordinates, column representatives, labels."""
    z_indices = tuple(z_indices)
    assert len(set(z_indices)) == len(z_indices)
    assert all(0 <= i < n for i in z_indices)
    y_indices = tuple(i for i in range(n) if i not in z_indices)
    types, labels = [], []
    for z in range(1 << len(z_indices)):
        column = []
        for y in range(1 << len(y_indices)):
            xs = [0] * n
            for k, i in enumerate(z_indices):
                xs[i] = (z >> k) & 1
            for k, i in enumerate(y_indices):
                xs[i] = (y >> k) & 1
            column.append(int(bool(f(*xs))))
        column = tuple(column)
        if column not in types:
            types.append(column)
        labels.append(types.index(column))
    return y_indices, z_indices, types, labels


def one_bit_partial_decomposition(columns):
    """None denotes a don't-care. Return coloring/completions or None."""
    assert columns and len({len(c) for c in columns}) == 1
    graph = [[] for _ in columns]
    for i in range(len(columns)):
        for j in range(i):
            conflict = any(a is not None and b is not None and a != b
                           for a, b in zip(columns[i], columns[j]))
            if conflict:
                graph[i].append(j)
                graph[j].append(i)
    colors = [None] * len(columns)
    for start in range(len(columns)):
        if colors[start] is not None:
            continue
        colors[start] = 0
        stack = [start]
        while stack:
            i = stack.pop()
            for j in graph[i]:
                if colors[j] is None:
                    colors[j] = colors[i] ^ 1
                    stack.append(j)
                elif colors[j] == colors[i]:
                    return None
    representatives = []
    for color in (0, 1):
        merged = []
        for row in range(len(columns[0])):
            specified = {columns[i][row] for i in range(len(columns))
                         if colors[i] == color and columns[i][row] is not None}
            assert len(specified) <= 1
            merged.append(next(iter(specified), 0))
        representatives.append(tuple(merged))
    return colors, representatives


if __name__ == '__main__':
    mux = truth(3, lambda s, a, b: a if s == 0 else b)
    assert not possible_in_two_gates(3, mux)
    assert mux == truth(3, lambda s, a, b: a ^ (s & (a ^ b)))
    for xs in product((0, 1), repeat=4):
        assert exact_two(*xs) == (sum(xs) == 2)
    for xs in product((0, 1), repeat=3):
        s, c = full_adder(*xs)
        assert s + 2 * c == sum(xs)
    _, _, types, labels = column_types(
        3, lambda y, z0, z1: y ^ (z0 & z1), (1, 2))
    assert len(types) == 2 and labels == [0, 0, 0, 1]
    print('mux: 3 gates are sufficient; 0/1/2 gates are impossible')
    print('exact-two: 16 cases; full adder: 8 cases; decomposition: passed')
```

直接运行会确认：选择函数能用三门实现而不能用至多两门实现；“恰有两个1”的链通过16组输入；全加器通过8组输入；示例分解只产生两种列。

配套的扩展核验还遍历了全部三变量函数与6种非空、非全体的$Z$分组，共1536个分解问题；部分函数则检查了两行四列的全部$3^8=6561$种表，把不兼容图方法与直接枚举颜色作了比较。两者结果一致。它们验证的是这些有限规模与上述实现，并没有证明任意规模的综合搜索都能高效完成。

读完本节，再看一段布尔代码时，可以先画出依赖图，标出重复子结果，最后才讨论门数。下一节把这些计算同时作用到一个机器字的许多位上，问题会变成：位之间何时互不干扰，进位和移位又何时能帮助我们传递信息。
