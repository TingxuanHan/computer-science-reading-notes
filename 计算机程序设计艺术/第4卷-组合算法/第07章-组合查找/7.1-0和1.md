## 1. 一个真值表，为什么能代表所有布尔函数

一个 $n$ 元布尔函数是映射

```math
f:\{0,1\}^n\longrightarrow\{0,1\}.
```

输入有 $2^n$ 种，每一行的输出可以独立选择 0 或 1，因此不同函数的数量为

$$
2^{2^n}.
$$

两个输入时只有 4 行，却有 16 个不同函数。与、或、异或只是其中三个；恒真、恒假、直接返回某个输入，也都属于这个集合。

用三个输入的多数函数做例子：至少两个输入为 1 时输出 1。它可以写成

$$
M(x,y,z)=(x\land y)\lor(x\land z)\lor(y\land z).
$$

| $xyz$ | 000 | 001 | 010 | 011 | 100 | 101 | 110 | 111 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| $M$ | 0 | 0 | 0 | 1 | 0 | 1 | 1 | 1 |

这个表把函数定义得很清楚，但每增加一个变量，表的长度就翻倍。真值表适合作为小规模的正确性参照，不一定适合作为大问题的存储形式。

还要分清三种运算：普通加法、逻辑或、异或。对 0 和 1 而言，$`1+1=2`$、$`1\lor1=1`$、$`1\oplus1=0`$。其中

$$
x\oplus y=(x+y)\bmod2.
$$

因此异或可以当作二元域上的加法；把逻辑或直接替换成普通加法，则会改变函数。

## 2. 从真值表得到表达式，也可以按变量拆开

对每个使函数等于 1 的输入，写一个只在该输入成立的合取项，再把这些项取或，就得到析取范式 DNF。反过来，为每个输出为 0 的输入写一个恰在该输入为假的析取子句，再把子句取与，可以得到合取范式 CNF。

两种形式都保证“能够表示”，却没有保证“表示得短”。直接展开最多会产生 $2^n$ 项。后来处理 SAT 时，CNF 的作用是提供统一的约束接口，不能据此断言任意函数都有很短的 CNF。

另一种重要表示是固定一个变量。令

$$
f_0=f(0,x_2,\ldots,x_n),\qquad
f_1=f(1,x_2,\ldots,x_n).
$$

那么

$$
f=(\neg x_1\land f_0)\lor(x_1\land f_1).
$$

验证只需要分两种情况：当 $x_1=0$，右边剩下 $f_0$；当 $x_1=1$，右边剩下 $f_1$。这就是 Shannon 展开，也是“如果变量为 0 走一边，为 1 走另一边”的依据。

它有两个立即可用的后果：

1. 若 $f_0=f_1$，结果与 $x_1$ 无关，测试这个变量可以删掉。
2. 若不同路径产生相同的剩余函数，它们可以共用后面的计算。

后面二叉判定图的两条约简规则，就来自这里。

## 3. §7.1.2：表达式短，不等于计算步骤少

布尔求值研究怎样用一串基本操作算出结果。每一步可以使用输入，也可以使用之前算出的中间值。原书的布尔链模型把任意二元布尔操作视为一步，并允许中间结果重复使用。

例如二选一函数

$$
F(s,a,b)=(s\land a)\lor(\neg s\land b)
$$

在 $s=1$ 时返回 $a$，否则返回 $b$。利用异或，可以改写成

$$
F(s,a,b)=b\oplus\bigl(s\land(a\oplus b)\bigr).
$$

若 $s=0$，括号内为 0；若 $s=1$，结果是 $b\oplus a\oplus b=a$。这给出三步计算链：先求 $a\oplus b$，再与 $s$，最后与 $b$ 异或。

计算代价必须连同操作集合一起说明。若与非、非与等任意二元函数都算一步，前一个表达式也能用三步实现；若只允许单独的 AND、OR、NOT，则显式求补会增加一步。不能把两个不同操作模型下的步骤数直接比较。

同样，公式是一棵树，中间结果被多处引用时，计算结构更像有向无环图。把共享子计算展开成多份，会夸大实际操作数；反过来，写出了较短的链，只证明一个上界，并没有自动证明全局最优。

程序里还有另一个边界：Python 的 `and`、`or` 会短路，而且不一定返回布尔值；`&`、`|`、`^` 对整数执行逐位运算。把整数集合交集写成 `A and B`，语法可能通过，含义却已经错了。

## 4. §7.1.3：把一个机器字当成许多平行的布尔变量

若集合的元素编号为 $0,1,\ldots,w-1$，可以用整数 $S$ 的第 $i$ 位表示元素 $i$ 是否出现：

$$
S=\sum_{i\in A}2^i.
$$

于是集合交、并、对称差分别对应按位与、或、异或。这里的一条机器指令，可以同时处理多个位置，节省的是逐元素解释和访问的开销。

补集必须指定全集。若只允许低 $w$ 位，则

```math
U=2^w-1,\qquad \overline S=U\mathbin{\&}(\mathop{\sim}S).
```

Python 的整数没有固定字长，`~S` 是负数，不能直接当作“低 $w$ 位的补集”。例如 $w=8$、$`S=5`$，有限全集中的补集是 250，而不是 Python 的 `~5=-6`。

位运算还可以一次清除一个元素。若正整数 $S$ 的最低一个 1 位在位置 $k$，则

```math
S\mathbin{\&}(S-1)
```

把这一位清零，其余 1 位不变。原因是减一把最低的 1 变成 0，并把它右侧的 0 全部变成 1；再与原数相与，右侧仍全为 0。

而

```math
S\mathbin{\&}(-S)=2^k
```

单独留下最低的 1 位。这可以逐个取出集合中的元素，也可以选择回溯搜索的下一个候选。

若要枚举一个掩码 $M$ 的全部子集，可从 $S=M$ 开始反复执行

```math
S\leftarrow(S-1)\mathbin{\&}M.
```

这个过程沿着 $M$ 允许的位向下计数。到 0 必须停止，否则会回到 $M$。若 $M$ 有 $k$ 个 1，就有 $2^k$ 个子掩码；位技巧减少的是每次转移的成本，并没有让输出总数变小。

## 5. 同一个位运算，还能同时核对整个真值表

不妨让整数的一位对应真值表的一行，而不是对应集合中的一个元素。对三个变量，一共 8 行，可以准备三个输入掩码，再逐位计算多数函数。

这时一个整数里的各个位相互独立地执行相同逻辑，得到 8 行结果。它很适合核对两种表达式是否等价：计算出两个结果掩码，检查异或是否为 0 即可。

但不要把“一个 Python 整数”理解成“始终一条固定成本指令”。真值表要占 $2^n$ 个比特，大整数会越变越长；当比特数超过机器字长时，运算会涉及多个字。位并行能大幅改善常数，无法凭空消掉指数空间。

同样，逐次执行 `S &= S - 1` 的循环次数等于 1 位数量；若每个整数占很多机器字，每次大整数运算的成本也需要计算。后面的例子只用小整数验证语义，不作为性能测量。

## 6. §7.1.4：二叉判定图压缩的是什么

按固定变量顺序反复使用 Shannon 展开，会先得到一棵二叉决策树。每个内部结点记录变量，0 分支叫 low，1 分支叫 high，最后到达终端 0 或 1。

接着应用两条规则：

- low 与 high 相同，直接用那个子结点替代当前结点。
- 两个结点的变量、low、high 都相同，把它们合并。

再要求每条路径上的变量顺序一致，就得到约简有序二叉判定图 ROBDD。原书在这一节中将这种有序且约简的对象简称为 BDD。

这里共享的是“剩下的函数”，不只是表面相同的一段文字。例如多数函数在测试前两个变量后，若它们一个为 0、一个为 1，剩下的结果都等于第三个变量；两条路径可以到达同一个结点。

在固定变量顺序、相同终端约定下，ROBDD 对一个布尔函数具有规范性，差别仅在结点编号或内存地址。递归地看，每个函数的两个余因子已经确定；删除无关变量、合并相同余因子后，结构也随之确定。

这解释了它为何适合等价性判断，却不保证图总是小。规范性只是在给定顺序下消除了多种表示的歧义，并没有给出多项式大小的承诺。

## 7. 变量顺序为什么能改变空间需求

考虑两组 $m$ 位变量是否逐位相同：

$$
E(a,b)=\bigwedge_{i=0}^{m-1}(a_i\leftrightarrow b_i).
$$

若顺序是 $a_0,b_0,a_1,b_1,\ldots$，读到一对后就能立即确认这一对相等或失败。通过的路径只需继续处理下一对，因此结点数可以随 $m$ 线性增长。

若先读完全部 $a$，再读全部 $b$，图就需要记住前半段究竟是哪一种 $m$ 位模式。进入 $b$ 区域时有 $2^m$ 个不同的剩余函数，每个要求匹配一个不同模式，于是会出现指数增长。

下面的程序在 $m=3$ 时，得到两种顺序下的非终端结点数 9 和 21。它们表示的函数完全相同，满足赋值也同样都是 8 个。这里的结点数不包含两个终端；原书某些地方的 $B(f)$ 包含终端，比较时要统一口径。

在已有 BDD 上统计满足赋值，还要处理被跳过的变量。一个分支若跳过 $d$ 个变量，这些变量可任意赋值，应乘以 $2^d$。直接把通向 1 的路径条数当作答案，会漏掉这些自由选择。

## 8. 可运行实验：位集合、真值表与 BDD

下面程序仅使用 Python 标准库。BDD 构造器为了清楚，先枚举全部输入，再做约简，因而构造阶段仍有指数成本；它演示表示和计数规则，不是大型符号计算引擎。

```python
from functools import lru_cache


def set_bits(s):
    if s < 0:
        raise ValueError("mask must be nonnegative")
    while s:
        bit = s & -s
        yield bit.bit_length() - 1
        s &= s - 1


def submasks(mask):
    if mask < 0:
        raise ValueError("mask must be nonnegative")
    s = mask
    while True:
        yield s
        if s == 0:
            return
        s = (s - 1) & mask


def build_bdd(order, function):
    order = tuple(order)
    if len(set(order)) != len(order):
        raise ValueError("variables must be distinct")
    nodes, unique, values = {}, {}, {}

    def visit(level):
        if level == len(order):
            return int(bool(function(values)))
        variable = order[level]
        values[variable] = 0
        low = visit(level + 1)
        values[variable] = 1
        high = visit(level + 1)
        del values[variable]
        if low == high:
            return low
        key = (level, low, high)
        if key not in unique:
            uid = len(nodes) + 2
            unique[key] = uid
            nodes[uid] = key
        return unique[key]

    return visit(0), nodes, order


def bdd_value(bdd, values):
    root, nodes, order = bdd
    while root > 1:
        level, low, high = nodes[root]
        root = high if values[order[level]] else low
    return root


def bdd_count(bdd):
    root, nodes, order = bdd
    n = len(order)

    def level(uid):
        return n if uid < 2 else nodes[uid][0]

    @lru_cache(None)
    def count(uid):
        if uid < 2:
            return uid
        k, low, high = nodes[uid]
        return sum(count(v) * (1 << (level(v) - k - 1))
                   for v in (low, high))

    return (1 << level(root)) * count(root)


print(list(set_bits(0b01010100)))
print(sorted(submasks(0b01010100)))
print((~5) & ((1 << 8) - 1))

inputs = [sum(((row >> (2 - k)) & 1) << row
              for row in range(8)) for k in range(3)]
x, y, z = inputs
majority = (x & y) | (x & z) | (y & z)
print([(majority >> row) & 1 for row in range(8)])

equal = lambda a: all(a[i] == a[i + 3] for i in range(3))
for order in [(0, 3, 1, 4, 2, 5), (0, 1, 2, 3, 4, 5)]:
    bdd = build_bdd(order, equal)
    print(len(bdd[1]), bdd_count(bdd))
```

输出：

```text
[2, 4, 6]
[0, 4, 16, 20, 64, 68, 80, 84]
250
[0, 0, 0, 1, 0, 1, 1, 1]
9 8
21 8
```

计数函数给终端规定层号 $n$，因此跳到终端时，尚未测试的变量也会进入自由度因子。若整个函数恒真，根就是终端 1，结果直接为 $2^n$；恒假则为 0。这两个边界可以帮助发现计数公式是否遗漏了根之前的跳层。

代码之外，还可用独立真值表穷举所有三变量布尔函数，比较 BDD 求值与满足赋值总数；对小位宽的全部掩码，把位运算结果与普通集合逐项比较。这类有限检查能发现实现错误，规范性和一般复杂度仍需要前面的结构论证。

## 9. 把这四个子节连成一条阅读路线

布尔基础回答函数是什么、哪些表达式等价；布尔求值关心用什么操作、执行多少步；位运算把许多布尔操作装进一个字；二叉判定图尝试共用相同的剩余函数。

这几层不能混在一起：函数相同，不表示求值代价相同；语句少，不表示机器工作量少；约简后的表示唯一，也不表示表示很小。

带着这个区分进入 7.2，会更容易看懂组合搜索：候选状态可以用比特表示，约束可以写成布尔函数，而搜索过程会反复固定变量、检查剩余条件，并尽量复用已有工作。
