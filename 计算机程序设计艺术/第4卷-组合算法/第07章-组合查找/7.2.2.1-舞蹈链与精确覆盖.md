> 阅读位置：压缩包中的Fascicle 5C《Dancing Links》，2017-04-15早期稿，§7.2.2.1。该稿正文书页1—5（PDF第6—10页）有明显缺段和占位文字，后接习题与答案，不能当作完整定稿。本篇用现有稿确认精确覆盖、拼放和颜色约束主题，并参照作者原始论文核对DLX机制；下方例子和Python实现独立编写。

## 1. 把若干选择拼起来，每个要求恰好满足一次

设要求集合为`{0,1,2,3}`，可选项为：

|选项编号|覆盖的要求|
|---|---|
|0|0、1|
|1|2、3|
|2|0、2|
|3|1、3|
|4|0|
|5|1、2、3|

我们要选一些选项，使每个要求恰好出现一次。这个例子有三个解：`{0,1}`、`{2,3}`和`{4,5}`。选`{0,2}`不行，因为要求0被覆盖两次；只选`{0}`也不行，因为2和3没有被覆盖。

用0/1矩阵A表示，行对应选项，列对应要求。令$x_r\in\{0,1\}$表示是否选择第r行，则问题为

$$
\sum_r A_{rc}x_r=1\qquad\text{对每一列 }c.
$$

这是精确覆盖，不是“至少覆盖一次”的集合覆盖。把等号误改成大于等于号，会改变整个问题。

## 2. Algorithm X把搜索分支放在一个尚未完成的要求上

在上述例子中，如果先处理要求0，只需尝试包含0的行0、2、4。任一合法解必然恰好包含其中一行，因此这三个分支互斥并覆盖全部解。

选定一行后，它覆盖的列已经完成；所有与这些列相交的其他行都不能再选。剩余问题仍是同类精确覆盖问题。若所有必需列均已完成，就得到一个解；若某个必需列没有任何可选行，当前分支无解。

可以选择候选行最少的列来分支。这不改变正确性，只希望更早暴露冲突。维护每列剩余行数，能让这一选择有可见的依据。候选数为0的列应立即被发现，而不是继续在其他列中探索。

## 3. 双向链接为什么能承担撤销记录

对于循环双向链表中的节点x，令l=L[x]、r=R[x]。删除x只需把l、r直接连起来。若保留x原来的两个邻居指针，并在相邻删除操作都已适当撤销后把x重新插回，就能恢复原结构。

DLX把这种可逆更新用于稀疏0/1矩阵，每个1是一个节点，同时属于行环和列环；列头还记录长度。它是Algorithm X的一种数据结构实现，而不是另一套不同的解集定义。这一机制可参见Knuth的[Dancing Links原始论文](https://arxiv.org/abs/cs/0011047)。

下面的教学实现用整数下标代替对象指针，便于打印、比较和检查。空位、列头和数据节点都保存在同一组数组中，根节点编号为0。

|数组|含义|
|---|---|
|L、R|行内左右链接；列头处用于必需列的环|
|U、D|同一列中的上下链接|
|C|数据节点所属列头|
|size|该列当前仍可用的数据节点数|
|row|数据节点所属原始选项编号|

这些数组不是五份答案副本，而是同一稀疏关系的不同索引。总节点数由输入中的1的个数决定，不需要为所有0分配链表节点。

## 4. 用这个例子理解cover和uncover

第一次处理要求0时，`cover(0)`在内部使用实际列头编号1。它把这列从“尚未完成的必需列”环中移出；遍历包含0的每一行，把这些行的其他节点从其他列中暂时摘掉。

为什么还保留要求0自己的列链？因为搜索接下来仍要依次尝试其中的行0、2、4。这些行在选中之前都是当前分支候选，不能提前丢掉遍历入口。

如果选择行0，它还包含要求1，就继续覆盖要求1。此时剩余要求2、3可以由行1覆盖，形成解`{0,1}`。返回时，先撤销在更深处发生的操作，再撤销要求1，恢复到“准备尝试要求0的另一行”的状态。

我们的`uncover`按与`cover`相反的方向遍历，恢复计数和链接，最后把列头插回。不要在删除时把节点原链接清空；那会丢失本实现需要的恢复信息。

一种常见错误是解集看起来对了，但列长度没有恢复。它可能让下一次列选择偏离预期，甚至在再次调用求解器时出错。因此测试不仅比较答案，还会把搜索前后的链接数组和列长度逐项比较，并在同一个对象上再次求解。

## 5. 必需列与次要列表达不同约束

有些要求必须恰好一次，有些只要求至多一次。我们把前者称为必需列，后者称为次要列。求解结束只需所有必需列被覆盖；次要列可以完全没有被选择，但一旦某行使用它，其他冲突行仍必须排除。

例如n皇后模型中，每行、每列必须恰好有一个皇后，可作为必需列；每条对角线只要求至多一个，适合作为次要列。如果把每条对角线都设为恰好一次，会强加本不存在的要求。

实现上只有必需列头加入根环；次要列保留自环和垂直数据关系，因此仍能参与冲突删除。下面接口规定每个选项至少包含一个必需列，并拒绝空行。它不枚举“仅覆盖次要列的任意附加选择”，也不把重复出现的相同输入行当作同一行：行编号仍代表不同选项身份。

## 6. 建模通常比链表细节更影响结果

数独的候选项可以是“第r行、第c列填数字d”。一个候选同时满足四个要求：该格有数字、该行出现d、该列出现d、该宫出现d。标准9×9数独因此有324个必需列，完整候选集合最多729行，每行4个1；已知数字会排除不相容候选。

拼块问题则可为每块拼图设置一个身份列，再为每个棋盘格设置一个位置列。某次合法摆放覆盖一个拼块身份和它占据的全部格子。只给格子建列而忘了拼块身份，可能让同一块被使用多次。

早期稿还讨论颜色控制覆盖：多个选择在某个次要项目上不一定相互排斥，可能要求颜色一致。这超出普通“至多一次”模型，不能仅凭已有次要列接口就宣称支持。本文代码没有实现颜色净化、一般多重覆盖或最优化版本。

## 7. 完整教学实现

`solve()`收集全部解，所以答案本身占用与输出规模相当的内存。正常完整搜索后，内部状态必须恢复到调用前；如果改成可以提前停止的生成器或加入取消功能，应当把每个覆盖操作配上可靠的退出清理。

代码把200个小实例与“穷举全部行子集”的朴素参照比较，包含必需/次要列、重复选项身份和无解情况；每个实例再次求解并检查状态恢复。检查数据结构而不仅是答案，是本节的重点。

```python
from itertools import combinations, product
from random import Random


class DLX:
    def __init__(self, ncols, rows, primary=None):
        if ncols < 0:
            raise ValueError('negative column count')
        primary = set(range(ncols)) if primary is None else set(primary)
        if not primary <= set(range(ncols)):
            raise ValueError('invalid primary column')
        n = ncols + 1             # header 0 is the root
        self.L, self.R = list(range(n)), list(range(n))
        self.U, self.D = list(range(n)), list(range(n))
        self.C, self.row = list(range(n)), [-1] * n
        self.size = [0] * n
        tail = 0
        for col in sorted(primary):
            h = col + 1
            self.L[h], self.R[h] = tail, 0
            self.R[tail], self.L[0] = h, h
            tail = h
        for rid, raw in enumerate(rows):
            values = list(raw)
            if not values or len(values) != len(set(values)) or any(c < 0 or c >= ncols for c in values):
                raise ValueError('rows must contain distinct valid columns')
            if not set(values) & primary:
                raise ValueError('this interface requires a primary item in every row')
            nodes = []
            for col in values:
                h, x = col + 1, len(self.L)
                self.L.append(x); self.R.append(x)
                self.U.append(self.U[h]); self.D.append(h)
                self.C.append(h); self.row.append(rid)
                self.D[self.U[h]] = x
                self.U[h] = x
                self.size[h] += 1
                nodes.append(x)
            for j, x in enumerate(nodes):
                self.L[x], self.R[x] = nodes[j - 1], nodes[(j + 1) % len(nodes)]

    def cover(self, c):
        self.R[self.L[c]] = self.R[c]
        self.L[self.R[c]] = self.L[c]
        i = self.D[c]
        while i != c:
            j = self.R[i]
            while j != i:
                self.D[self.U[j]] = self.D[j]
                self.U[self.D[j]] = self.U[j]
                self.size[self.C[j]] -= 1
                j = self.R[j]
            i = self.D[i]

    def uncover(self, c):
        i = self.U[c]
        while i != c:
            j = self.L[i]
            while j != i:
                self.size[self.C[j]] += 1
                self.D[self.U[j]] = j
                self.U[self.D[j]] = j
                j = self.L[j]
            i = self.U[i]
        self.R[self.L[c]] = c
        self.L[self.R[c]] = c

    def snapshot(self):
        return tuple(tuple(a) for a in (self.L, self.R, self.U, self.D, self.size))

    def solve(self):
        answers, path = [], []

        def search():
            if self.R[0] == 0:
                answers.append(tuple(path))
                return
            c, j = self.R[0], self.R[0]
            while j:
                if self.size[j] < self.size[c]:
                    c = j
                j = self.R[j]
            self.cover(c)
            r = self.D[c]
            while r != c:
                path.append(self.row[r])
                j = self.R[r]
                while j != r:
                    self.cover(self.C[j])
                    j = self.R[j]
                search()
                j = self.L[r]
                while j != r:
                    self.uncover(self.C[j])
                    j = self.L[j]
                path.pop()
                r = self.D[r]
            self.uncover(c)
        before = self.snapshot()
        search()
        assert self.snapshot() == before
        return answers


def brute(ncols, rows, primary):
    answers = set()
    for selected in product((0, 1), repeat=len(rows)):
        counts = [sum(use and c in row for use, row in zip(selected, rows)) for c in range(ncols)]
        if all(counts[c] == 1 for c in primary) and all(v <= 1 for v in counts):
            answers.add(tuple(i for i, use in enumerate(selected) if use))
    return answers


def verify():
    rng = Random(721)
    cases = 0
    for ncols in range(1, 6):
        for _ in range(40):
            primary = set(range(rng.randint(1, ncols)))
            options = [a for k in range(1, ncols + 1) for a in combinations(range(ncols), k)
                       if set(a) & primary]
            rows = [rng.choice(options) for _ in range(rng.randrange(9))]
            dlx = DLX(ncols, rows, primary)
            got = {tuple(sorted(a)) for a in dlx.solve()}
            assert got == brute(ncols, rows, primary)
            assert got == {tuple(sorted(a)) for a in dlx.solve()}
            cases += 1
    assert DLX(0, []).solve() == [()]
    rows = [(0, 1), (2, 3), (0, 2), (1, 3), (0,), (1, 2, 3)]
    assert {tuple(sorted(a)) for a in DLX(4, rows).solve()} == {(0, 1), (2, 3), (4, 5)}
    return {'random_exact_cover_cases': cases, 'state_restoration': 'verified twice per case'}


if __name__ == '__main__':
    print(verify())
```

精确覆盖的优势来自三个部分共同作用：模型正确表达恰好一次或至多一次，分支选择尽早发现冲突，可逆更新减少复制。链表再精巧，也不能挽救一个把约束写错的模型。
