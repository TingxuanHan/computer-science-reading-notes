## 1. 列出所有情况，先明确“访问一次”是什么意思

假设一个测试系统有三项设置：模式有2种，强度有3档，开关有2种。配置可以写成三元组

$$
(a_0,a_1,a_2),\qquad 0\le a_0<2,\quad 0\le a_1<3,\quad 0\le a_2<2.
$$

总共有12种配置。知道这个数，并不等于已经有了一个能逐项测试它们的程序。生成算法还必须回答：从哪一种开始，怎样得到下一种，何时结束，以及是否会遗漏或重复。

这一节的各种算法，往往生成同一个对象集合，却使用不同的访问顺序。若消费者要按编号分工，混合进制很方便；若切换一项设置成本很高，格雷码更合适；若输入是一条连续符号流，希望每个长度为n的窗口都出现一次，就要换成德布鲁因循环。

生成器内部只保留当前状态，和把全部结果装进列表，是两种资源开销。本文用`yield tuple(a)`交付快照，复制长度n的元组需要O(n)时间；即使内部后继只修改一个位置，也不能把整段Python程序说成“每个结果只花常数时间”。

## 2. 混合进制就是一只各位容量不同的里程表

设第i位的基数为$`m_i`$，每位可取$`0,\ldots,m_i-1`$。从全零出发，最右位加一；若达到基数就归零，并向左进位。共有

$$
N=\prod_{i=0}^{n-1}m_i
$$

个对象。我们的约定是最右位变化最快，因此前述配置的开头为`000, 001, 010, 011, 020, 021, 100`。

为什么没有重复？可以给每个对象一个整数编号：

$$
R(a)=\sum_{i=0}^{n-1}a_i\prod_{j=i+1}^{n-1}m_j.
$$

每次进位恰好让编号加一。从0走到N−1就同时证明了覆盖性、唯一性和终止性。实现时不必重复计算乘积，用霍纳法依次做`r = r * base + digit`即可。

反过来，从最右位开始对基数取余、整除，就能把编号还原为元组。这是排名与反排名。它允许任务直接从第r个配置开始，而不用先生成前r个；还可以把编号区间分给不同工作进程。

一次进位最坏会扫描n位。如果所有基数至少为2，把全部进位次数加起来后，平均修改量受几何级数控制。但允许大量基数1时，扫描固定位置会带来额外成本。工程实现可先去掉这些固定维度。

还有一个值得保留的边界：零个维度的笛卡尔积有一个元素，即空元组`()`。它与某一维没有任何可选值不同。下面接口规定基数必须为正，因此后者作为非法输入处理。

## 3. 格雷码让相邻配置只改一位

二进制计数从`0111`变为`1000`时，四位都会改变。二进制反射格雷码采用

$$
g(r)=r\oplus(r\gg1),\qquad 0\le r<2^n.
$$

n=3时，按通常高位在左显示，得到`000, 001, 011, 010, 110, 111, 101, 100`。相邻两项，包括末项回到首项，都只差一位。

可以从反射构造理解：把n−1位序列前面添0，再把它逆序后前面添1。两半内部保留原来的单比特变化；连接处低位完全相同，只改新添的高位。归纳后，所有n位串各出现一次。

代数形式也能解释变化位置。r增加一时，它的末尾连续1翻成0，前面的0变成1；这些连续变化经过相邻位异或后互相抵消，只剩一位变化。这里的结论依赖二进制反射构造，并不是“任何排列过的二进制串都是格雷码”。

格雷码还可逆。若$`g=b\oplus(b\gg1)`$，反复代入得到

$$
b=g\oplus(g\gg1)\oplus(g\gg2)\oplus\cdots.
$$

因此格雷码是重新安排访问顺序，并没有丢失原编号的信息。

## 4. 单比特变化为何能省下实际工作

假设要计算每个子集的权重和

$$
W(a)=\sum_i w_i a_i.
$$

若从头求和，每次需要遍历n项。格雷码从a走到下一项时，只翻转第j位，就能把W加上或减去$`w_j`$。类似地，某些乘积、校验值、局部目标函数，也可以随状态增量更新。

但收益来自消费者确实支持增量操作。若每个对象都要完整序列化、写文件，输出成本仍然存在；若目标函数每次都涉及全体变量，单比特变化也未必带来数量级收益。

原节还讨论了更一般的混合进制反射序列、变换次数的平衡及其他格雷循环。不同构造控制的是不同性质：一次只改一个坐标、不反复偏爱某些坐标、能否首尾相接，以及生成下一步需要多少辅助操作。这些性质不能混为一谈。

## 5. 无循环后继：把“找下一位”变成查表

在这里，“无循环”指两次访问之间的控制步骤有固定上界，不是说整个枚举过程没有循环。下面`gray_focus`用焦点数组维护下一次该翻的坐标。当前状态占n位，辅助数组占n+1个位置。

`focus[0]`直接给出下一个变化位置j；两个链接式更新重新安排后续访问；j=n是终止哨兵。初始焦点为`0,1,…,n`。这把“扫描一串低位，决定下一步”变成了固定次数的数组访问。

代码中的坐标0对应最低位，所以元组显示为低位在前，与上文常规二进制书写方向相反。校验先把它还原为整数，再与公式$`g(r)`$逐项比较，避免把显示方向差异误判成顺序错误。

## 6. 德布鲁因循环解决的是连续窗口覆盖

格雷码关注相邻完整对象差多少；德布鲁因循环关注相邻窗口共享多少。字母表有k个符号时，一个n阶德布鲁因循环长度为$`k^n`$，沿循环读取的全部长度n窗口，恰好覆盖所有n元组一次。

例如二进制n=3时，循环`00010111`的8个循环窗口覆盖8种三元组。若要存成普通线性串，末尾再附上开头n−1个符号，跨边界的窗口才看得见。

这也可视为一个图问题：顶点是长度n−1的串，每条n位串是从其前缀到后缀的一条边。每个顶点有k条入边、k条出边；遍历所有边一次所产生的符号流，正好满足窗口要求。这里遍历的是边，不是把顶点各访问一次。

原节还从项链和Lyndon词组织同一构造。项链把循环移位看成同类；Lyndon词是无周期词中循环移位的最小代表。按字典序串接长度整除n的适当代表，可构造德布鲁因循环。下面递归程序维护候选周期，只在周期整除n时追加一个周期。这是教学实现，返回整个循环，所以会占用与输出长度相当的内存。

## 7. 可运行代码与核验

以下代码仅使用Python标准库。混合进制结果和`itertools.product`逐项比较；排名与反排名往返；格雷码同时核验公式、唯一性和相邻距离；德布鲁因循环核验全部循环窗口。有限测试用于发现实现错误，前面的不变式与构造说明才负责解释算法为什么成立。

```python
from itertools import product
from math import prod


def mixed_tuples(radices):
    m = tuple(radices)
    if any(v < 1 for v in m):
        raise ValueError('radices must be positive')
    a = [0] * len(m)
    while True:
        yield tuple(a)
        j = len(a) - 1
        while j >= 0 and a[j] == m[j] - 1:
            a[j] = 0
            j -= 1
        if j < 0:
            return
        a[j] += 1


def rank_tuple(a, m):
    if len(a) != len(m) or any(b < 1 or not 0 <= x < b for x, b in zip(a, m)):
        raise ValueError('invalid tuple')
    r = 0
    for x, base in zip(a, m):
        r = r * base + x
    return r


def unrank_tuple(r, m):
    if any(b < 1 for b in m) or not 0 <= r < prod(m):
        raise ValueError('invalid rank or radix')
    a = [0] * len(m)
    for j in range(len(m) - 1, -1, -1):
        r, a[j] = divmod(r, m[j])
    return tuple(a)


def gray_focus(n):
    if n < 0:
        raise ValueError('n must be nonnegative')
    a = [0] * n                 # index 0 is the low bit
    focus = list(range(n + 1))
    while True:
        yield tuple(a)
        j = focus[0]
        focus[0] = 0
        if j == n:
            return
        focus[j] = focus[j + 1]
        focus[j + 1] = j + 1
        a[j] ^= 1


def inverse_gray(g):
    b = 0
    while g:
        b ^= g
        g >>= 1
    return b


def de_bruijn(k, n):
    if k < 1 or n < 1:
        raise ValueError('k and n must be positive')
    a, answer = [0] * (n + 1), []

    def visit(t, period):
        if t > n:
            if n % period == 0:
                answer.extend(a[1:period + 1])
            return
        a[t] = a[t - period]
        visit(t + 1, period)
        for digit in range(a[t - period] + 1, k):
            a[t] = digit
            visit(t + 1, t)
    visit(1, 1)
    return tuple(answer)


def verify():
    tuple_cases = 0
    for n in range(5):
        for m in product(range(1, 4), repeat=n):
            got = list(mixed_tuples(m))
            assert got == list(product(*(range(b) for b in m)))
            for r, a in enumerate(got):
                assert rank_tuple(a, m) == r
                assert unrank_tuple(r, m) == a
                tuple_cases += 1
    for n in range(11):
        rows = list(gray_focus(n))
        words = [sum(bit << j for j, bit in enumerate(a)) for a in rows]
        assert words == [r ^ (r >> 1) for r in range(1 << n)]
        assert len(set(words)) == 1 << n
        assert all((x ^ y).bit_count() == 1 for x, y in zip(words, words[1:]))
        assert all(inverse_gray(g) == r for r, g in enumerate(words))
    for k in range(1, 4):
        for n in range(1, 6):
            cycle = de_bruijn(k, n)
            windows = {tuple(cycle[(i + j) % len(cycle)] for j in range(n))
                       for i in range(len(cycle))}
            assert len(cycle) == k ** n
            assert windows == set(product(range(k), repeat=n))
    return {'tuple_rank_roundtrips': tuple_cases, 'gray_max_n': 10,
            'de_bruijn_cases': 15}


if __name__ == '__main__':
    print(verify())
```

## 8. 本节的选择原则

|使用需求|优先考虑|需要付出的代价|
|---|---|---|
|直接定位第r个对象、分段运行|混合进制排名/反排名|相邻对象可能改多位|
|每次切换一项并增量维护结果|格雷码|访问顺序不再是普通字典序|
|内部后继延迟必须稳定|焦点数组等无循环方法|额外状态及更细的正确性论证|
|用连续输入覆盖全部固定长度窗口|德布鲁因循环|窗口跨边界，输出语义不同|

下一节讨论排列。它们不再是各坐标独立取值：某个元素一旦使用，其余位置就不能再次使用。这一处约束，会把里程表变成新的后继规则。
