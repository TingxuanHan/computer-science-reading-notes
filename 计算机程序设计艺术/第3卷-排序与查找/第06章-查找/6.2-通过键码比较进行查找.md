## 1. 二分查找最重要的部分是区间含义

设数组 $a$ 已按非降序排列。与其先问“找到了吗”，不如先定义一个边界问题：

```math
\mathop{\mathrm{lower\_bound}}\nolimits(x)
=\min\{i:a_i\ge x\},
```

没有这样的元素时返回 $n$。这个定义能自然处理重复键、空数组和插入位置。

维护半开区间 $[lo,hi)$，并始终保证：

```math
i\lt lo\Rightarrow a_i\lt x,\qquad
i\ge hi\Rightarrow a_i\ge x.
```

令 $mid=\lfloor(lo+hi)/2\rfloor$。若 $a_{mid}<x$，则 $mid$ 及其左侧都不是边界，把 $lo$ 改成 $mid+1$；否则边界不会在 $mid$ 右边，把 $hi$ 改成 $mid$。每一步都保留不变量，又严格缩短未确定区间。

当 $lo=hi$ 时，两边的性质恰好把边界夹住。若还要回答精确命中，只需检查

```math
lo\lt n\quad\text{且}\quad a_{lo}=x.
```

这里的最后一次相等检查不属于循环中的小于比较。循环最多进行 $\lceil\log_2(n+1)\rceil$ 次小于比较；实际 Python 表达式的条数不能直接当成原书一次三路键码比较的计数。

二分查找的速度依赖能快速访问中间位置。对单向链表反复走到中间，通常会失去数组版本的优势。数组插入一个元素也可能移动 $O(n)$ 个已有元素，查找快并不表示更新同样快。

## 2. 二叉查找树把有序区间保存在结构中

对互异键，二叉查找树要求：

$$
\text{左子树所有键}<\text{当前键}<\text{右子树所有键}.
$$

查找从根开始，等于则成功，小于走左边，大于走右边，到空链接则失败。插入先走同样的路径，到空链接时挂上新节点。

删除需要区分三种情况：

1. 没有孩子，直接移除。
2. 只有一个孩子，让父链接接向这个孩子。
3. 有两个孩子，可用右子树最小键，也就是中序后继，替换当前键，再删除后继原来的节点。

第三种情况必须完成后半步，否则会保留两个相同键。若节点带有值，替换时也要保持键和值的对应关系。本文代码实现的是集合语义，重复插入不增加节点。

这些操作沿树的一条路径工作，成本取决于高度 $h$。普通 BST 并不自动满足 $h=O(\log n)$：按 $1,2,\ldots,n$ 的顺序插入，会得到一条长度为 $n$ 的链。

随机分析要把“随机”说具体。在固定互异键的全部插入排列等概率、只进行插入的模型下，再等概率选一个已存键查找，平均节点比较次数为

$$
2\left(1+\frac1n\right)H_n-3\qquad(n\ge1).
$$

若等概率选取 $n+1$ 个失败间隙，则对应均值为

$$
2H_{n+1}-2.
$$

这里不是把所有二叉树形状等概率抽取。连续执行任意删除和插入，也不保证一直维持这个随机树分布。平均性质不能代替对最坏高度的控制。

## 3. 最优查找树：概率分布与树高是两种目标

如果数据长期不变，且某些键远比其他键热门，可以让热门键更靠近根。最小高度的树，未必有最小的加权查找成本。

给定 $K_1<\cdots<K_n$，设成功概率为 $p_1,\ldots,p_n$；失败落入各相邻间隙及两端的概率为 $q_0,\ldots,q_n$，全部概率和为 1。以根深度为 0，访问实际节点才计算一次键码比较，则期望成本是

```math
\sum_{i=1}^{n}p_i(\mathop{\mathrm{depth}}\nolimits(K_i)+1)
+\sum_{j=0}^{n}q_j\mathop{\mathrm{depth}}\nolimits(\text{间隙 }j).
```

空树不比较任何键，成本取 0。有些教材把访问外部空节点也计入成本，初值因此不同；两套公式不能混用。

把区间 $(i,j)$ 定义为键 $K_{i+1},\ldots,K_j$ 及其间隙，记

$$
w(i,j)=\sum_{t=i+1}^{j}p_t+\sum_{t=i}^{j}q_t.
$$

若选择 $K_k$ 为根，左右子问题分别是 $(i,k-1)$ 与 $(k,j)$。区间内的每个请求都先比较一次根，因此

$$
c(i,i)=0,
$$

```math
c(i,j)=w(i,j)+
\min_{i\lt k\le j}\{c(i,k-1)+c(k,j)\}\qquad(i\lt j).
```

按区间长度从小到大计算，就得到动态规划。直接枚举根的版本需要 $O(n^3)$ 时间、$`O(n^2)`$ 空间；利用非负权重下最优根的单调性，可以把搜索范围缩小到 $O(n^2)$ 时间。

这个方法适合静态权重问题。每插入一个键就重新求最优树，维护费用可能超过节省的查找费用。接下来的平衡树选择了另一种保证：不依赖访问概率，约束结构的最坏高度。

## 4. AVL 树用局部条件约束全局高度

本文约定空树高度为 0，叶节点高度为 1，并定义

$$
b(v)=h(v_{\mathrm{left}})-h(v_{\mathrm{right}}).
$$

AVL 条件要求每个节点都有 $|b(v)|\le1$。这里的符号方向与原书使用的右高减左高相反，但条件相同；旋转判断必须和选用的方向一致。

局部高度差为什么足以限制整棵树？令 $S(h)$ 是高度为 $h$ 的 AVL 树最少包含的节点数。最稀疏时，两棵子树的高度分别为 $h-1,h-2$：

$$
S(0)=0,\quad S(1)=1,\quad
S(h)=1+S(h-1)+S(h-2).
$$

由此

$$
S(h)=F_{h+2}-1.
$$

斐波那契数按指数增长，所以容纳 $n$ 个节点的 AVL 树高度为 $O(\log n)$。这条结论来自明确的结构约束，而不是对输入顺序的乐观假设。

插入后，从插入点向根更新高度。左边过高时看左孩子的倾斜方向，右边过高时对称处理：

| 失衡路径 | 修复 |
| --- | --- |
| 左—左 | 对当前节点右旋 |
| 左—右 | 先对左孩子左旋，再对当前节点右旋 |
| 右—右 | 对当前节点左旋 |
| 右—左 | 先对右孩子右旋，再对当前节点左旋 |

旋转的依据是中序次序不变。以右旋为例，把当前根写为 $z$、其左孩子写为 $y$，相关三段子树 $A,B,C$ 与两个节点的次序为

```math
A\lt y\lt B\lt z\lt C.
```

旋转后让 $y$ 做根、$`z`$ 做右孩子，仍保留这条次序，所有键的查找区间也就保留下来。高度要先更新降下去的旧根，再更新升上来的新根。

AVL 删除还可能让高度下降沿祖先方向继续传播，不能把插入时的停止条件原样搬过去。下面仅实现插入和查询，避免让一个简短示例假装具备完整容器接口。

## 5. 多路树把成本单位改成页面访问

如果记录在外存里，一次加载一个页面能得到许多键和孩子指针，那么逐层只分成两路，未必划算。一个节点容纳多个有序键，可以把候选区间同时分成多段。

对阶为 $m$ 的 B 树，常用约定是最多 $m$ 个孩子；非根内部节点至少有

$$
t=\lceil m/2\rceil
$$

个孩子，有 $k$ 个孩子的内部节点保存 $k-1$ 个键。根在非单节点树中至少有两个孩子，所有外部空节点位于同一层。这里用外部节点表示查找失败的间隙，与把最底层有键节点叫作“叶子”的另一种说法要区分。

若根到外部节点的距离为 $h$，非空树且 $m\ge3$，则最少有 $2t^{h-1}$ 个外部间隙。含 $n$ 个键的查找树有 $n+1$ 个间隙，因此

$$
n+1\ge2t^{h-1},
\qquad
h\le1+\log_t\frac{n+1}{2}.
$$

分支多使层数低。插入溢出时分裂节点，把中间键提升到父节点；根也溢出时才增加一层。删除造成节点过空时，通过向相邻兄弟借键或合并节点保持占用条件。

这一节的核心不是背诵一个最大孩子数，而是联结“每页能放多少信息”和“沿路径要读取多少页”。页面内部还需要查找，根或上层页面也可能在缓存中。原书具体机器的耗时表不能直接作为今天设备的性能数字。

## 6. 可运行的二分边界与 AVL 插入

下面的键需支持一致的全序关系；示例使用整数。AVL 集合对重复键保持不变。每个节点缓存高度，因此修复高度不必重新遍历子树。

```python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = self.right = None
        self.height = 1


def height(v):
    return v.height if v else 0


def fix(v):
    v.height = 1 + max(height(v.left), height(v.right))


def rotate_right(z):
    y = z.left
    z.left = y.right
    y.right = z
    fix(z)
    fix(y)
    return y


def rotate_left(z):
    y = z.right
    z.right = y.left
    y.left = z
    fix(z)
    fix(y)
    return y


def insert(v, key):
    if v is None:
        return Node(key)
    if key < v.key:
        v.left = insert(v.left, key)
    elif key > v.key:
        v.right = insert(v.right, key)
    else:
        return v
    fix(v)
    balance = height(v.left) - height(v.right)
    if balance > 1:
        if height(v.left.left) < height(v.left.right):
            v.left = rotate_left(v.left)
        return rotate_right(v)
    if balance < -1:
        if height(v.right.right) < height(v.right.left):
            v.right = rotate_right(v.right)
        return rotate_left(v)
    return v


def contains(v, key):
    while v is not None:
        if key == v.key:
            return True
        v = v.left if key < v.key else v.right
    return False


def inorder(v):
    if v is not None:
        yield from inorder(v.left)
        yield v.key
        yield from inorder(v.right)


def lower_bound(a, key):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < key:
            lo = mid + 1
        else:
            hi = mid
    return lo


root = None
for key in [30, 10, 20, 50, 40, 60, 20]:
    root = insert(root, key)
print(list(inorder(root)), height(root))
print(contains(root, 40), contains(root, 35))
print(lower_bound([2, 4, 4, 9], 4), lower_bound([2, 4, 4, 9], 5))
```

输出：

```text
[10, 20, 30, 40, 50, 60] 3
True False
1 3
```

核对 AVL 不能只看输出是否排序。应在每次插入后同时检查：左右子树范围正确、缓存高度等于递归计算高度、每个节点的高度差不超过 1、重复插入没有增加节点。三元素的四种失衡顺序，以及较长的递增和递减输入，能揭示只测试随机数据时容易漏掉的问题。

## 7. 把四种方案放回各自的问题里

静态有序数组适合直接定位和紧凑存储；普通 BST 便于理解按比较分支的动态结构，但需要防范退化；最优查找树使用访问权重优化平均代价；AVL 控制最坏高度；B 树围绕页面容量和占用率减少层数。
