# 【计算机程序设计艺术 TAOCP】卷3·6.4 散列：地址算出来以后，冲突和删除怎么办

如果能根据键直接算出记录的位置，查找似乎就只剩一次数组访问。问题在于：可用地址有限，不同键可能得到相同地址；表会逐渐变满；插入和删除还会改变原来的探测路径。

因此，理解散列需要把三件事一起看：怎样计算初始地址、冲突后怎样继续、什么时候可以确认查找失败。只写出一个取模表达式，还没有得到完整的查找算法。

> 阅读定位：《计算机程序设计艺术》第 3 卷《排序与查找》第 2 版，苏运霖译，国防工业出版社，2002 年；原书 §6.4，书内第 478—520 页。扫描 PDF 页码为书页加 13，第 521 页开始 §6.5。下面用自拟的整数键线性探测表解释状态与边界，不复刻原书的 MIX 程序。

## 1. 散列函数提供起点，不负责保证唯一

设表有 $M$ 个槽位，散列函数给出

```math
h(K)\in\{0,1,\ldots,M-1\}.
```

不同键 $K_1\ne K_2$ 可能满足 $h(K_1)=h(K_2)$，这叫冲突。若键的可能数量超过 $M$，冲突从计数上就不可能完全避免。

一个简单例子是

$$
h(K)=K\bmod M.
$$

但取模的效果依赖输入结构。若键全是 $M$ 的倍数，就会全部落到同一个槽位。选一个素数作为表长可以避免某些算术规律带来的问题，却不能自动消除所有不良输入。

乘法散列可以通过乘以常数并取适当部分，把键的信息混合到地址中。字符串散列也应考虑字符位置；若只是把字符值相加，字符排列不同的字符串会系统性地得到同一个结果。

对于已知、固定的键集合，可以设法构造无冲突的函数。但这样的静态设计不表示随后加入任意新键仍然无冲突。实际容器仍需要明确支持什么更新操作。

## 2. 冲突后，记录放在哪里

常见的两条路线是：

| 方法 | 冲突记录存放方式 | 主要边界 |
| --- | --- | --- |
| 分离链接 | 每个地址对应一组记录，如链表 | 桶内查找、额外链接、内存分配 |
| 开放寻址 | 所有记录保存在表内，冲突后按规则探测其他槽位 | 空间占用率、探测覆盖、删除状态 |

记装载因子为

$$
\alpha=\frac{N}{M},
$$

其中 $N$ 是实际记录数。分离链接允许 $\alpha>1$；在均匀散列模型下，桶的期望长度与 $\alpha$ 成比例，查询的期望成本通常写成 $O(1+\alpha)$。

开放寻址若希望插入时最终遇到空槽，就需要 $\alpha<1$。即使只差一个槽位才满，探测路径也可能很长；“还有空间”与“性能仍然好”是两个条件。

原书还讨论把链接放进同一地址表中的聚合式组织，以及插入时重排探测路径等方法。分析公式取决于具体碰撞处理机制，不能只因都叫散列就互相套用。

## 3. 线性探测为什么会形成长簇

本文采用向前的线性探测：

$$
h_j(K)=(h(K)+j)\bmod M,\qquad j=0,\ldots,M-1.
$$

发生冲突就检查下一格，到表尾回绕。优点是简单、访问位置相邻；问题是连续占用区容易合并。

一个长簇中的任意地址发生新插入，往往都会把新元素放到簇尾，继续延长这一段。后来本来属于邻近地址的元素又会撞上它。这种自我增长就是基本聚集现象。

在独立均匀的初始散列地址、从空表逐项插入、表长很大且固定 $\alpha<1$ 的经典模型下，线性探测的平均探测次数近似为

$$
E[C_{\text{成功}}]\approx
\frac12\left(1+\frac{1}{1-\alpha}\right),
$$

$$
E[C_{\text{失败}}]\approx
\frac12\left(1+\frac{1}{(1-\alpha)^2}\right).
$$

成功查询这里等概率选择一个已存键；失败查询具有相同的均匀初始地址模型。探测次数包括访问最终判定成功或失败的那个槽位。

| 装载因子 | 成功查询近似次数 | 失败查询近似次数 |
| --- | ---: | ---: |
| 0.5 | 1.5 | 2.5 |
| 0.8 | 3 | 13 |
| 0.9 | 5.5 | 50.5 |

当 $\alpha$ 接近 1，失败查找比成功查找恶化得更快。这说明容量预留为什么重要，但表中数字不是某个任意输入的最坏保证，也不能原样用于留下大量删除标记的表。

最坏情况下，多个键落到同一地址，一次操作仍然可能检查 $M$ 个槽位。所谓散列的“常数时间”，需要说明随机性来源、装载因子和维护策略。

## 4. 双重散列必须走得完整

为了让不同键在冲突后走不同路线，可以使用

```math
h_j(K)=(h_1(K)+j\,h_2(K))\bmod M.
```

仅有不同的步长还不够，步长必须保证能覆盖所有槽位。经过 $r$ 步回到起点，需要

```math
r\,h_2(K)\equiv0\pmod M.
```

最小正整数解为

$$
r=\frac{M}{\gcd(M,h_2(K))}.
$$

因此，覆盖整张表的条件是 $\gcd(M,h_2(K))=1$。素数表长配合 $1$ 到 $M-1$ 的步长满足这个条件；若表长为二的幂，则应选择奇数步长。取一个与键无关的固定步长，只是重新安排了访问次序，不能指望它自动消除线性探测式的聚集。

在更理想化的“各键探测排列均匀”模型中，失败探测的尺度约为 $1/(1-\alpha)$，成功探测约为 $-\ln(1-\alpha)/\alpha$。实际双重散列并不等于完全独立的随机排列，这些表达式也不能冒充有限表的逐次精确成本。

## 5. 删除不能随手把槽位变空

设 $M=5$，键 0、5、10 的初始地址都是 0，它们依次存到槽位 0、1、2。现在删除 0。

如果把槽位 0 直接恢复成从未使用的空槽，查找 10 时会在第一格停止，错误地报告不存在。后面的记录仍在，但路径上的“可以停止”标志被破坏了。

简单做法是区分三种状态：

- EMPTY：真正的空槽，可以结束失败查找。
- LIVE：保存有效键值对。
- DELETED：曾经有记录，查找必须继续；插入可以复用。

插入遇到 DELETED 时，应记住第一个可复用位置，但继续向后找，直到遇到目标键、真正的空槽，或者探测完整张表。若立刻写入，后面可能已经存在同一个键，从而产生重复记录。

另一类删除方法会移动后面的记录，修复探测链。它能避免墓碑累积，但需要严格判断哪些记录可以往前搬，不能任意把后一个槽位挪过来。

若采用删除标记，容量管理还应观察

$$
\alpha_{\text{占用}}
=\frac{N+D}{M},
$$

其中 $D$ 是删除标记数。有效记录少不代表探测短。重建时只重新插入有效记录，能清理标记；扩容重建则同时改变地址计算。均摊成本依赖扩容规则，不是“偶尔扩容”这句话本身就能保证。

## 6. 可运行的固定容量散列表

下面仅接受整数键，支持存放 None 值。容量固定，满表插入新键时抛出 OverflowError；已有键仍可以更新。每条探测路径最多走 $M$ 格，因此满表及全删除标记的状态也会结束。

为了看清算法，使用最简单的取模函数，示例主动制造冲突。它没有实现自动扩容，不把测试里的正确性当作生产环境性能保证。

```python
EMPTY = object()
DELETED = object()


class LinearMap:
    def __init__(self, capacity):
        if type(capacity) is not int or capacity <= 0:
            raise ValueError("capacity must be a positive integer")
        self.slots = [EMPTY] * capacity
        self.size = self.deleted = 0

    def _indices(self, key):
        if type(key) is not int:
            raise TypeError("integer keys only")
        m = len(self.slots)
        for step in range(m):
            yield (key + step) % m

    def _find(self, key):
        for i in self._indices(key):
            entry = self.slots[i]
            if entry is EMPTY:
                return None
            if entry is not DELETED and entry[0] == key:
                return i
        return None

    def __getitem__(self, key):
        i = self._find(key)
        if i is None:
            raise KeyError(key)
        return self.slots[i][1]

    def _write_new(self, i, key, value):
        if self.slots[i] is DELETED:
            self.deleted -= 1
        self.slots[i] = (key, value)
        self.size += 1

    def __setitem__(self, key, value):
        first_deleted = None
        for i in self._indices(key):
            entry = self.slots[i]
            if entry is EMPTY:
                target = i if first_deleted is None else first_deleted
                self._write_new(target, key, value)
                return
            if entry is DELETED:
                if first_deleted is None:
                    first_deleted = i
            elif entry[0] == key:
                self.slots[i] = (key, value)
                return
        if first_deleted is None:
            raise OverflowError("table is full")
        self._write_new(first_deleted, key, value)

    def __delitem__(self, key):
        i = self._find(key)
        if i is None:
            raise KeyError(key)
        self.slots[i] = DELETED
        self.size -= 1
        self.deleted += 1

    def __len__(self):
        return self.size

    def rebuild(self, capacity):
        fresh = LinearMap(capacity)
        for entry in self.slots:
            if entry is not EMPTY and entry is not DELETED:
                fresh[entry[0]] = entry[1]
        return fresh


table = LinearMap(5)
for key, value in [(0, "zero"), (5, "five"), (10, "ten")]:
    table[key] = value
del table[0]
table[10] = "TEN"
table[15] = "fifteen"
print(len(table), table[5], table[10], table[15])
table[-1] = None
print(table[-1], table.deleted)
table[20] = "twenty"
try:
    table[25] = "overflow"
except OverflowError:
    print("full")
larger = table.rebuild(11)
print(len(larger), larger[10], larger.deleted)
```

输出：

```text
3 five TEN fifteen
None 0
full
5 TEN 0
```

删除 0 后更新 10，表的有效元素数没有错误增加。插入 15 复用了删除槽位；表满后插入新键明确失败；重建把五条有效记录搬入更大的表。

检查这样的实现，至少需要覆盖：同地址冲突、从表尾回绕、满表更新、满表失败查找、全删除标记、删除后重新插入、删除不存在的键，以及存储 None。还可以用 Python 字典作为语义参照，在容量约束下对随机操作逐步比对，检查槽位中没有重复键，计数也与真实状态一致。

## 7. 散列的边界：精确查询与维护条件

散列适合按完整键查找记录，但通常不直接保留大小顺序。找到“所有键在某个区间内的记录”或“所有以某前缀开头的键”，不能自动从一次地址计算得到答案。

原书的分析反复提醒我们，平均成本由结构规则和分布假设共同决定。好的散列函数、完整的探测路径、正确的删除语义、合理的占用率，缺少任何一项都会留下问题。

下一节 §6.5 把查询从一个主键扩展成多个条件：一条记录可能满足多个属性，一个条件可能命中许多记录。此时，倒排表、位图和候选过滤开始承担不同的工作。
