# 【计算机程序设计艺术 TAOCP】卷3·6.3 数字查找：把键码拆成字符，怎样沿前缀找到记录

把 car、cart、cat 放进同一张表，前三次查找可能反复比较开头的 c 和 a。既然这些前缀相同，能不能把相同部分只组织一次，让后续字符决定去哪里？

数字查找正是从键码的组成部分出发。这里的“数字”可以是一位二进制、一组比特，也可以是一个字符；它不要求键码本身是十进制整数。关键变化是：用当前字符或数位直接选择下一条路径。

> 阅读定位：《计算机程序设计艺术》第 3 卷《排序与查找》第 2 版，苏运霖译，国防工业出版社，2002 年；原书 §6.3，书内第 458—478 页，扫描 PDF 页码为书页加 13。末页与 §6.4 相接。原书包含检索树、数字查找树和 Patricia 方法；本文使用自拟的稀疏字符 Trie 代码解释前缀和终止标记。

## 1. Trie 把共有前缀变成共有路径

一个朴素的字符 Trie 可以这样组织：

1. 根表示空前缀。
2. 从一个节点出发，标记为字符 $c$ 的边表示在当前前缀后追加 $c$。
3. 沿完整键走到的节点，用额外标志表示“这里确实存有一个键”。

于是 car 和 cart 共享 c、a、r 三条边，cart 只额外走一条 t 边；cat 在 a 之后分向 t。

这种结构同时支持两个问题：

- 精确查找：是否存有完整键 car？
- 前缀查找：有哪些键以 ca 开头？

精确查找走完输入后，还要检查终止标志。前缀查找走到前缀节点后，则要枚举下面所有已经终止的键。两种查询共享前半段路径，终点条件不同。

## 2. “走得到”不等于“这个键存在”

假设只存 cart。查询 car 可以顺利走过三条边，但 car 并没有被插入。因此节点是否存在与键是否存在必须分开记录。

同样地，删除 car 时如果 cart 还在，就不能把 r 节点以下的整段路径删掉。正确做法是先清除 car 的终止标志，再从下往上删除既不表示完整键、又没有孩子的空节点。

空字符串也值得单独检查。它对应根本身，所以根可以有终止标志。若程序默认“每个键至少有一条边”，就会把这个边界漏掉。

键值映射还要处理另一种歧义：值本来就允许是 None 时，不能用“值是否为 None”判断键是否存在。下面的实现使用独立的 terminal 标志；查无此键时抛出 KeyError，已存 None 则正常返回 None。

原书还讨论在叶端保存完整键、减少展开节点的方法。这种表示并不要求把每个键的所有字符都各建一个节点，但最终需要比较候选的完整键。不能把某一种叶端表示中的检查步骤，直接从另一种实现里删掉。

## 3. 时间为什么与键长有关

设键长为 $L$，每个字符选取孩子的成本为常数。普通 Trie 的精确查找读取至多 $L$ 个字符，因此是 $O(L)$；键不在表中时，遇到不存在的分支可以提前结束。

这个上界不需要表中的键随机分布。它也不意味着查找完全“与数据规模无关”：随着数据增加，键长、前缀共享、内存占用和缓存行为都可能变化。

与二叉查找树相比，比较次数的单位发生了变化。平衡 BST 查找是 $O(\log n)$ 次**完整键比较**，每次比较长字符串可能读多个字符；Trie 的 $O(L)$ 计数通常是**数位访问或分支选择**。不先统一成本单位，这两个表达式就无法直接比较。

对于前缀 $P$，假设返回 $k$ 个结果，光是输出它们的记录标识就需要 $\Omega(k)$ 工作；若输出完整字符串，还至少与总输出长度成比例。不能把一次定位到前缀节点的 $O(|P|)$ 当作返回全部结果的时间。

下面的 Python 版本用字典保存孩子，依赖字典操作的通常均摊或期望效率。为按字符顺序枚举结果，还会对子节点排序，并构造路径字符串，这些成本也应算入实际枚举过程。

## 4. 多大的分支数合适

若每个节点用一个长度为 $M$ 的数组保存孩子，选第 $d$ 个孩子十分直接，但每个节点都要付出 $M$ 个槽位。很多节点只有一两个孩子时，空指针占用会很明显。

| 分支表示 | 好处 | 要付出的成本 |
| --- | --- | --- |
| 固定 $M$ 路数组 | 分支定位直接 | 稀疏节点浪费槽位 |
| 稀疏映射 | 只保存实际存在的分支 | 映射结构和查找有额外成本 |
| 一次读取更多比特 | 同样位长可能需要更少层 | 分支数随每层位数指数增加 |
| 压缩单孩子路径 | 减少节点和指针跳转 | 需要检查被压缩的标签或完整候选 |

若每层读取 $r$ 位，那么 $M=2^r$。把 $r$ 增大，并不保证总时间一直下降；更大的节点可能抵消更浅的层数。

在独立、均匀的 $M$ 进制数位模型中，要把约 $n$ 个键分开，所需区分长度通常与 $\log_M n$ 同阶。这是概率模型下的尺度判断。输入若共享很长的前缀，仍然需要处理这些前缀，不能用这个平均估计替代最坏分析。

## 5. 数字查找树与 Trie 不要混在一起

数字查找树，也称 DST，可以在节点中直接存放一个完整键。查找时先比较目标与当前完整键是否相同；不同才根据目标的某一位选择左、右或更一般的下一分支。

这与“内部节点表示前缀、沿字符逐层前进”的 Trie 表示有差别：

- 节点中的记录可能在较浅位置就被完整比较并命中。
- 分支根据目标数位决定，不必根据它与当前节点键的大小关系决定。
- 不能照搬二叉查找树的规则，认为一次中序遍历必然得到键的大小次序。

读实现时应先确认：节点装的是记录、前缀、位位置还是边标签；每一步比较的是完整键还是一个数位。名字相近并不保证状态含义相同。

## 6. Patricia：只保留真正分叉的位置

假设一批二进制键的前二十位完全相同，只有第二十一位才出现差别。普通二进制 Trie 会经过一串只有一个孩子的节点。Patricia 的重要想法是记录实际发生分歧的位位置，跳过没有分支作用的部分。

压缩带来一个必须补回的条件：**走到候选记录，不代表已经检查了所有位。**

一个不存在的查询键，可能在所有已检查的分叉位上都选择了同样的方向，却在被跳过的位置不同。因此，对于完整键的精确查找，最后仍要核对候选完整键。

长度也属于键的一部分。一个键是另一个键的前缀时，需要独立的结束标记，或者在比较和分支规则中显式编码长度。若直接给短键无限补零，它可能与后缀全零的长键混淆。

原书 Patricia 的讨论还涉及文本后缀和前缀匹配。若任务是判断“文本某个后缀是否以查询串开头”，最后应该验证查询长度对应的前缀；若任务是字典中的精确键查找，则必须验证完整键和长度。二者的接受条件不能混用。

压缩路径同样可以采用保存字符串片段的形式。插入一个在片段中间分歧的新键时，需要把片段拆成共有前缀与两个分支；这使插入逻辑复杂一些，但能减少节点数量。

## 7. 可运行的字符 Trie：精确查找、前缀枚举与删除

下面按 Python 字符串迭代得到的 Unicode 码点处理键，使用字符串本身的比较顺序枚举，不处理拼音排序、大小写折叠或 Unicode 规范化。这些语义应在使用索引前统一。

```python
class Node:
    def __init__(self):
        self.children = {}
        self.terminal = False
        self.value = None


class Trie:
    def __init__(self):
        self.root = Node()

    def _walk(self, key):
        node = self.root
        for ch in key:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def put(self, key, value):
        node = self.root
        for ch in key:
            if ch not in node.children:
                node.children[ch] = Node()
            node = node.children[ch]
        node.terminal = True
        node.value = value

    def __contains__(self, key):
        node = self._walk(key)
        return node is not None and node.terminal

    def get(self, key):
        node = self._walk(key)
        if node is None or not node.terminal:
            raise KeyError(key)
        return node.value

    def remove(self, key):
        node, path = self.root, []
        for ch in key:
            child = node.children.get(ch)
            if child is None:
                raise KeyError(key)
            path.append((node, ch))
            node = child
        if not node.terminal:
            raise KeyError(key)
        node.terminal = False
        node.value = None
        for parent, ch in reversed(path):
            child = parent.children[ch]
            if child.terminal or child.children:
                break
            del parent.children[ch]

    def with_prefix(self, prefix):
        start = self._walk(prefix)
        if start is None:
            return
        stack = [(prefix, start)]
        while stack:
            key, node = stack.pop()
            if node.terminal:
                yield key, node.value
            for ch in sorted(node.children, reverse=True):
                stack.append((key + ch, node.children[ch]))


trie = Trie()
for key, value in [("cart", 4), ("car", None), ("cat", 3),
                   ("dog", 5), ("", 0)]:
    trie.put(key, value)
print(list(trie.with_prefix("ca")))
trie.remove("car")
print("car" in trie, "cart" in trie, trie.get(""))
print(list(trie.with_prefix("car")))
```

输出：

```text
[('car', None), ('cart', 4), ('cat', 3)]
False True 0
[('cart', 4)]
```

删除 car 后，cart 仍然存在，说明删除的是键的终止状态，而非粗暴删除整条前缀路径。空字符串存于根节点，值为 None 的键也能与不存在区分。

进一步验证时，可以用普通字典做参照：随机执行插入、覆盖和删除；每次前缀查询都同“扫描字典并筛选 startswith 的键，再排序”的结果比较。还应检查一条长链、所有键共享前缀、空前缀返回全表，以及删除不存在键时结构不变。

## 8. 选结构之前，先确定键的表示

数字查找利用了键的内部结构，因而特别依赖编码规则。按字节还是按字符分支、怎样区分短键与长键、是否规范化大小写，都会改变“同一个键”的定义。

Trie 适合把精确查找和前缀枚举放在一起考虑；压缩结构解决单分支路径带来的空间浪费；DST 和 Patricia 又在节点内容、位选择和最后确认方式上作了不同取舍。
