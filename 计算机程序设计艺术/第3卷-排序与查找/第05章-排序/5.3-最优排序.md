# 【计算机程序设计艺术 TAOCP】卷3·5.3 最优排序：知道下界以后，为什么还不能宣布最优

“这个排序已经是最优的”听起来像一个完整结论，其实还少了条件：优化的是比较次数、移动次数还是总时间？比较可以依赖先前结果吗？所有键码是否互异？说的是最坏情况还是平均情况？

原书 §5.3 先限定问题，再讨论排序、合并、选择和排序网络。这样才能把一个可实现的上界与一个不可突破的下界放在同一把尺子上比较。

> 阅读定位：《计算机程序设计艺术》第 3 卷《排序与查找》第 2 版，苏运霖译，国防工业出版社，2002 年；§5.3，书内第 170—233 页。四个下级小节分别从第 171、186、196、208 页开始；第 234 页开始 §5.4。扫描 PDF 页码为书页加 13。

## 1. 比较决策树把算法中的信息流显式画出来

考虑 $n$ 个互异键码，并限制算法只能通过两个键码的大小比较获取次序信息。一次比较只有两个可能结果，可以作为二叉树的一个内部节点。

从根走到叶子的路径，记录了算法实际做过的比较。到达叶子时，算法必须能够确定全部记录的次序。

输入可能有 $n!$ 种相对次序。不同的次序必须被正确区分，而深度不超过 $h$ 的二叉树最多有 $2^h$ 个叶子，因此

$$
n!\le2^h,
\qquad h\ge\lceil\log_2(n!)\rceil.
$$

若 $S(n)$ 表示最坏比较次数能够达到的最小值，就得到

$$
S(n)\ge\lceil\log_2(n!)\rceil.
$$

用斯特林公式展开，

$$
\log_2(n!)
=n\log_2n-(\log_2e)n+\tfrac12\log_2n+O(1).
$$

于是比较排序的最坏情况至少需要 $\Omega(n\log n)$ 次比较。

这个推导不能套到任意整数运算模型上。基数排序读取键码数位，获得信息的方式已经超出上述二叉比较模型。允许相等键码时，也需要重新说明哪些输入必须区分、如何处理相等结果。

## 2. 数得下叶子，不代表造得出所需的树

信息量下界只告诉我们树至少多高，却没有保证存在一棵同样高度、而且每个节点都是合法键码比较的排序决策树。

比较必须遵守传递性。若已经知道 $a<b<c$，再问 $a<c$ 不会产生新的有效分支；某些形式上画出来的分支根本不对应任何输入。因此，一棵“叶子数刚好够”的任意二叉树，不一定能变成排序程序。

要证明最优，通常需要两部分证据：

- 下界：说明所有符合模型的算法都不能更省。
- 上界：给出一个确实能处理全部合法输入的算法，并计算它的最坏成本。

只有两者相等，才能得到精确最优值。一个算法做了 8 次，而下界是 7 次，只说明目前有区间 $7\le S(n)\le8$，并不自动说明这个算法还存在一种可行的“删掉一次比较”方式。

这里可以给出一个完全闭合的小例子。四个互异元素共有 $24$ 种排列，而 $2^4<24\le2^5$，所以至少需要 5 次比较。后文的四输入网络固定使用 5 次比较并能排好所有输入，于是四元素的最坏比较次数就是 5。

原书还讨论合并插入等节省比较的构造。阅读这些构造时，重点是每一次比较怎样利用已有偏序；不能只比较最终公式的首项，就忽略线性项和小规模差异。

## 3. 合并：已有次序也是信息

若两份输入已经分别有序，长度为 $m$ 和 $n$，还需要区分的只是两份序列在输出中的交错方式，共有

$$
\binom{m+n}{m}
$$

种。若 $M(m,n)$ 是互异键码下合并所需的最小最坏比较数，则

$$
\left\lceil\log_2\binom{m+n}{m}\right\rceil
\le M(m,n)\le m+n-1,
\qquad m,n\ge1.
$$

右边来自普通两路合并。两份长度接近时它很有效，但长度极不平衡时，可以利用更强的已有结构。

比如只有一个新元素，要把它放进长度为 $n$ 的有序表中，需要区分 $n+1$ 个间隙。二分查找可以用至多 $\lceil\log_2(n+1)\rceil$ 次比较找到位置，远少于最坏情况下逐个扫描的 $n$ 次。数组移动成本仍可能为线性，这一节优化的是比较。

两份等长输入还有一个比单纯计数更强的下界。考虑最终次序

$$
B_1<A_1<B_2<A_2<\cdots<B_m<A_m.
$$

其中每一对相邻元素都来自不同输入序列。如果其中某对从未直接比较，交换这两个相邻元素仍不破坏各自输入内部的次序，也不会改变其他比较结果，算法就无法区分这两种合法输入。

这样的相邻关系有 $2m-1$ 个，所以该输入强迫任意正确算法至少做这么多次比较。结合普通合并的上界，得到

$$
M(m,m)=2m-1.
$$

这个证明展示了一种重要技巧：当叶子计数不够强时，可以直接构造算法必须取得的次序证据。

## 4. 选择：不必为了一个名次排出所有名次

找最小值只需扫描一次，做 $n-1$ 次比较；这也是下界，因为除最小值以外，每个元素至少要在一次比较中输掉“最小值候选”的资格。

找第二小值时，淘汰赛结构能够保存更多信息。先找出最小值，第二小值必定出现在**直接输给最小值**的元素中，而不是所有输过比赛的元素中。

若 $n=2^r$，采用平衡淘汰赛，最小值正好参加 $r$ 场比较。因此找最小值和第二小值共需

$$
(n-1)+(r-1)=n+\log_2n-2
$$

次比较。这里计入了在 $r$ 个直接败者中再找最小值的成本。若 $n$ 不是二的幂，要根据具体赛程处理轮空和路径长度，不能直接把非整数的 $\log_2n$ 塞进精确计数。

同时找最小值和最大值也能省比较：先把元素两两比较，每对较小者只参加最小值竞争，较大者只参加最大值竞争。

偶数 $n$ 时，先做 $n/2$ 次配对比较，再各做 $n/2-1$ 次比较，合计

$$
\frac{3n}{2}-2.
$$

奇数时保留一个元素同时初始化最小值和最大值，对余下元素配对，合计 $3(n-1)/2$。统一写成 $\lceil3n/2\rceil-2$，比两次独立扫描的 $2n-2$ 更少。

一般的第 $k$ 小元素又是不同的问题。它不要求建立完整次序，但必须排除足够多的候选；不能简单地把排序下界乘上 $k/n$ 当作选择下界。

## 5. 排序网络：提前固定所有比较位置

普通比较排序可以根据前面的结果决定下一次比较谁。排序网络则预先固定比较器连接的位置，每个比较器把较小值送到一端、较大值送到另一端。

四条线的一个网络可以按下面三层执行，位置编号从 0 开始：

| 层 | 同层比较器 |
|---|---|
| 1 | $(0,1)$、$`(2,3)`$ |
| 2 | $(0,2)$、$`(1,3)`$ |
| 3 | $(1,2)$ |

前两层使最小值到位置 0、最大值到位置 3，最后一个比较器排好中间两个值。因此它使用 5 个比较器，深度为 3。

“5 个比较器”和“3 层”对应不同目标：一个衡量总工作量，一个衡量理想并行执行的关键路径。若两个比较器共用一条线，通常不能把它们随意放到同一层。

### 为什么只测 0 和 1 就能验证网络

原书的 0—1 原理说：如果一个固定比较网络能够排好所有 $2^n$ 种二进制输入，它就能排好任意全序键码输入。

理由是单调阈值映射与取最小值、最大值可交换。假设某次输出仍有 $y_i>y_{i+1}$，选择一个阈值，把不超过 $y_{i+1}$ 的数映成 0，其余映成 1。把同样映射应用到输入，再经过同一网络，输出相应位置就会出现 1、0，形成一个二进制反例。

因此不存在二进制反例，就不存在一般反例。这个结论依赖网络固定且由比较交换组成，不能拿来证明任意带分支程序在测试少数值后就普遍正确。

## 6. Python：穷举小网络，给“正确”附上一份证据

```python
from itertools import permutations, product
from math import factorial

NETWORK4 = [(0, 1), (2, 3), (0, 2), (1, 3), (1, 2)]

def network_sort(values, network):
    a = list(values)
    for i, j in network:
        if not (0 <= i < j < len(a)):
            raise ValueError("比较器位置不合法")
        if a[i] > a[j]:
            a[i], a[j] = a[j], a[i]
    return a

def pair_minmax(values):
    a = list(values)
    if not a:
        raise ValueError("空输入没有最小值和最大值")
    comparisons = 0
    if len(a) % 2:
        low = high = a[0]
        start = 1
    else:
        comparisons = 1
        low, high = (a[0], a[1]) if a[0] <= a[1] else (a[1], a[0])
        start = 2
    for i in range(start, len(a), 2):
        x, y = a[i], a[i + 1]
        comparisons += 3
        if x > y:
            x, y = y, x
        if x < low:
            low = x
        if y > high:
            high = y
    return low, high, comparisons

binary_ok = sum(network_sort(x, NETWORK4) == sorted(x)
                for x in product((0, 1), repeat=4))
permutation_ok = sum(network_sort(x, NETWORK4) == sorted(x)
                     for x in permutations(range(4)))
# 对整数 m，(m-1).bit_length() 精确等于 ceil(log2(m))。
lower_bound = (factorial(4) - 1).bit_length()
broken = NETWORK4[:-1]
counterexample = next(x for x in product((0, 1), repeat=4)
                      if network_sort(x, broken) != sorted(x))
print(lower_bound, len(NETWORK4), binary_ok, permutation_ok)
print(counterexample)
print(pair_minmax([9, 2, 7, 4, 8, 1]))
```

输出：

```text
5 5 16 24
(0, 1, 0, 1)
(1, 9, 7)
```

第一行同时给出下界、构造的成本和穷举结果。删去最后一个比较器后，程序会找到具体反例，比“似乎还需要一次比较”更明确。

这份验证证明了这个四输入网络的正确性，再结合下界证明它在比较器数量上最优。它没有搜索所有规模的网络，也没有得出更大规模最优值的结论。

## 7. 最优性结论应当怎样写

一个完整的表述应同时包含输入范围、允许的操作、优化指标、上下界证据和是否达到等号。例如：“对四个互异键码，只计大小比较的最坏次数，下界为 5；存在一个使用 5 次比较的正确构造，因此最优值为 5。”

到了外部排序，主要代价会变成数据读写与设备调度。比较次数上已经很省的程序，可能仍然在外存访问上做了大量无用工作。
