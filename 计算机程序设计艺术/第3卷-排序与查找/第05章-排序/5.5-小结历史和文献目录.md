# 【计算机程序设计艺术 TAOCP】卷3·5.5 小结、历史和文献目录：怎样读懂一张排序性能表

读完一章排序算法，很容易想做一张排行榜：哪个最快，哪个最省空间，哪个应该永远优先使用。原书在本章结尾给出的提醒恰恰是，排序方法的适用性取决于数据、表示方式、机器和评价标准。

§5.5 一方面收拢前面的方法，另一方面回顾排序技术的历史。把这两部分一起读，会看到一个贯穿全章的问题：人们是在怎样的资源限制下，发现哪些信息值得保留、哪些操作值得省掉的？

> 阅读定位：《计算机程序设计艺术》第 3 卷《排序与查找》第 2 版，苏运霖译，国防工业出版社，2002 年；§5.5，书内第 355—365 页，扫描 PDF 页码为书页加 13。第 366 页已经进入第六章“查找”的章前导言。

## 1. 全章可以沿着四个问题重新连接

§5.1 问输入具有什么结构：逆序、重复键码、连续路段，以及排列与图表之间的对应。

§5.2 问怎样在内存中组织记录：维护有序前缀、通过交换分区、重复选择极值、合并已有次序，或者利用键码数位进行分布。

§5.3 问在指定模型里还能省多少：下界需要证明，上界需要构造，比较次数最少和执行时间最短并非同一件事。

§5.4 把数据放到外部设备上：工作量不再只是比较，还包括路段分配、读写、缓冲、设备定位和调度。

这样看，每种方法都有它要保留的信息。插入排序保留前缀的次序，堆保留极值的竞争关系，合并保留两个输入各自的次序，替代选择保留仍能进入当前路段的候选。理解这些信息为什么有用，比只记算法名称更容易迁移到新问题。

## 2. 性能表中的每个数，都应当带着条件阅读

原书第 358 页用 MIX 程序比较多种内部排序方法，同时列出稳定性、程序长度、空间、平均运行量、最大运行量以及两个给定规模的实际计数。

这张表非常适合学习怎样做比较，但不能把表中数字直接换算成今天某台机器的耗时。原书在表前就说明：数字针对特定机器和程序，一些行的输入假设也不完全相同。

例如，“平均”可能是在互异键码的均匀随机排列上取平均，也可能依赖某种键码分布；“最大”则要求覆盖全部合法输入。表中的主项省略低阶项，不能据此断言小数组的实际快慢。

同样，稳定性和空间也需要看具体实现：普通数组选择排序可以少交换，却不稳定；链表合并能减少记录移动，但需要链接字段；给每条记录额外附上原始序号，可以把同键顺序编码进键码，却又增加了存储和比较成本。

阅读性能结论时，可以先填写下面这张小表：

| 需要写清的条件 | 它可能改变什么 |
|---|---|
| 键码是否互异，是否来自有限范围 | 比较下界、分布排序的适用性、分区行为 |
| 输入是否接近有序，是否已有长路段 | 插入和自然合并的实际工作量 |
| 记录长度、键码比较成本 | 移动记录与多做比较之间的取舍 |
| 稳定性要求 | 可接受的算法和同键处理规则 |
| 辅助空间与外存限制 | 缓冲大小、路数、读写趟数 |
| 衡量最坏、期望还是实测耗时 | 能够声称的保证范围 |

如果某个结论没有交代这些条件，它可能仍然是有用的经验，但还不是可以直接复用的精确分析。

## 3. 一个小计数实验：相同输入也能有不同的“赢家”

为了看清成本权重，我们只比较直接插入和直接选择两个简单实现，并记录两种事件：

- $C$：键码之间的大小比较次数，不计下标边界检查。
- $W$：列表槽位的赋值次数；交换两个槽位记 2 次，不计临时变量赋值和初始复制。

再定义一个用于教学的加权成本

$$
T_\lambda=C+\lambda W,\qquad\lambda\ge0.
$$

它不是实际 CPU 时间公式，只是把“比较”和“写入”分开计价。下面刻意保留插入排序每轮末尾的放回赋值，即使元素没有移动，这次赋值也计数。

```python
def insertion_metrics(values):
    a = list(values)
    comparisons = writes = 0
    for i in range(1, len(a)):
        item, j = a[i], i - 1
        while j >= 0:
            comparisons += 1
            if a[j] <= item:
                break
            a[j + 1] = a[j]
            writes += 1
            j -= 1
        a[j + 1] = item
        writes += 1
    return a, comparisons, writes

def selection_metrics(values):
    a = list(values)
    comparisons = writes = 0
    for i in range(len(a) - 1):
        best = i
        for j in range(i + 1, len(a)):
            comparisons += 1
            if a[j] < a[best]:
                best = j
        if best != i:
            a[i], a[best] = a[best], a[i]
            writes += 2
    return a, comparisons, writes

cases = [('ordered', list(range(8))),
         ('reversed', list(range(7, -1, -1)))]
for name, values in cases:
    left = insertion_metrics(values)
    right = selection_metrics(values)
    assert left[0] == right[0] == sorted(values)
    print(name, left[1:], right[1:])
    for weight in (0, 4):
        costs = (left[1] + weight * left[2],
                 right[1] + weight * right[2])
        print(weight, costs)
```

输出：

```text
ordered (7, 7) (28, 0)
0 (7, 28)
4 (35, 28)
reversed (28, 35) (28, 8)
0 (28, 28)
4 (168, 60)
```

对已经有序的八个元素，只计比较时插入更省；按这里的赋值规则，当写入权重为 4 时，选择的加权成本反而更低。分界来自

$$
7+7\lambda=28,\qquad\lambda=3.
$$

这不是在推荐用选择排序处理有序数组。恰恰相反，插入实现可以避免没有发生移动时的冗余放回，改变后的 $W$ 会改变结论。**性能属于具体实现与计数模型，不能只贴在算法名称上。**

完全逆序时，两者在这个小例子中都做 28 次比较，但写入量差异很大。样例说明两个指标可能分离，并不证明这两个方法在所有输入上具有某种统一排名。

## 4. 历史线索：排序一直在推动系统设计

下面的历史梳理依据本节的叙述与所列文献，不把书中引用过的论文冒称为已经逐篇核读的原始资料。

### 穿孔卡片阶段：数据处理需求先于电子计算机

原书从十九世纪的人口普查谈起，介绍 Hollerith 的制表与分类设备及其在 1890 年美国人口普查中的应用。记录以卡片存在，分类箱和机器的动作限制，直接影响处理顺序。

把多位键码按位分类的思想，也是在这样的实际工作中发展起来。最低位优先之所以有效，需要每轮保持同类记录的原有次序；后来写进程序的稳定性规则，在机械处理里同样重要。

原书还区分了发明、专利、实际使用和公开出版之间的证据。一个技术可能先在操作实践中被发现，许多年后才出现在容易检索的文献里，因此“最早找到的文章”与“第一次有人这样做”不一定相同。

### 存储程序阶段：排序可以检验指令系统

本节记述，冯·诺依曼在 1945 年编写内部合并排序程序，用来考察拟议中的 EDVAC 指令是否适用。同年，Zuse 独立写过直接插入排序程序，作为其语言中列表操作的例子。

这里的排序不只是一个应用功能。它需要比较、条件分支、地址访问和记录搬移，可以暴露机器是否善于处理组合性任务。一个指令集合能够表达数值公式，并不自动意味着它容易表达数据组织过程。

### 大量数据阶段：缓冲和程序生成也进入算法

原书对 Holberton 及 UNIVAC 相关工作有较详细的叙述，包括让读、写和计算重叠的缓冲安排，以及根据记录大小、键码位置等输入生成排序程序的工作。

这一段历史把“排序算法”扩展成了更完整的系统问题：设备怎样并行工作，输入输出何时可以继续，用户如何描述记录格式，生成的程序如何适配这些参数。只统计大小比较，已经不足以覆盖这些贡献。

### 分析阶段：把经验变成可以重复讨论的模型

本节提到 Seward 在 1954 年工作中发展分布计数与替代选择思想，Demuth 在 1956 年的研究中分别考虑不同存储访问模型。随后，内部排序、外部合并以及比较复杂度的研究逐渐形成更系统的分析。

它们共同说明：明确内存、设备访问和允许操作之后，才能谈某种方法为什么更好。算法分析与工程实现之间不是先后替代的关系，而是不断相互修正。

## 5. 读“未来发展”时，要保留版本的时间坐标

本节后半部分讨论自适应排序、缓存影响，以及当时的大规模排序基准。这里的“当前”“世界纪录”和“未来”，均属于该版成书时的语境。

不能把其中的纪录秒数直接写成今天的最佳成绩，也不能把 MIX 上的规模阈值搬成通用建议。更可复用的是它提出的衡量问题：输入和输出是否都在磁盘上？是否计入程序启动？键码有多少重复？当一个基准已经太小、主要测到固定开销时，是否应该调整任务规模？

自适应性的线索也值得接回 §5.1。若输入已经有较少逆序或少量长路段，一个程序是否能相应少做工作，需要从它利用的输入结构来证明，不能只因为“通常会快”就称为自适应。

## 6. 怎样沿着文献目录继续读

这份文献线索可以按问题使用，而不是从头逐条收集：

1. 想理解某个算法的基本动作，先回到本章对应小节，确认不变式、假设与伪代码。
2. 想研究历史归属，区分原始报告、专利、机器手册、后来的回顾文章以及本书的转述。
3. 想比较性能，记录硬件模型、输入分布、键码与记录长度、空间预算和计时边界。
4. 想复现结果，先核验正确性、稳定性与记录守恒，再做计数或耗时实验；不要让一个错误但少做工作的实现占据排行榜。

原书的习题还把稳定性、小存储空间、最坏运行时间放到一起，提醒读者不要把常见实现的取舍当作不可证明地放宽或加强的定理。一个朴素实现做不到某事，并不等于所有算法都做不到。

第五章留下的完整能力，是从输入结构出发选择方法，用不变式解释正确性，用明确成本比较实现，再把结论放回它成立的条件中。第六章继续讨论查找时，这些关于有序信息、存储表示和访问成本的认识还会用到。
