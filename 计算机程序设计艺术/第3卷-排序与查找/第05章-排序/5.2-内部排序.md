# 【计算机程序设计艺术 TAOCP】卷3·5.2 内部排序：比较、移动和稳定性，分别要付出多少代价

给一列数排好序并不难，难的是说明为什么这样排合适。两种算法都能得到递增序列，却可能在比较次数、数据移动量、额外空间和最坏情况上表现不同。

原书 §5.2 把内部排序分成插入、交换、选择、合并和分布五组。沿着这五种基本动作理解，比把几十种算法分别背下来更容易看出它们的联系。

> 阅读定位：《计算机程序设计艺术》第 3 卷《排序与查找》第 2 版，苏运霖译，国防工业出版社，2002 年；§5.2，书内第 68—170 页，扫描 PDF 页码为书页加 13。五个下级小节分别从第 75、99、132、151、161 页开始。

## 1. 先确定究竟在给什么东西排序

排序的对象是记录 $R_i$，比较的对象通常只是其中的键码 $K_i$。若一条记录包含很长的文本，移动整条记录可能远比比较一个整数昂贵。这时可以先排地址或索引，最后按需要访问记录。

稳定排序还要求：若 $K_i=K_j$ 且原输入中 $i<j$，输出中 $R_i$ 仍在 $R_j$ 前面。这个要求不是“结果是否递增”的同义词。

例如先按报名时间排，再稳定地按成绩排，就能得到“成绩为主、同分按报名先后”的次序。若第二次排序不稳定，第一层信息可能被破坏。

所以，判断一个实现前至少要明确：键码能否只靠比较访问？同键记录是否需要稳定？额外内存能有多少？比较与移动的代价是否接近？输入是否经常接近有序？

## 2. 插入：维护一个已经排好的前缀

直接插入排序的不变式是：处理第 $j$ 条记录前，前 $j-1$ 条已经有序。暂存新记录，把比它大的记录逐个向右移，最后把它放入空位。

若只在严格大于新键码时移动，同键记录不会越过彼此，算法就是稳定的。

记输入的严格逆序数为 $I$。新记录每越过一个较大记录，就消除一对逆序，因此整个过程的右移次数恰好为

$$
M_{\mathrm{shift}}=I.
$$

每次成功的键码比较对应一次右移；每轮还至多有一次失败的键码比较。因此本文实现对 $n\ge1$ 有

$$
I\le C\le I+n-1.
$$

加上外层循环和最终放回，运行量为 $\Theta(n+I)$。已经有序时是线性量级，完全逆序时是平方量级。前一篇的逆序数在这里直接变成了代码的工作量。

二分插入把寻找插入位置的比较减少到对数量级，但数组中腾出位置仍可能移动线性数量的记录。**比较减少，不等于移动同时减少。**若要稳定，应把新记录插到已有同键记录之后。

Shell 排序则允许先按较大间隔处理子序列，逐渐缩小间隔直到 1。它改变了远距离错位的修正方式；复杂度依赖具体间隔序列，不能给所有 Shell 排序统一贴一个精确指数。

## 3. 交换：局部纠错与分区解决的是不同问题

相邻交换可以逐次消除逆序。冒泡排序若在一轮没有发生交换时停止，能快速识别已经有序的输入，但一般仍可能需要平方数量的比较。

快速排序采用另一种交换结构：选定枢轴，进行分区，使左侧键码不大于它，右侧不小于它，然后继续处理两侧。

若各次分区都比较均衡，递推近似为

$$
T(n)=2T(n/2)+\Theta(n),
$$

得到 $\Theta(n\log n)$。若每次只分出一个元素，则变成

$$
T(n)=T(n-1)+\Theta(n)=\Theta(n^2).
$$

随机化枢轴可以让互异键码下的期望成本达到 $\Theta(n\log n)$，但期望保证和每次运行的最坏保证要分开。

重复键码也会影响分区。若对相等键码的处理不当，指针可能停滞，或者反复产生极不均衡的子问题。实际实现必须把“等于枢轴时怎么办”写进循环规则；三路分区是明确处理重复值的一种方法。

原书还讨论将较长的子文件留待以后处理、先处理较短者。由于连续进入的较短子问题长度至少减半，可以控制待处理区间所占的栈空间。空间保证来自调度方式，不是仅凭“用了快速排序”就自动得到的。

## 4. 选择：重复找极值，为何需要保存比赛结果

直接选择每轮从未排部分找最小值，比较次数固定为

$$
(n-1)+(n-2)+\cdots+1=\frac{n(n-1)}2.
$$

它的交换次数较少，但普通远距离交换版本不稳定。例如 $(2,A),(2,B),(1,C)$，把最小项换到开头后，会得到 $(1,C),(2,B),(2,A)$。

堆排序保留了“当前最大值在根部”的结构。取走根以后，只沿一条路径恢复堆性质，不必从头重新比赛。

一趟自底向上建堆是 $O(n)$，并不是把 $n$ 个元素分别插入堆所得的粗略 $O(n\log n)$。直观上，能够向下移动很多层的节点很少；按高度加总得到

```math
\sum_{h\ge0}O\!\left(\frac{n(h+1)}{2^{h+1}}\right)=O(n).
```

随后进行 $n-1$ 次取出与恢复，每次至多对数量级，总成本为 $O(n\log n)$。典型数组堆排序使用常量额外空间，但不稳定。

## 5. 合并：把两份有序信息变成更大的一份

两路合并每次只需比较两个输入序列的首项，输出较小者。长度为 $m,n$ 的两份非空序列，最多需要 $m+n-1$ 次键码比较；其中一份耗尽后，另一份直接接上即可。

当键码相等时优先取左边，并且左右子问题来自输入中先后相邻的区间，递归合并排序就能保留稳定性。

均分子问题的自顶向下合并排序，其最坏比较次数满足

$$
C(n)=C(\lfloor n/2\rfloor)+C(\lceil n/2\rceil)+n-1,
\quad C(1)=0.
$$

由此得到，对 $n\ge1$，

$$
C(n)=n\lceil\log_2n\rceil-2^{\lceil\log_2n\rceil}+1.
$$

这是指定拆分方式和合并实现的最坏比较数，不是所有输入都恰好做这么多次。

数组合并通常需要线性辅助空间。链表合并可以通过重接链接避免搬动记录，但节点访问方式和分配开销也会进入实际成本。已经存在的自然路段同样可以作为合并的起点。

## 6. 分布：利用键码结构，为什么不违反比较下界

计数排序在键码来自有限整数区间时，可以先计数，再通过前缀和确定各键码的输出区域。若范围大小为 $b$，常见稳定实现的成本为 $O(n+b)$。

LSD 基数排序从最低位开始，每一轮对当前位做稳定分布。若每位有 $b$ 种取值，键码共 $d$ 位，则成本为

$$
O(d(n+b)).
$$

稳定性为什么必需？处理第 $j$ 位前，记录已经按更低的 $j$ 位有序。当前位相同的记录必须保留低位次序，下一轮才能让更高位成为新的主关键字。

这些算法直接读取键码的数位或数值范围，已经超出“只能比较两个键码大小”的模型，所以不受该模型下 $\Omega(n\log n)$ 比较次数下界的限制。

范围太大时，计数表可能不可接受；位数很多时，扫描次数也会增加。基数排序的线性表述必须同时写清 $d$ 和 $b$ 的假设。

| 常见实现 | 最坏时间量级 | 稳定性 | 主要取舍 |
|---|---|---|---|
| 直接插入 | $O(n^2)$ | 稳定 | 能利用较少逆序；数组移动可能多 |
| 双路原地快速排序 | $O(n^2)$ | 通常不稳定 | 平均表现依赖分区与输入模型 |
| 数组堆排序 | $O(n\log n)$ | 不稳定 | 常量辅助空间与最坏保证 |
| 数组合并排序 | $O(n\log n)$ | 可稳定 | 常见实现使用 $O(n)$ 辅助空间 |
| LSD 稳定基数排序 | $O(d(n+b))$ | 稳定 | 依赖可提取的数位与桶空间 |

## 7. Python：给相同键码保留身份

下面用二元组 `(键码, 身份)` 表示记录。三个实现只按第一个字段排序；若结果连第二个字段的先后也一致，就能观察到稳定性。

```python
def insertion(records):
    a = list(records)
    comparisons = shifts = 0
    for i in range(1, len(a)):
        item, j = a[i], i - 1
        while j >= 0:
            comparisons += 1
            if a[j][0] <= item[0]:
                break
            a[j + 1] = a[j]
            shifts += 1
            j -= 1
        a[j + 1] = item
    return a, comparisons, shifts

def merge_sort(records):
    a = list(records)
    if len(a) < 2:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i][0] <= right[j][0]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    return result + left[i:] + right[j:]

def radix_sort(records, base=10):
    a = list(records)
    if not isinstance(base, int) or base < 2:
        raise ValueError("基数至少为 2")
    if any(not isinstance(x[0], int) or x[0] < 0 for x in a):
        raise ValueError("示例只处理非负整数键码")
    largest = max((x[0] for x in a), default=0)
    place = 1
    while place <= largest:
        buckets = [[] for _ in range(base)]
        for item in a:
            buckets[(item[0] // place) % base].append(item)
        a = [item for bucket in buckets for item in bucket]
        place *= base
    return a

data = [(21, 'A'), (4, 'B'), (21, 'C'), (13, 'D'), (4, 'E')]
ordered, comparisons, shifts = insertion(data)
print(ordered, comparisons, shifts)
print(merge_sort(data) == ordered, radix_sort(data) == ordered)
```

输出：

```text
[(4, 'B'), (4, 'E'), (13, 'D'), (21, 'A'), (21, 'C')] 9 6
True True
```

B 仍在 E 前面，A 仍在 C 前面。右移 6 次与输入的严格逆序数一致。合并代码为了可读性使用切片，不作为低分配次数的工程版本；基数代码把桶显式写成列表，方便检查每一轮是否保持输入顺序。

测试还应覆盖空序列、全相等、完全逆序、少量错位和多个基数。只检查“键码递增”不够，还应确认记录没有丢失、没有增加，并按需要核验同键记录的相对顺序。

## 8. 从算法名称回到具体成本

这一节最值得带走的，是对实现细节的敏感：一次二分查找省下的可能只是比较，一次大跨度交换可能破坏稳定性，一段已经有序的输入可能被某些算法利用，也可能被另一些算法忽略。
